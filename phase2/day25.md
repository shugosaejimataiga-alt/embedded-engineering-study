

# C-Day25 ポインタ演算

## 学習内容

C-Day25では、ポインタの加算・減算、ポインタを使った配列の走査、配列の範囲について学習した。

今回の主な内容は以下。

- ポインタの加算
- ポインタの減算
- `p++` / `p--`
- `p + i`
- `*(p + i)`
- 配列をポインタで順番に処理する方法
- 配列を逆順に処理する方法
- ポインタ演算とデータ型の大きさ
- 配列の範囲外アクセス
- 配列の1個後ろを指すポインタ
- アドレスを指すことと、その値を読み書きすることの違い

---

# 1. ポインタ演算とは

ポインタ演算とは、ポインタが持っているメモリアドレスを基準として、別の要素のアドレスを求めたり、ポインタ自身を前後の要素へ移動させたりすること。

例：

    int numbers[5] = {10, 20, 30, 40, 50};
    int *p = numbers;

このとき `p` は `numbers[0]` のアドレスを保持している。

    p + 1

は `numbers[1]` のアドレスを表す。

    p + 2

は `numbers[2]` のアドレスを表す。

---

# 2. `p + i` と `*(p + i)` の違い

ここは今回特に重要だった。

    p + i

は、

「pが保持しているメモリアドレスを基準として、i個先の要素のメモリアドレス」

を表す。

一方、

    *(p + i)

は、

「pからi個先のメモリアドレスに保存されている値」

を表す。

例：

    int numbers[5] = {10, 20, 30, 40, 50};
    int *p = numbers;

この場合、

    p + 2

は `numbers[2]` のメモリアドレス。

    *(p + 2)

は、そのアドレスに保存されている値 `30`。

つまり、

    p + 2
    ↓
    メモリアドレス

    *(p + 2)
    ↓
    そのメモリアドレスにある値

という違い。

---

# 3. `p + i` ではp自体は動かない

例えば、

    int *p = numbers;

として、

    *(p + 2)

を使用しても、`p` 自体が持っているアドレスは変化しない。

`p` はそのまま `numbers[0]` のアドレスを保持している。

その `p` を基準として、

    p + 2

というアドレスを一時的に計算し、

    *(p + 2)

でその場所の値を読む。

つまり、

    p + i

は、

「p自体を移動させる」

のではなく、

「pを基準に別のアドレスを計算する」

処理。

---

# 4. `p++`

    p++;

を実行すると、ポインタ自身が次の要素を指すようになる。

例：

    int numbers[5] = {10, 20, 30, 40, 50};
    int *p = numbers;

最初は、

    p → numbers[0] → 10

その後、

    p++;

を実行すると、

    p → numbers[1] → 20

さらに、

    p++;

を実行すると、

    p → numbers[2] → 30

となる。

つまり、

    p++

は、

「ポインタ自身を次の要素へ移動させる」

処理。

---

# 5. `p--`

    p--;

は、現在指している要素から1個前の要素へ移動する。

例えば、

    10  20  30  40  50
            ↑
            p

という状態で、

    p--;

を実行すると、

    10  20  30  40  50
        ↑
        p

となる。

つまり、

    p++
    → 次の要素へ移動

    p--
    → 前の要素へ移動

ということ。

---

# 6. `p++` は1バイト進むという意味ではない

ポインタ演算では、

    p++;

は単純にメモリアドレスを1バイト増やすという意味ではない。

ポインタが指しているデータ型の大きさに応じて移動する。

例えば、

    int *p;

なら、

    p++;

によって `sizeof(int)` バイト分進む。

仮に、

    sizeof(int) == 4

なら、

    p++

で4バイト分進む。

一方、

    char *p;

なら、`char` は1バイトなので、

    p++;

で1バイト進む。

つまり、

    int *
    → int型1個分進む

    char *
    → char型1個分進む

    double *
    → double型1個分進む

ということ。

ポインタ演算は、

「何バイト進むか」

ではなく、

「そのデータ型の要素を何個進むか」

と考える。

---

# 7. `i++` と `p++` は別のもの

例えば、

    for (int i = 0; i < 5; i++) {
        printf("%d\n", *p);
        p++;
    }

では、

    i++

と、

    p++

は役割が違う。

    i++
    → 変数iを1増やす
    → 主にループの回数を進める

    p++
    → ポインタ自身を次の要素へ移動する

という違い。

`i++` をしたからといって、ポインタ `p` が自動的に次の要素へ移動するわけではない。

---

# 8. for文のiは必ずしも配列の添字ではない

今回特に重要だった考え方。

例えば、

    for (int i = 0; i < 5; i++) {
        printf("%d\n", *p);
        p--;
    }

の `i` は、配列の添字として使っているわけではない。

単純に、

    0
    1
    2
    3
    4

と5回ループするためのカウンターとして使っているだけ。

実際にどの配列要素を参照するかは `p` の位置によって決まる。

したがって、

    i++

で `i` が増えていても、

    p--

によってポインタを逆方向へ移動させることができる。

つまり、

「iが増える方向」と「ポインタが動く方向」は別に考える。

---

# 9. ポインタで配列を走査する方法

## 方法1：ポインタ自体を動かす

    int numbers[5] = {10, 20, 30, 40, 50};
    int *p = numbers;

    for (int i = 0; i < 5; i++) {
        printf("%d\n", *p);
        p++;
    }

この場合、

    p → numbers[0]
    p → numbers[1]
    p → numbers[2]
    p → numbers[3]
    p → numbers[4]

と `p` 自身が移動する。

---

## 方法2：pを基準にアドレスを計算する

    int numbers[5] = {10, 20, 30, 40, 50};
    int *p = numbers;

    for (int i = 0; i < 5; i++) {
        printf("%d\n", *(p + i));
    }

この場合、`p` 自身は動かない。

    p + 0
    p + 1
    p + 2
    p + 3
    p + 4

と、その都度アドレスを計算している。

つまり、

    p++
    → p自身を動かす

    p + i
    → p自身は動かさず、pを基準に別のアドレスを計算する

という違い。

---

# 10. 配列を逆順に処理する

例えば、

    int numbers[5] = {5, 10, 15, 20, 25};

を、

    25
    20
    15
    10
    5

の順番で処理することもできる。

重要なのは、

「現在pがどこを指しているか」

を把握すること。

例えば `p` が `25` を指している状態なら、

    printf("%d\n", *p);

で `25` を表示できる。

その後、

    p--;

すると、`20` を指す。

これを繰り返すことで逆順に処理できる。

---

# 11. 最初のfor文が終わった後のpの位置

次のコードでは、

    for (int i = 0; i < 5; i++) {
        printf("%d\n", *p);
        p++;
    }

5回目の処理で `25` を表示したあとにも `p++` が実行される。

そのため、ループ終了後の `p` は、

    5  10  15  20  25  [配列の1個後ろ]
                        ↑
                        p

となる。

この状態で、

    *p

として値を読むことはできない。

逆順に処理したい場合は、まず、

    p--;

として `25` の位置へ戻す必要がある。

---

# 12. 配列の添字は0から始まる

5個の要素を持つ配列、

    int numbers[5];

の有効な添字は、

    0
    1
    2
    3
    4

となる。

つまり、

    numbers[0] → 1個目
    numbers[1] → 2個目
    numbers[2] → 3個目
    numbers[3] → 4個目
    numbers[4] → 5個目

となる。

要素数が5でも、最後の添字は5ではなく4。

    numbers[5]

は配列の範囲外。

---

# 13. 配列の範囲

例えば、

    int numbers[5] = {5, 10, 15, 20, 25};
    int *p = numbers;

なら、値を読み書きできる範囲は、

    p + 0
    p + 1
    p + 2
    p + 3
    p + 4

まで。

つまり、

    numbers[0]
    ～
    numbers[4]

まで。

---

# 14. 配列の1個後ろを指すことはできる

C言語では、

    p + 5

のように、

「配列の最後の要素の1個後ろ」

を指すポインタまでは作ることができる。

つまり、

    numbers[0]
    numbers[1]
    numbers[2]
    numbers[3]
    numbers[4]
    配列の1個後ろ ← 指すだけならOK

となる。

ただし、そこは配列の要素ではない。

そのため、

    *(p + 5)

として値を読み取ることはできない。

また、

    *(p + 5) = 100;

のように値を書き込むこともできない。

つまり、

    p + 5
    → 配列の1個後ろを指すだけならOK

    *(p + 5)
    → 値を読むのでNG

    *(p + 5) = 値
    → 値を書き込むのでNG

ということ。

---

# 15. 配列の1個後ろよりさらに先はダメ

配列の1個後ろまではポインタとして作成できる。

しかし、

    p + 6

のように、さらにその先を指すポインタ演算はできない。

整理すると、

    配列の中
    → OK

    配列の1個後ろ
    → 指すだけならOK

    配列の1個後ろよりさらに先
    → NG

となる。

---

# 16. 配列の1個手前はダメ

配列の1個後ろは特別に指すことができるが、

    numbers - 1

のように、

「配列の先頭より1個手前」

を指すポインタを作ることはできない。

つまり、

    配列の1個後ろ
    → 指すだけならOK

    配列の1個手前
    → ポインタとして作ること自体がNG

という違いがある。

---

# 17. メモリアドレスを指すことと、値を読むことは別

今回特に重要だった理解。

「そのメモリアドレスをポインタが指していること」

と、

「そのメモリアドレスにある値を読む・書くこと」

は別。

例えば、

    int *end = numbers + 5;

とすれば、配列の1個後ろのアドレスを `end` に保持することはできる。

しかし、

    *end

として値を読むことはできない。

つまり、

    アドレスを保持する
    ≠
    そのアドレスの値を読み書きする

ということ。

---

# 18. 配列の範囲外アクセスが危険な理由

配列の範囲外の値を読み書きすると、C言語では未定義動作になる。

そのため、

- 関係ないメモリを読み取る
- 他の変数の値を書き換える
- 不正な値が表示される
- プログラムがクラッシュする
- 一見正常に動いているように見える

など、予測できない動作になる可能性がある。

したがって、

「配列として確保された範囲内だけを読み書きする」

ことが重要。

# 19. 今回特に詰まったポイント

## `p++` と `i++` の違い

最初は、

「i++でループが進むのに、なぜp++も必要なのか」

という部分で混乱した。

今回理解したことは、

    i++
    → iという変数を増やすだけ

    p++
    → ポインタ自身を次の要素へ移動する

という違い。

---

## `p + i` の意味

    p + i

は、p自身を変更するのではない。

pが保持しているメモリアドレスを基準として、i個先のアドレスを計算するだけ。

---

## `p + 2` と `*(p + 2)` の違い

    p + 2
    → 2個先のメモリアドレス

    *(p + 2)
    → 2個先のメモリアドレスにある値

という違いを理解した。

---

## for文のiは添字とは限らない

    for (int i = 0; i < 5; i++)

と書いてあっても、`i` を配列の添字として使わなければ、

「5回処理するためのカウンター」

として使っているだけ。

したがって、

    i++

でiが増えていても、

    p--

でポインタを逆方向へ移動することができる。

---

## 現在のpの位置を把握する

ポインタを扱うときは、

「現在pがどの要素を指しているか」

を常に意識する必要がある。

特に、

    for (int i = 0; i < 5; i++) {
        printf("%d\n", *p);
        p++;
    }

が終わった後は、`p` が配列の1個後ろを指している。

その状態で `*p` として値を読むことはできない。

---

## ループの最後でポインタを動かしすぎない

逆順に処理するとき、

    printf("%d\n", *p);
    p--;

とすると、最後の `5` を表示したあとにも `p--` が実行される。

すると配列の1個手前を指すことになりNG。

そのため、

「最後の要素を表示したあとに、さらにポインタを移動させない」

ことも重要。

---

# 20. Day25で理解したこと

今回の学習を通して、以下を理解した。

- ポインタ演算とは何か
- `p++` で次の要素へ移動できる
- `p--` で前の要素へ移動できる
- `p + i` はi個先のアドレスを表す
- `*(p + i)` はi個先のアドレスにある値を表す
- `p + i` ではp自身は移動しない
- ポインタ演算の移動量はデータ型の大きさによって決まる
- `int *` ならint型1個分ずつ移動する
- `i++` と `p++` は全く別の処理
- for文のiは単なるループ回数のカウンターとして使うこともできる
- ポインタを使って配列を前方向へ走査できる
- ポインタを使って配列を逆方向へ走査できる
- 配列の最後の添字は「要素数 - 1」
- 配列の1個後ろを指すポインタまでは作れる
- 配列の1個後ろの値を読み書きしてはいけない
- 配列の1個後ろよりさらに先を指すポインタ演算はできない
- 配列の1個手前を指すポインタを作ることはできない
- メモリアドレスを指すことと、その値を読み書きすることは別
- 配列の範囲外アクセスは未定義動作になる
- ポインタ演算では、現在pがどこを指しているかを常に把握する必要がある
