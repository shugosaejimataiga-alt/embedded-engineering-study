# 2. ポインタの基本構造

## 2-1. ポインタとは

ポインタとは、メモリアドレスを保存する変数である。

```c
int speed = 20;
int *p = &speed;
```

それぞれの意味は次のとおり。

| 表記 | 意味 |
|---|---|
| `speed` | 変数に保存されている値 |
| `&speed` | speed自身のメモリアドレス |
| `p` | ポインタに保存されているメモリアドレス |
| `*p` | pが指す先に保存されている値 |
| `&p` | ポインタ変数p自身のメモリアドレス |

### 重要な法則

```c
p == &speed
*p == speed
```

上記の関係は、pがspeedを指している場合に成立する。

### ポインタの宣言

```c
int *p = &speed;
```

これはint型の変数を指すポインタを宣言し、speedのアドレスで初期化する処理である。

### ポインタを通した値の変更

```c
*p = 50;
```

これはpに保存されているアドレスを変更しているわけではない。

pが指しているメモリに保存された値を50に変更している。

したがって、speedの値が50になる。

# 3. ポインタ自身の変更と指す先の値の変更

今回の学習で特に重要だった区別。

```c
int speed = 20;
int backupSpeed = 70;

int *p = &speed;
```

## 3-1. 指す先の値を変更する

```c
*p = 50;
```

変更されるもの：

- speedの値：20 → 50
- pに保存されたアドレス：変更なし

## 3-2. ポインタが保持するアドレスを変更する

```c
p = &backupSpeed;
```

変更されるもの：

- pに保存されたアドレス：speedのアドレス → backupSpeedのアドレス
- speedの値：変更なし
- backupSpeedの値：変更なし

### 重要

| 書き方 | 変更する対象 |
|---|---|
| `p = &speed;` | ポインタが保持するアドレス |
| `*p = 50;` | ポインタが指す先の値 |

ポインタ自身の値と、ポインタが指す先の値は別である。

# 4. ポインタと関数

## 4-1. 関数にアドレスを渡す

```c
#include <stdio.h>

void updateSpeed(int *p);

int main(void)
{
    int speed = 20;

    updateSpeed(&speed);

    printf("%d\n", speed);

    return 0;
}

void updateSpeed(int *p)
{
    *p = 50;
}
```

実行結果：

```text
50
```

### 処理の流れ

1. main関数でspeedを宣言する。
2. `&speed` でspeedのアドレスを取得する。
3. 関数にアドレスを渡す。
4. 関数のポインタ引数pがアドレスを受け取る。
5. `*p = 50;` によってspeedの値を変更する。

## 4-2. ポインタも値渡しされる

C言語の関数呼び出しでは、引数の値がコピーされる。

ポインタを引数として渡す場合も同じである。

ただし、コピーされる値がメモリアドレスなので、呼び出し元と同じ変数にアクセスできる。

### 重要な考え方

- 関数のポインタ変数は呼び出し元とは別の変数。
- しかし、保存されているアドレスが同じなら、同じメモリを参照できる。
- そのため、ポインタを間接参照すると呼び出し元の変数を変更できる。

## 4-3. 関数内でポインタ自身を変更した場合

```c
void updatePointer(int *p)
{
    int another = 100;

    p = &another;
}
```

この場合、変更されるのは関数内のポインタpだけである。

呼び出し元のポインタ変数が保持するアドレスは変更されない。

また、anotherは関数終了時に寿命が終わる。

### 覚える法則

「別関数から変数の中身を変更したい場合は、その変数自身のアドレスを渡す」

この法則は、変更したい変数がポインタ変数である場合にも成立する。

# 5. 配列とポインタの関係

## 5-1. 配列の宣言

```c
int distances[5] = {100, 70, 40, 30, 90};

int *p = distances;
```

通常の式において、配列名distancesは先頭要素のアドレスに変換される。

そのため、pはdistances[0]を指している。

## 5-2. 配列とポインタの表記一覧

| 表記 | 意味 |
|---|---|
| `distances` | 通常の式では先頭要素のアドレスに変換される |
| `&distances[0]` | 先頭要素のアドレス |
| `p` | pに保存されているアドレス |
| `*p` | pが指す先の値 |
| `p[0]` | pが指す先の最初の要素の値 |
| `&p[0]` | pが指す先の最初の要素のアドレス |
| `p[i]` | i番目の要素の値 |
| `&p[i]` | i番目の要素のアドレス |
| `p + i` | i要素分進んだアドレス |
| `*(p + i)` | i要素分進んだ位置の値 |
| `&p` | ポインタ変数p自身のアドレス |
| `&distances` | 配列全体のアドレス |

※ 添字やポインタ演算は、有効な範囲で使用することが前提。

## 5-3. 同じものを表す書き方

pがdistancesの先頭要素を指している場合：

```c
p == &distances[0]

p == &p[0]

p[i] == *(p + i)

&p[i] == p + i

*p == p[0]
```

### 重要な法則

```c
p[i]       == *(p + i)
&p[i]      == p + i
p          == &p[0]
```

値を取得するのか、アドレスを取得するのかを区別する。

# 6. 配列を関数に渡す方法

```c
int distances[5] = {100, 70, 40, 30, 90};

int *p = distances;
```

次の3つは、同じ先頭要素のアドレスを渡す。

```c
updateDistances(distances, 5);

updateDistances(p, 5);

updateDistances(&p[0], 5);
```

受け取る関数：

```c
void updateDistances(int *p, int count)
```

### 重要

`p` はポインタ変数なので、すでにアドレスが保存されている。

そのため、関数に渡す際に、毎回`&`を付ける必要はない。

### 注意

```c
&p
```

これは配列の先頭要素のアドレスではなく、ポインタ変数p自身のアドレスである。

型も異なる。

```c
p   // int *

&p  // int **
```

# 7. ポインタ演算

## 7-1. ポインタの移動

```c
int values[5] = {10, 20, 30, 40, 50};

int *p = values;
```

```c
p += 1;
```

これにより、pはvalues[1]を指すようになる。

つまり、次の要素へ移動する。

### 注意

ポインタの加算では、単純にメモリアドレスの数値を1バイト増やすわけではない。

ポインタが指す型の大きさに応じて移動する。

int型のポインタなら、int型1個分進む。

## 7-2. ポインタを進める処理と値を変更する処理

```c
p += 1;
```

ポインタが指す位置を1要素分進める。

```c
*p += 1;
```

ポインタが現在指している値を1増加させる。

```c
*p -= 10;
```

ポインタが現在指している値を10減少させる。

### 違い

| 表記 | 操作 |
|---|---|
| `p++` | ポインタを次の要素へ進める |
| `p--` | ポインタを前の要素へ戻す |
| `*p += 1` | 指す先の値を1増加 |
| `*p -= 10` | 指す先の値を10減少 |

# 8. ポインタによる配列の走査

## 8-1. 先頭から順番に処理する

```c
int values[5] = {10, 20, 30, 40, 50};

int *p = values;

for (int i = 0; i < 5; i++) {
    printf("%d\n", *p);
    p++;
}
```

実行結果：

```text
10
20
30
40
50
```

### 重要

このfor文のiは、単純に繰り返し回数を管理する変数として使われている。

iが必ず配列の添字を表すわけではない。

## 8-2. 逆順に処理する

```c
int values[5] = {10, 20, 30, 40, 50};

int *p = values + 5;

for (int i = 0; i < 5; i++) {
    p--;
    printf("%d\n", *p);
}
```

実行結果：

```text
50
40
30
20
10
```

### 重要

逆順で処理する場合でも、

```c
for (int i = 0; i < 5; i++)
```

という書き方で問題ない。

iが繰り返し回数を管理し、pが実際の参照位置を管理しているためである。

## 8-3. 先頭位置を確認する

```c
if (p != &values[0]) {
    p--;
}
```

これは、pが配列の先頭を指していなければ、1要素前に戻るという意味である。

アドレス同士を比較している。

# 9. 配列の範囲外アクセス

## 9-1. 配列の添字

```c
int values[5] = {10, 20, 30, 40, 50};
```

有効な添字：

```text
0
1
2
3
4
```

5要素の配列では、最後の添字は4である。

## 9-2. 間違った繰り返し

```c
for (int i = 0; i <= 5; i++) {
    values[i] += 10;
}
```

このコードでは、iが5になった際に範囲外アクセスが発生する。

## 9-3. 正しい繰り返し

```c
for (int i = 0; i < 5; i++) {
    values[i] += 10;
}
```

これなら0〜4まで処理される。

## 9-4. 配列の最後の1つ後ろのポインタ

```c
int values[5] = {10, 20, 30, 40, 50};

int *p = values + 5;
```

これは許される。

pは配列の最後の1つ後ろを指している。

ただし、

```c
printf("%d\n", *p);
```

これは許されない。

最後の1つ後ろの位置を間接参照しているため、未定義動作になる。

### 重要な法則

- 配列内の要素を指すポインタを作る：OK
- 配列の最後の1つ後ろを指すポインタを作る：OK
- 最後の1つ後ろから配列内へ戻す：OK
- 最後の1つ後ろを間接参照する：NG
- 配列の先頭より前へポインタを進める：原則NG
- 最後の1つ後ろより先へ進める：原則NG

# 10. 間接参照とは

今回、特に認識を修正した重要な用語。

## 10-1. 間接参照の意味

間接参照とは、ポインタに保存されているアドレスを使って、そのアドレスが指す先のオブジェクトにアクセスすることである。

```c
int speed = 20;

int *p = &speed;
```

### 間接参照する操作

```c
*p
```

```c
*p = 50;
```

```c
p[0]
```

### 間接参照ではない操作

```c
p
```

```c
p + 1
```

```c
p++
```

```c
&p
```

### 重要

ポインタが保持するアドレスを使用・変更することと、そのアドレスが指す先の値にアクセスすることは違う。

`*p`や`p[i]`によって指す先の値にアクセスする操作が、間接参照である。

# 11. 未初期化ポインタ

## 11-1. 未初期化ポインタとは

```c
int *p;
```

この時点では、pに有効なアドレスが設定されていない。

今回のような初期化されていない自動変数の値は不定である。

そのまま使用することは危険。

```c
*p = 50;
```

有効なアドレスを設定していないため、未定義動作につながる。

## 11-2. 正しい初期化

```c
int speed = 20;

int *p = &speed;
```

この場合、pはspeedのアドレスを保持している。

したがって、

```c
*p = 50;
```

によってspeedの値を変更できる。

# 12. NULLポインタ

## 12-1. NULLとは

NULLポインタは、どのオブジェクトも指していないことを表すポインタ値である。

```c
int *p = NULL;
```

これは有効な初期化方法である。

ただし、NULLのまま間接参照してはいけない。

```c
*p = 50;
```

これは未定義動作になる。

## 12-2. NULLと未初期化ポインタの違い

| 種類 | 意味 |
|---|---|
| 未初期化ポインタ | 値が不定である |
| NULLポインタ | どのオブジェクトも指していないことが明示されている |

NULLで初期化したポインタは、安全にNULL比較できる。

ただし、NULLを間接参照することはできない。

# 13. NULL確認と早期リターン

## 13-1. 正しいNULL確認

```c
if (p == NULL) {
    return;
}
```

これは、pがNULLなら関数を終了するという意味である。

## 13-2. NULLではない場合の確認

```c
if (p != NULL) {
    // 通常の処理
}
```

### 記号の違い

| 表記 | 意味 |
|---|---|
| `==` | 等しいか比較 |
| `!=` | 等しくないか比較 |
| `!` | 論理否定 |

### 注意

```c
if (p == !NULL)
```

という書き方は誤り。

`!NULL` は整数値1になるため、ポインタのNULL確認には適切でない。

## 13-3. NULL確認の位置

重要なのは、間接参照する前にNULLを確認すること。

```c
void updateValues(int *p, int count)
{
    if (p == NULL) {
        return;
    }

    for (int i = 0; i < count; i++) {
        p[i] += 10;
    }
}
```

### 処理の流れ

1. pがNULLか確認する。
2. NULLならreturnで関数を終了する。
3. NULLでなければfor文で配列を処理する。

今回、NULL確認をfor文の中で値にアクセスした後に置いてしまった。

しかし、値にアクセスした時点ですでに間接参照が発生する。

そのため、NULL確認を先に行う必要がある。

## 13-4. returnの意味

```c
return;
```

は、現在実行している関数をその場で終了する。

void型関数では、戻り値なしのreturnを使用できる。

### 重要

returnは、for文だけを終了する命令ではない。

関数そのものを終了する。

呼び出し元の関数では、関数呼び出しの次の処理から実行が続く。

### breakとの違い

| 表記 | 意味 |
|---|---|
| `return` | 関数を終了する |
| `break` | 最も内側のループまたはswitch文を終了する |
| `continue` | ループの現在の繰り返しの残りを飛ばす |

# 14. 複数のポインタのNULL確認

## 14-1. ポインタ引数が複数ある場合

```c
void updateControl(int *p1, int *p2, const char **pp)
```

この関数は3つのポインタを受け取っている。

- p1：int型を指すポインタ
- p2：int型を指すポインタ
- pp：const char型を指すポインタへのポインタ

いずれかがNULLの場合に処理を終了するなら、次のように書く。

```c
if (p1 == NULL || p2 == NULL || pp == NULL) {
    return;
}
```

## 14-2. なぜORを使うのか

```c
||
```

は論理OR演算子。

いずれかの条件が真なら、全体が真になる。

今回の場合、1つでもNULLなら関数を終了する。

## 14-3. 二重ポインタのNULL確認

```c
pp == NULL
```

と

```c
*pp == NULL
```

は違う。

| 表記 | 確認対象 |
|---|---|
| `pp == NULL` | 二重ポインタpp自身がNULLか |
| `*pp == NULL` | ppが指しているポインタ変数の値がNULLか |
| `&pp == NULL` | ppという変数自身のアドレスとNULLの比較 |

今回、`&pp == NULL` と書いてしまった。

しかし、確認したいのは関数が受け取ったppに保存されているアドレスだった。

そのため、

```c
pp == NULL
```

が正しい。

### 注意

`*pp` を評価するためには、先にppがNULLではないことを確認する必要がある。

`*pp` 自身がNULLかどうかも確認したい場合は、次のようにできる。

```c
if (pp == NULL || *pp == NULL) {
    return;
}
```

論理ORは左から評価され、左側が真なら右側を評価しない。

そのため、ppがNULLなら`*pp`は評価されない。

ただし、今回の最終課題で要求されたのは、関数が受け取ったポインタ引数そのもののNULL確認である。

# 15. 未定義動作（Undefined Behavior）

## 15-1. 未定義動作とは

C言語の規格が、プログラムの動作を保証していない状態のこと。

未定義動作が発生すると、どのような結果になるか保証されない。

### 発生し得る現象

- プログラムが異常終了する。
- 意図しない結果になる。
- メモリの内容が破壊される。
- 一見正常に動いているように見える。

必ずエラーになるとは限らない。

## 15-2. 代表的な原因

### NULLポインタの間接参照

```c
int *p = NULL;

*p = 50;
```

### 配列の範囲外アクセス

```c
int values[3] = {10, 20, 30};

values[3] = 40;
```

### 未初期化ポインタの使用

```c
int *p;

*p = 50;
```

### 重要

NULLを確認するだけで、すべてのポインタ操作が安全になるわけではない。

ポインタが有効なオブジェクトを指していること、そのオブジェクトの寿命が続いていること、アクセス範囲が正しいことも重要である。

# 16. 文字列とポインタ

## 16-1. 文字列リテラル

```c
const char *mode = "RUN";
```

この場合、modeは文字列リテラル"RUN"の先頭文字のアドレスを保持する。

文字列は次のようなchar配列として存在する。

```text
[0]  'R'
[1]  'U'
[2]  'N'
[3]  '\0'
```

"RUN"は終端文字を含めて4要素分の配列である。

文字列全体がポインタ変数modeの中に入っているわけではない。

## 16-2. 文字列の表記

```c
const char *mode = "RUN";
```

| 表記 | 意味 |
|---|---|
| `mode` | 文字列の先頭アドレス |
| `*mode` | 先頭文字'R' |
| `mode[0]` | 先頭文字'R' |
| `mode[1]` | 2番目の文字'U' |
| `mode[2]` | 3番目の文字'N' |
| `mode[3]` | 終端文字'\0' |

### 重要

```c
mode[0] == *(mode + 0)
```

ポインタでも配列の添字表記を使用できる。

ただし、アクセス先が有効な範囲内にあることが必要。

---

# 17. 文字列リテラルとchar配列の違い

## 17-1. 文字列リテラルを指すポインタ

```c
const char *mode = "RUN";
```

この場合、

```c
mode = "STOP";
```

は可能。

ポインタが指す先を変更しているためである。

一方、

```c
mode[0] = 'S';
```

はできない。

constによって、指す先の文字の変更が禁止されている。

また、constを外しても文字列リテラル自体を書き換える操作は未定義動作になる。

## 17-2. 変更可能なchar配列

```c
char mode[5] = "RUN";
```

この場合、文字を変更できる。

```c
mode[0] = 'S';
mode[1] = 'T';
mode[2] = 'O';
mode[3] = 'P';
mode[4] = '\0';
```

これにより、配列には"STOP"が保存される。

### 注意

"RUN"に必要なのは4要素。

"STOP"に必要なのは5要素。

終端文字を含めた領域を確保する必要がある。

## 17-3. 重要な違い

| 書き方 | 意味 |
|---|---|
| `mode = "STOP";` | ポインタの指す先を変更 |
| `mode[0] = 'S';` | 指す先の最初の文字を変更 |
| `*mode = 'S';` | 指す先の最初の文字を変更 |

文字列の先頭アドレスを変更することと、文字列の中身を変更することは違う。

# 18. constとポインタ

## 18-1. const char *

```c
const char *mode = "RUN";
```

これは、ポインタを通して指す先の文字を変更できないという意味。

ただし、ポインタ自身が保持するアドレスは変更できる。

```c
mode = "STOP";
```

これは可能。

## 18-2. char *const

```c
char text[] = "RUN";

char *const p = text;
```

これは、ポインタ自身が保持するアドレスを変更できないという意味。

ただし、指している先が変更可能な領域であれば、文字は変更できる。

```c
p[0] = 'F';
```

これは可能。

### constの違い

| 宣言 | 指す先の値 | ポインタ自身のアドレス値 |
|---|---|---|
| `const char *p` | 変更不可 | 変更可能 |
| `char *const p` | 変更可能な領域なら変更可能 | 変更不可 |
| `const char *const p` | 変更不可 | 変更不可 |

# 19. 二重ポインタ

今回、ロードマップに追加して学習した内容。

## 19-1. 二重ポインタとは

ポインタ変数自身のアドレスを保存するポインタである。

```c
int speed = 30;

int *p = &speed;

int **pp = &p;
```

### メモリの関係

```text
pp → p → speed
```

仮に次のアドレスだったとする。

| 変数 | 自身のアドレス | 保存している値 |
|---|---|---|
| speed | 1000 | 30 |
| p | 2000 | 1000 |
| pp | 3000 | 2000 |

## 19-2. 二重ポインタの表記

| 表記 | 意味 | 仮の値 |
|---|---|---|
| `pp` | p自身のアドレス | 2000 |
| `*pp` | pに保存されたアドレス | 1000 |
| `**pp` | speedに保存された値 | 30 |
| `&pp` | pp自身のアドレス | 3000 |

### 最重要法則

```c
pp   == &p
*pp  == p
**pp == *p
```

この関係は、

```c
int **pp = &p;
```

としている場合に成立する。

## 19-3. 宣言と間接参照の違い

```c
int **pp = &p;
```

これは二重ポインタ変数ppの宣言と初期化。

一方、

```c
**pp = 50;
```

これはppを二段階間接参照し、最終的に指しているint型変数の値を50に変更する。

宣言にある`**`と、式で使う`**`は区別する。

---

# 20. 二重ポインタによる値とアドレスの変更

```c
int speed = 30;
int backupSpeed = 70;

int *p = &speed;

int **pp = &p;
```

## 20-1. 指す先の値を変更する

```c
**pp = 50;
```

この場合、speedの値が50になる。

## 20-2. ポインタ自身が保持するアドレスを変更する

```c
*pp = &backupSpeed;
```

この場合、pがbackupSpeedを指すようになる。

### 重要

| 書き方 | 変更する対象 |
|---|---|
| `*pp = &backupSpeed;` | pに保存されているアドレス |
| `**pp = 50;` | pが指す先のint型変数の値 |

つまり、

```c
*pp == p
```

であるため、

```c
*pp = &backupSpeed;
```

は、今回の関係では

```c
p = &backupSpeed;
```

と同じ変数を変更している。

# 21. 二重ポインタと関数

## 21-1. なぜ二重ポインタを使用するのか

別関数から、呼び出し元のポインタ変数が保持するアドレスを変更したい場合に使用できる。

### 通常のポインタの場合

```c
void changePointer(int *p)
{
    // p自身を変更しても、
    // 呼び出し元のポインタ変数には反映されない
}
```

これはポインタが値渡しされるためである。

### 二重ポインタの場合

```c
void changePointer(int **pp, int *newAddress)
{
    *pp = newAddress;
}
```

二重ポインタを通して、呼び出し元のポインタ変数を変更できる。

## 21-2. main関数からの受け渡し

```c
int speed = 30;
int backupSpeed = 70;

int *selected = &speed;
```

selected自身のアドレスを関数に渡す。

```c
changePointer(&selected, &backupSpeed);
```

あるいは、

```c
int **pp = &selected;

changePointer(pp, &backupSpeed);
```

としてもよい。

### 重要

```c
pp == &selected
```

という関係なので、どちらもselected自身のアドレスを渡している。

### 理解の法則

変更したい変数が普通のint型なら、そのint型変数のアドレスを渡す。

変更したい変数がint型ポインタなら、そのポインタ変数自身のアドレスを渡す。

どちらも「変更したい変数のアドレスを渡す」という同じ仕組みである。

---

# 22. 文字列と二重ポインタ

## 22-1. 別関数から文字列の指す先を変更する

```c
#include <stdio.h>

void changeMode(const char **pp);

int main(void)
{
    const char *mode = "RUN";

    const char **pp = &mode;

    changeMode(pp);

    printf("%s\n", *pp);

    return 0;
}

void changeMode(const char **pp)
{
    *pp = "STOP";
}
```

実行結果：

```text
STOP
```

### 処理の流れ

1. modeが"RUN"の先頭アドレスを保持する。
2. ppがmode自身のアドレスを保持する。
3. changeMode関数にppを渡す。
4. `*pp = "STOP";` によりmodeに保存されたアドレスを変更する。
5. modeが"STOP"を指すようになる。

## 22-2. 二重ポインタと文字列の表記

```c
const char *mode = "STOP";

const char **pp = &mode;
```

| 表記 | 意味 |
|---|---|
| `pp` | mode自身のアドレス |
| `*pp` | 文字列の先頭アドレス |
| `**pp` | 文字列の先頭文字'S' |

### printfとの関係

```c
printf("%s\n", *pp);
```

これは正しい。

`%s`には文字列の先頭アドレスを渡す。

一方、

```c
printf("%s\n", **pp);
```

これは誤り。

`**pp`はchar型の文字1つであり、文字列の先頭アドレスではない。

文字1つを表示する場合は、

```c
printf("%c\n", **pp);
```

とする。

# 23. 二重ポインタのNULL確認

## 23-1. 表記の違い

```c
const char **pp;
```

この場合、

```c
pp
```

は二重ポインタに保存されているアドレス。

```c
*pp
```

はppが指すポインタ変数に保存されているアドレス。

```c
**pp
```

は、そのポインタが指している先の文字。

```c
&pp
```

は二重ポインタ変数pp自身のアドレス。

## 23-2. NULL確認で使用する表記

関数の引数で受け取ったpp自身がNULLかどうか確認したいなら、

```c
if (pp == NULL) {
    return;
}
```

とする。

### 間違えた書き方

```c
if (&pp == NULL) {
    return;
}
```

これはppというローカル変数自身のアドレスを確認している。

関数から渡されたアドレスがNULLかどうかを調べる目的には合わない。

### 重要

NULL確認では、どのポインタのどの段階を確認したいのかを明確にする。

# 24. for文・if文・returnの組み合わせ

今回の総合課題で重要だった部分。

## 24-1. 先に安全性を確認する

```c
void updateValues(int *p, int count)
{
    if (p == NULL) {
        return;
    }

    for (int i = 0; i < count; i++) {
        p[i] += 10;
    }
}
```

NULL確認をfor文の前に置く。

## 24-2. elseでreturnするとどうなるか

```c
for (int i = 0; i < count; i++) {
    if (p[i] <= 20) {
        // 条件成立時の処理
    } else {
        return;
    }
}
```

これは、20より大きい値が1つでも見つかると、関数全体を終了してしまう。

全要素を調べたい場合には適さない。

## 24-3. 全要素を調べる場合

```c
for (int i = 0; i < count; i++) {
    if (p[i] <= 20) {
        // 条件成立時の処理
    }
}
```

elseでreturnしなければ、条件に一致しなかった場合も次の要素へ進める。

### 重要

`return;`は、処理を本当に終了してよい場合だけ使用する。

# 25. 今回の学習で発生した主な間違い

## 25-1. ポインタの宣言忘れ

誤り：

```c
speed = 20;
```

まだspeedを宣言していなければコンパイルエラーになる。

正しくは、

```c
int speed = 20;
```

## 25-2. 代入と減算代入の混同

```c
p[i] = -10;
```

これは-10を代入する。

```c
p[i] -= 10;
```

これは現在の値から10を減らす。

## 25-3. ポインタの移動と値の変更の混同

```c
p += 1;
```

ポインタが次の要素へ移動する。

```c
*p += 1;
```

現在指している値が1増える。

## 25-4. NULL確認の位置

誤り：

```c
p[i] -= 10;

if (p == NULL) {
    return;
}
```

ポインタを間接参照した後に確認している。

正しくは間接参照前に確認する。

## 25-5. 二重ポインタのNULL確認

誤り：

```c
&pp == NULL
```

受け取った二重ポインタ自身を確認するなら、

```c
pp == NULL
```

である。

## 25-6. for文の途中でreturn

全要素を調べる必要があるのに、最初の条件不成立でreturnしてしまった。

returnは関数全体を終了することを再確認した。

## 25-7. 文字列とprintf

```c
printf("%s\n", **pp);
```

は誤り。

二重ポインタppが指すポインタに文字列の先頭アドレスが保存されている場合、

```c
printf("%s\n", *pp);
```

を使用する。

# 26. 総合的に理解した重要な法則

## 26-1. 普通のポインタ

```c
int value = 20;
int *p = &value;
```

```c
p       // valueのアドレス
*p      // valueの値
&p      // p自身のアドレス
```

## 26-2. 配列とポインタ

```c
int values[5] = {10, 20, 30, 40, 50};
int *p = values;
```

```c
p[i]       == *(p + i)
&p[i]      == p + i
p          == &p[0]
```

## 26-3. 二重ポインタ

```c
int value = 20;
int *p = &value;
int **pp = &p;
```

```c
pp   == &p
*pp  == p
**pp == *p
```

## 26-4. 変更対象の違い

```c
p = &value;
```

ポインタ自身に保存されるアドレスを変更する。

```c
*p = 50;
```

ポインタが指す先の値を変更する。

```c
*pp = &value;
```

二重ポインタが指すポインタ変数に保存されるアドレスを変更する。

```c
**pp = 50;
```

二重ポインタを二段階たどった先の値を変更する。

## 理解が深まったこと

# 30. 今後も意識すること

今回の学習で理解できた内容でも、コードを作成するときに表記を混同する場面があった。

特に次の点に注意する。

- `p`、`*p`、`&p`を区別する。
- `pp`、`*pp`、`**pp`、`&pp`を区別する。
- 宣言時の`*`と、式の中で使用する`*`を区別する。
- ポインタを移動するのか、値を変更するのかを明確にする。
- 関数の引数として渡す対象を確認する。
- NULL確認を間接参照より前に行う。
- 複数のポインタ引数がある場合は、それぞれ確認する。
- 配列の要素数と添字の範囲を区別する。
- returnによって処理が途中で終了してよいか確認する。
- 文字列リテラルの指す先の変更と、文字の書き換えを区別する。
