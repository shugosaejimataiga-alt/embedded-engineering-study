## 2. ローカル変数に対するstatic

### 2-1. 通常のローカル変数

関数内で宣言した通常のローカル変数は、関数が呼び出されるたびに生成され、関数の処理が終了すると寿命が終わる。

例：

```c
#include <stdio.h>

void count(void)
{
    int number = 0;

    number++;

    printf("%d\n", number);
}

int main(void)
{
    count();
    count();
    count();

    return 0;
}
```

実行結果：

```text
1
1
1
```

理由：

- 関数が呼び出されるたびに `number` が初期化される。
- 毎回0から始まる。
- 1を加算して表示する。
- 次回の関数呼び出しには前回の値が引き継がれない。

### 2-2. staticローカル変数

関数内のローカル変数に `static` を付けると、関数の処理が終了しても変数の値が保持される。

例：

```c
#include <stdio.h>

void count(void)
{
    // 初期化はプログラム実行中に一度だけ行われる
    static int number = 0;

    number++;

    printf("%d\n", number);
}

int main(void)
{
    count();
    count();
    count();

    return 0;
}
```

実行結果：

```text
1
2
3
```

理由：

- `number` は最初に0で初期化される。
- 1回目の呼び出しで1になる。
- 関数が終了しても1が保持される。
- 2回目の呼び出しで2になる。
- 3回目の呼び出しで3になる。

### 2-3. 重要なポイント

通常のローカル変数：

- 関数の実行ごとに生成される。
- 関数終了時に寿命が終わる。
- 前回の値は保持されない。

staticローカル変数：

- プログラムの実行中、値が保持される。
- 初期化は一度だけ行われる。
- 関数が再び呼び出されても前回の値が残っている。
- 変数を名前で使用できる範囲は宣言されたブロック内のまま。

つまり、関数内の `static` は、主に変数の寿命を変えるために使用される。

## 3. ファイルスコープの変数に対するstatic

関数の外で定義した変数に `static` を付けると、別の翻訳単位からその変数名を使って直接参照できなくなる。

通常、今回のような構成では1つの `.c` ファイルが1つの翻訳単位になる。

例：

```c
// motor.c

static int changeCount = 0;
```

この場合、`changeCount` は `motor.c` 内で管理する変数になる。

別ファイルの `main.c` から、

```c
extern int changeCount;
```

と宣言しても、`motor.c` の `static` 変数にはリンクできない。

### 3-1. 同じファイル内では使用できる

```c
// motor.c

static int changeCount = 0;

void increaseSpeed(void)
{
    changeCount++;
}
```

このコードは正しい。

理由：

- `changeCount` はファイルスコープの変数である。
- `increaseSpeed()` は同じ `motor.c` 内にある。
- `static` は同じファイル内からのアクセスを禁止するものではない。

### 3-2. 重要なポイント

関数の外で定義した変数は、通常のグローバル変数でも `static` 変数でも、プログラムの実行中は値が保持される。

そのため、ファイルスコープの変数に付ける `static` は、主に外部からの名前によるアクセスを制限するために使用される。

---

## 4. 関数に対するstatic

`static` は変数だけでなく、関数にも付けられる。

### 4-1. staticがない関数

```c
void increaseSpeed(void)
{
    // 処理
}
```

この関数は外部リンケージを持つ。

別ファイルから適切に宣言し、リンクすれば呼び出せる。

### 4-2. staticがある関数

```c
static void resetCount(void)
{
    // 処理
}
```

この関数は内部リンケージを持つ。

別の `.c` ファイルから、その関数名を使って直接呼び出すことはできない。

### 4-3. 使い分け

外部に公開する関数：

```c
void increaseSpeed(void);
```

ファイル内部だけで使用する関数：

```c
static void resetCount(void);
```

このように、必要な関数だけを外部に公開する設計ができる。

---

## 5. externの役割

`extern` は、別の場所で定義されている変数などを宣言する際に使用する。

### 5-1. 変数の定義

```c
// motor.c

int speed = 10;
```

これは変数の定義である。

`speed` というint型の変数を実際に用意し、初期値10を設定する。

### 5-2. 変数の宣言

```c
// main.c

extern int speed;
```

これは変数の宣言である。

意味：

「`speed` というint型の変数が別の場所に定義されている」

コンパイラにその変数の存在と型を知らせる。

`extern int speed;` 自体は、新しく変数の実体を作るものではない。

### 5-3. 宣言と定義の違い

```c
int speed = 10;
```

- 変数の定義
- 実際の変数を用意する
- 初期値10を設定する

```c
extern int speed;
```

- 変数の宣言
- 別の場所にある変数を使用できるようにする
- 新しい変数の実体は作らない

### 5-4. externを使って別ファイルの変数を操作する

motor.c：

```c
int speed = 10;
```

main.c：

```c
#include <stdio.h>

extern int speed;

int main(void)
{
    speed += 5;

    printf("%d\n", speed);

    return 0;
}
```

実行結果：

```text
15
```

両方のファイルをコンパイル・リンクすることで、同じ変数を扱えるようになる。

## 6. 内部リンケージと外部リンケージ

リンケージとは、異なる場所に書かれた同じ名前の宣言が、同じ変数や関数を指すかどうかを決める仕組みである。

### 6-1. 内部リンケージ

例：

```c
static int changeCount = 0;
```

```c
static void resetCount(void)
{
    changeCount = 0;
}
```

特徴：

- 同じ翻訳単位内で名前を共有できる。
- 別の翻訳単位から、その名前で直接参照できない。
- ファイル内部の実装を隠すために利用できる。

### 6-2. 外部リンケージ

例：

```c
int speed = 10;
```

```c
void increaseSpeed(void)
{
    speed += 5;
}
```

特徴：

- 異なる翻訳単位からも同じ変数や関数を参照できる。
- 別ファイル側で適切な宣言が必要になる。
- リンカによって宣言と定義の対応が解決される。

### 6-3. まとめ

```c
// 内部リンケージ
static int count = 0;

// 外部リンケージ
int speed = 10;

// 内部リンケージ
static void reset(void)
{
    count = 0;
}

// 外部リンケージ
void update(void)
{
    speed++;
}
```

重要なのは、`static` を付けることで、変数や関数を外部に公開するかどうかを制御できる点である。

なお、関数内の通常のローカル変数は、内部リンケージではなくリンケージを持たない。

## 7. ヘッダーファイルとexternの関係

今回、特に理解が深まった部分。

### 7-1. ヘッダーファイルは関数宣言専用ではない

`.h` ファイルには、以下の内容を記述できる。

- 関数の宣言
- 外部変数の宣言
- 構造体や列挙型などの型定義
- typedef
- マクロ定義

つまり、ヘッダーファイルは、複数ファイルで共有する宣言や定義をまとめるために使用する。

### 7-2. externをmain.cに直接書く方法

motor.c：

```c
int speed = 10;
```

main.c：

```c
#include <stdio.h>

extern int speed;

int main(void)
{
    printf("%d\n", speed);

    return 0;
}
```

この方法でも正しい。

### 7-3. externをmotor.hに書く方法

motor.h：

```c
#ifndef MOTOR_H
#define MOTOR_H

extern int speed;

#endif
```

main.c：

```c
#include <stdio.h>
#include "motor.h"

int main(void)
{
    printf("%d\n", speed);

    return 0;
}
```

こちらも正しい。

### 7-4. なぜヘッダーファイルから宣言を利用できるのか

```c
#include "motor.h"
```

この指示によって、プリプロセッサが `motor.h` の内容を `main.c` に展開する。

例えば、ヘッダーファイル内に、

```c
extern int speed;
```

と書かれていれば、その宣言が `main.c` に取り込まれる。

したがって、`main.c` に同じ宣言を直接書き直す必要はない。

### 7-5. どちらの方法がよいか

方法①：

```c
// main.c
extern int speed;
```

方法②：

```c
// motor.h
extern int speed;
```

```c
// main.c
#include "motor.h"
```

どちらもC言語として正しい。

ただし、複数のファイルで同じ変数を使用する場合は、ヘッダーファイルに宣言をまとめる方が管理しやすい。

また、ヘッダーファイルに公開する宣言をまとめることで、宣言の食い違いを防ぎやすくなる。

## 8. コンパイラとリンカとの関係

Day34で学んだコンパイルとリンクの仕組みも復習した。

### 8-1. なぜmain.cでmotor.cをincludeしなくてもよいのか

motor.c：

```c
int speed = 10;
```

main.c：

```c
#include <stdio.h>

extern int speed;

int main(void)
{
    printf("%d\n", speed);

    return 0;
}
```

この場合、`main.c` に、

```c
#include "motor.c"
```

と書く必要はない。

理由は、別ファイルの変数や関数の実体を結びつける役割がリンカにあるからである。

### 8-2. 処理の流れ

```text
main.c
  ↓
前処理・コンパイル・アセンブル
  ↓
main.o
                         ┐
                         │
                         ↓
                       リンカ
                         ↑
                         │
                         ┘
motor.o
  ↑
前処理・コンパイル・アセンブル
  ↑
motor.c

リンカがmain.oとmotor.oを結びつける
  ↓
実行ファイル
```

※上図は概念的な流れ。

### 8-3. それぞれの役割

プリプロセッサ：

- `#include` に従ってヘッダーの内容を展開する。
- マクロや条件付きコンパイルを処理する。

コンパイラ：

- 構文や型の整合性などを確認する。
- 関数の宣言と定義の不一致などを検出する。

リンカ：

- オブジェクトファイル同士を結びつける。
- 外部参照されている変数や関数の定義を探す。
- 未定義参照や多重定義などを検出する。

### 8-4. ヘッダーの重要性

例えば、motor.hに、

```c
void increaseSpeed(void);
```

と宣言されているのに、motor.cで、

```c
void increaseSpeed(int value)
{
}
```

と定義してしまった場合。

motor.cがmotor.hをインクルードしていれば、コンパイラが宣言と定義の不一致を検出できる。

これにより、コンパイル段階で不具合を発見しやすくなる。

## 9. 引数と戻り値の復習

今回のプログラムでは、`void` と `return` の役割も復習した。

### 9-1. voidの意味

```c
void increaseSpeed(void)
{
    speed += 5;
}
```

最初の `void`：

- 戻り値がないことを表す。

括弧内の `void`：

- 引数がないことを表す。

### 9-2. 引数なしでもグローバル変数を変更できる

```c
int speed = 10;

void increaseSpeed(void)
{
    speed += 5;
}
```

`speed` は関数の外で定義されたファイルスコープの変数である。

そのため、同じファイル内の `increaseSpeed()` から直接操作できる。

必ずしも引数として渡す必要はない。

### 9-3. 戻り値を返す関数

```c
int getChangeCount(void)
{
    return changeCount;
}
```

意味：

- 戻り値の型はint型。
- 引数はない。
- `changeCount` の値を呼び出し元に返す。

### 9-4. 戻り値を変数に保存する場合

```c
int get1 = getChangeCount();

printf("%d\n", get1);
```

関数の戻り値を `get1` に保存して表示する。

### 9-5. 戻り値を直接使う場合

```c
printf("%d\n", getChangeCount());
```

戻り値は必ず変数に保存する必要はない。

その場で直接利用することもできる。

使い分け：

- 後の処理でも値を利用するなら変数に保存する。
- その場で利用するだけなら直接渡してもよい。

## 10. staticとカプセル化の関係

今回、Javaで学習したカプセル化との関連も確認した。

### 10-1. カプセル化とは

内部のデータや処理を隠し、外部には必要な操作だけを公開する設計の考え方。

### 10-2. C言語での例

motor.c：

```c
static int changeCount = 0;

int getChangeCount(void)
{
    return changeCount;
}
```

この場合、

- `changeCount` は別ファイルから名前で直接参照できない。
- `getChangeCount()` は外部から呼び出せる。
- 外部ファイルは関数を通して値を取得できる。

### 10-3. なぜstatic変数の値を別ファイルに返せるのか

`static` が制限するのは、別ファイルから変数名を使って直接参照することである。

変数の値を関数の戻り値として返すことは禁止していない。

処理の流れ：

1. `main.c` が `getChangeCount()` を呼び出す。
2. `motor.c` 内の関数が `changeCount` を読み取る。
3. `return` で値を返す。
4. `main.c` が返された値を利用する。

このとき、int型の値がコピーされて返される。

そのため、外部ファイルから内部変数を直接変更することなく、必要な情報だけ取得できる。

### 10-4. Javaとの比較

Java：

```java
class Motor {
    private int changeCount = 0;

    public int getChangeCount() {
        return changeCount;
    }
}
```

C言語：

```c
static int changeCount = 0;

int getChangeCount(void)
{
    return changeCount;
}
```

Javaの `private` とC言語のファイルスコープの `static` は、アクセス制御の仕組みや範囲が異なる。

しかし、内部データを隠し、公開された処理を通して利用するという考え方は共通している。

# 11. 最終課題：モーター速度管理プログラム

今回の学習内容を組み合わせて、複数ファイルから構成されるプログラムを作成した。

## 11-1. ファイル構成

```text
main.c
motor.c
motor.h
```

### プログラムの仕様

- モーター速度の初期値は10。
- 速度変更回数の初期値は0。
- `increaseSpeed()` を呼び出すと速度が5増加する。
- 同時に変更回数が1増加する。
- `changeCount` は `motor.c` の内部だけで管理する。
- `getChangeCount()` を通して変更回数を取得する。
- main.cで速度変更を3回実行する。
- 最後に速度と変更回数を表示する。

---

## 11-2. motor.h

```c
#ifndef MOTOR_H
#define MOTOR_H

// 別の場所で定義される変数の宣言
extern int speed;

// モーター速度を増加させる関数の宣言
void increaseSpeed(void);

// 速度変更回数を取得する関数の宣言
int getChangeCount(void);

#endif
```

### ポイント

- インクルードガードを使用する。
- 外部公開する変数を `extern` で宣言する。
- 外部公開する関数のプロトタイプを書く。
- 内部専用の `changeCount` は宣言しない。

---

## 11-3. motor.c

```c
#include "motor.h"

// モーター速度
int speed = 10;

// motor.c内部でのみ管理する変更回数
static int changeCount = 0;

// モーター速度と変更回数を増加させる
void increaseSpeed(void)
{
    speed += 5;
    changeCount++;
}

// 変更回数を返す
int getChangeCount(void)
{
    return changeCount;
}
```

### ポイント

`int speed = 10;`

- 外部リンケージを持つ変数。
- 別ファイルから宣言して参照できる。

`static int changeCount = 0;`

- 内部リンケージを持つ変数。
- motor.c内で管理する。
- 外部ファイルから変数名で直接参照できない。

`increaseSpeed()`

- speedを5増加させる。
- changeCountを1増加させる。
- 外部から呼び出せる。

`getChangeCount()`

- changeCountの値を返す。
- 外部ファイルから内部の変更回数を取得できる。

---

## 11-4. main.c

```c
#include <stdio.h>
#include "motor.h"

int main(void)
{
    increaseSpeed();
    increaseSpeed();
    increaseSpeed();

    printf("%d\n", speed);
    printf("%d\n", getChangeCount());

    return 0;
}
```

### ポイント

`#include "motor.h"`

- 公開されている変数や関数の宣言を取り込む。

`increaseSpeed()`

- 3回呼び出して速度を変更する。

`printf("%d\n", speed);`

- 公開された変数speedの値を表示する。

`printf("%d\n", getChangeCount());`

- 関数の戻り値を直接printfに渡す。
- changeCountを直接参照せず、関数を通して値を取得する。

## 13. 今回理解が深まった重要事項

### ① staticの意味は宣言する場所によって異なる

関数内：

- 前回の値を保持する。
- 関数終了後も変数の寿命が続く。

ファイルスコープ：

- 内部リンケージにする。
- 別ファイルから変数名で直接参照できなくする。

関数定義：

- 内部リンケージにする。
- 別ファイルから関数名で直接呼び出せなくする。

### ② externは別ファイルを取り込む命令ではない

`extern` は変数などの宣言に使用する。

`.c` ファイル同士の結びつけはリンカが行う。

### ③ ヘッダーファイルは宣言を共有する

`#include` によってヘッダーファイルの内容が展開される。

ヘッダーには関数宣言だけでなく、変数宣言や型定義も書ける。

### ④ motor.cをmain.cにincludeする必要はない

複数の `.c` ファイルをビルド対象に指定すれば、リンカが外部参照を解決する。

### ⑤ 関数は引数なしでもグローバル変数を操作できる

スコープ内にある変数なら、引数として渡さなくても直接参照できる。

### ⑥ static変数でも関数を通して値を返せる

`static` が禁止するのは外部からの名前による直接参照であり、値を返すことではない。

### ⑦ 戻り値は変数に保存しなくてもよい

戻り値はその場でほかの関数に渡したり、計算に利用したりできる。

### ⑧ Javaのカプセル化と共通する考え方がある

C言語でも `static` と公開関数を組み合わせて、データを内部に隠す設計ができる。
