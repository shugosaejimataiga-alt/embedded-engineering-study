# C-Day22 ポインタによる値の操作

## 学習内容

- ポインタを通した値の読み取り
- ポインタを通した値の変更
- `NULL`
- 未初期化ポインタ
- 不正なアドレスへのアクセス
- `p`、`*p`、`&p` の違い
- `NULL`チェックの意味

---

## 1. ポインタとは

ポインタは、メモリアドレスを保存するための変数。

```c
int number = 30;
int *p = &number;
```

この場合、

- `number` は `int` 型の変数
- `&number` は `number` 自身のメモリアドレス
- `p` は `&number` を保存しているポインタ変数

となる。

```text
number → 30
&number → numberのメモリアドレス
p → &number
```

---

## 2. 宣言時の `*`

```c
int *p;
```

この場合の `*` は間接参照ではない。

`p` を「int型の変数を指すためのポインタ」として宣言するための `*`。

実際に作られる変数名は `p`。

```c
int *p = &number;
```

は、

「int型の変数を指すポインタ `p` を宣言し、`number` のメモリアドレスを保存する」

という意味。

---

## 3. `p` と `*p`

```c
int number = 30;
int *p = &number;
```

この場合、

```text
p  → numberのメモリアドレス
*p → そのメモリアドレスにある値（30）
```

`*p` のように、ポインタが保存しているメモリアドレスを使って、その先の値へアクセスすることを「間接参照」という。

例えば、

```c
printf("%d\n", *p);
```

では `30` が表示される。

---

## 4. ポインタを使った値の変更

```c
int number = 30;
int *p = &number;

*p = 100;
```

`*p = 100;` は、

「pが指しているメモリアドレスにある値を100に変更する」

という意味。

そのため、

```text
number = 100
```

になる。

ポインタそのものを書き換えているのではなく、ポインタの指し先にある値を書き換えている。

---

## 5. `&p`

```c
&p
```

は、ポインタ変数 `p` 自身のメモリアドレス。

例えば、

```text
number
値：30
アドレス：0x1000

p
値：0x1000
アドレス：0x2000
```

なら、

```text
p       → 0x1000（numberのアドレス）
*p      → 30（numberの値）
&p      → 0x2000（p自身のアドレス）
```

となる。

---

## 6. `NULL`

```c
int *p = NULL;
```

これは、

「ポインタ変数 `p` を宣言して、その `p` に `NULL` を入れる」

という意味。

宣言時の `*` は、`*p` に `NULL` を代入しているという意味ではない。

次の2つは同じ考え方。

```c
int *p = NULL;
```

```c
int *p;
p = NULL;
```

`NULL` が入っている場合、

```text
p → NULL
```

となり、有効なメモリアドレスを指していない。

つまり、

「pの箱にはNULLが入っているが、メモリアドレスへの指し先はない」

という状態。

---

## 7. `p = NULL` と `*p` の違い

```c
p = NULL;
```

は、ポインタ `p` の中身を `NULL` にする。

つまり指し先をなくす。

一方、

```c
*p = 50;
```

は、`p` が指しているメモリアドレスにある値を `50` に変更する。

整理すると、

```text
p      → ポインタが保存しているメモリアドレス
*p     → そのメモリアドレスにある値
&p     → ポインタ変数p自身のメモリアドレス
p=NULL → pには有効な指し先がない
```

---

## 8. NULLポインタを間接参照してはいけない

```c
int *p = NULL;

*p = 50;
```

これは危険。

`p` はどこも指していないのに、

```c
*p
```

によって指し先の値へアクセスしようとしているため。

```text
p
↓
NULL
↓
有効な指し先がない
```

この状態で `*p` を使ってはいけない。

---

## 9. NULLチェック

ポインタを使う前に、

```c
if (p != NULL) {
    *p = 50;
}
```

のように確認できる。

`p != NULL` は、

「pに有効な指し先がある状態か」

を確認するために使う。

`p == NULL` の場合は指し先がないので、`*p` を使用してはいけない。

---

## 10. 未初期化ポインタ

```c
int *p;
```

この時点で `p` はポインタとして宣言されている。

ただし、中身は未初期化なので、何が入っているか分からない。

その状態で、

```c
*p = 100;
```

としてはいけない。

`p` がどこを指しているか分からないため、不正なメモリを書き換えたり、プログラムが異常終了したりする可能性がある。

---

## 11. 未初期化ポインタとNULLポインタの違い

### 未初期化

```c
int *p;
```

- `p` はポインタ
- 中身が何か分からない
- 指し先も分からない
- そのまま `*p` を使ってはいけない

### NULLで初期化

```c
int *p = NULL;
```

- `p` はポインタ
- `p` の中身は `NULL`
- 指し先がないことが明確
- そのまま `*p` を使ってはいけない
- `p == NULL` で状態を判定できる

NULLポインタもそのまま間接参照すれば危険だが、未初期化ポインタと違い「指し先がない」と明確に分かるため安全に管理しやすい。

---

## 12. 安全にポインタを使う例

```c
#include <stdio.h>

int main(void)
{
    int number = 25;
    int *p = NULL;

    p = &number;

    if (p != NULL) {
        *p = 100;
    }

    printf("%d\n", number);

    return 0;
}
```

処理の流れ：

```text
number = 25

↓

p = NULL
まだ指し先なし

↓

p = &number
pがnumberのメモリアドレスを保存

↓

p != NULL
有効な指し先があることを確認

↓

*p = 100
numberの値を100へ変更

↓

number = 100
```

---

## 13. メモリアドレスと変数

メモリアドレスは、メモリ上に置かれている変数の場所を表す。

```c
int number = 10;
```

`number` 用のメモリ領域が確保され、その中に `10` が保存される。

```c
&number
```

は、その `number` のメモリ領域の先頭アドレスを表す。

「10のメモリアドレス」ではなく、

「10を保存している変数 `number` のメモリアドレス」

ということ。

---

## 14. データ型とメモリサイズ

データ型によって使用するメモリサイズが異なる。

例：

```text
char   → 1 byte
int    → 多くの環境で4 byte
double → 多くの環境で8 byte
```

例えば `int` が4バイトで、`number` の先頭アドレスが `0x1000` なら、

```text
0x1000
0x1001
0x1002
0x1003
```

のように4バイト分を使用する。

`&number` はその先頭アドレスを表す。

`0x` から始まる値は16進数。

## 今日特に詰まったポイント

### 宣言時の `*` と間接参照の `*`

```c
int *p;
```

この `*` はポインタを宣言するためのもの。

```c
*p = 50;
```

この `*p` は、ポインタが指している先の値へアクセスする間接参照。

同じ `*` でも意味が違う。

### `int *p = NULL;`

これは、

```text
ポインタpを宣言
+
pにNULLを代入
```

という意味。

`*p` にNULLを代入しているわけではない。

### `p` / `*p` / `&p`

```text
p  → ポインタに保存されているメモリアドレス
*p → そのメモリアドレスにある値
&p → ポインタ変数p自身のメモリアドレス
```

### NULLと未初期化

```c
int *p;
```

→ 中身が不明。

```c
int *p = NULL;
```

→ 指し先がないと明確に分かる。

どちらもそのまま `*p` を使用してはいけない。
