# 2. 構造体の基本

## 2-1. 構造体とは

構造体は、異なる型のデータを1つにまとめて管理するための仕組み。

```c
struct Vehicle {
    int number;
    int remaining;
    float speed;
};
```

この構造体には以下のメンバーが存在する。

| メンバー | 型 | 意味 |
|---|---|---|
| number | int | 車体番号 |
| remaining | int | バッテリー残量 |
| speed | float | 走行速度 |

構造体変数の宣言と初期化：

```c
struct Vehicle vehicle = {1, 80, 1.5f};
```

構造体のメンバーには`.`でアクセスできる。

```c
vehicle.number
vehicle.remaining
vehicle.speed
```

値の変更：

```c
vehicle.remaining = 50;
vehicle.speed = 0.5f;
```

## 2-2. typedefによる型名の定義

```c
typedef struct Vehicle {
    int number;
    int remaining;
    float speed;
} Vehicle;
```

これにより、構造体変数を次のように宣言できる。

```c
Vehicle vehicle = {1, 80, 1.5f};
```

`typedef`を使用していない場合は、次のように書く。

```c
struct Vehicle vehicle = {1, 80, 1.5f};
```

重要：

- `struct Vehicle`は構造体の型を表す。
- `typedef`によって`Vehicle`という別名を定義できる。
- `typedef`を使っても、構造体のデータやメモリ構造が変わるわけではない。

# 3. 構造体1個と構造体配列の違い

## 3-1. 構造体が1個の場合

```c
Vehicle vehicle = {1, 80, 1.5f};
```

この場合、構造体は1個だけ存在する。

```c
vehicle
```

これは構造体そのもの。

```c
&vehicle
```

これは構造体のメモリアドレス。

## 3-2. 構造体が複数ある場合

```c
Vehicle vehicles[3] = {
    {1, 80, 1.5f},
    {2, 50, 1.0f},
    {3, 20, 0.5f}
};
```

構造体3個を配列として管理している。

| 書き方 | 意味 |
|---|---|
| vehicles[0] | 1番目の構造体 |
| vehicles[1] | 2番目の構造体 |
| vehicles[2] | 3番目の構造体 |

メンバーへのアクセス：

```c
vehicles[0].remaining
vehicles[1].remaining
vehicles[2].remaining
```

構造体配列でも、各要素は構造体そのものなので`.`を使用する。

## 3-3. 構造体と配列は別の概念

構造体：
異なる型の複数のメンバーを1つにまとめる。

配列：
同じ型の要素を複数並べる。

構造体の配列とは、構造体型のデータを複数並べたもの。

したがって、次の2つは異なる。

```c
Vehicle vehicle;
```

構造体1個。

```c
Vehicle vehicles[3];
```

構造体3個の配列。

# 4. 構造体とメモリアドレス

## 4-1. 構造体そのものとアドレス

```c
Vehicle vehicle;
Vehicle vehicles[3];
```

| 書き方 | 意味 |
|---|---|
| vehicle | 構造体そのもの |
| &vehicle | 構造体のアドレス |
| vehicles[1] | 2番目の構造体そのもの |
| &vehicles[1] | 2番目の構造体のアドレス |

重要：

`&`は、対象のメモリアドレスを取得する演算子。

## 4-2. 配列名と先頭要素のアドレス

```c
Vehicle vehicles[3];
```

通常の式では、

```c
vehicles
```

は先頭要素のアドレスに自動変換される。

つまり、

```c
vehicles
&vehicles[0]
```

は同じ先頭要素のアドレスを表す。

ただし、配列そのものがポインタ型というわけではない。

## 4-3. 配列全体のアドレス

```c
&vehicles
```

これは、配列全体のアドレス。

比較：

| 書き方 | 意味 | 型 |
|---|---|---|
| vehicles | 通常は先頭要素のアドレスに変換 | Vehicle * |
| &vehicles[0] | 先頭の構造体のアドレス | Vehicle * |
| &vehicles | 配列全体のアドレス | Vehicle (*)[3] |

`&vehicles[0]`と`&vehicles`は同じメモリ位置を示すが、ポインタの型が異なる。

例えば、ポインタ演算を行う場合は、その型の違いが重要になる。

## 4-4. 配列名がアドレスに変換される理由

C言語では、配列型の式は通常、先頭要素を指すポインタに自動変換される。

これを「配列からポインタへの変換」という。

代表的な例外：

- `sizeof`で配列全体のサイズを取得する場合
- 単項`&`で配列全体のアドレスを取得する場合

したがって、配列名が常にポインタそのものという理解は正しくない。

# 5. 構造体ポインタの基本

## 5-1. ポインタ変数の宣言

```c
Vehicle vehicle = {1, 80, 1.5f};

Vehicle *p = &vehicle;
```

ここで、

```c
p
```

は構造体のアドレスを保存しているポインタ。

```c
*p
```

は、そのアドレスにある構造体そのものを表す。

```c
&p
```

は、ポインタ変数`p`自身のアドレス。

整理：

| 書き方 | 意味 |
|---|---|
| p | 構造体を指すポインタ |
| *p | ポインタが指す構造体そのもの |
| &p | ポインタ変数自身のアドレス |

## 5-2. ポインタが指す構造体のメンバー

```c
(*p).remaining
```

これは、`p`が指している構造体そのものにアクセスし、`remaining`メンバーを選択している。

同じ処理を次のようにも書ける。

```c
p->remaining
```

この2つは同じ意味。

```c
(*p).remaining
p->remaining
```

`->`は、ポインタが指す構造体のメンバーにアクセスする演算子。

つまり、

```c
p->remaining
```

には、実質的に`(*p).remaining`の働きが含まれている。

## 5-3. メンバーの値の変更

```c
p->remaining = 50;
```

または、

```c
(*p).remaining = 50;
```

どちらも元の`vehicle.remaining`を50に変更する。

重要：

`p`に保存されたアドレスを変更しているわけではない。

ポインタが指す先にある構造体のメンバーを変更している。

# 6. . と -> の正しい使い分け

## 6-1. 最重要ルール

**`.`と`->`は、左側にある式の型で判断する。**

| 左側の式 | 使用する演算子 |
|---|---|
| 構造体型 | . |
| 構造体を指すポインタ型 | -> |

このルールは、構造体が1個でも配列でも変わらない。

## 6-2. 構造体1個の場合

```c
Vehicle vehicle = {1, 80, 1.5f};
Vehicle *p = &vehicle;
```

```c
vehicle.remaining
p->remaining
(*p).remaining
```

すべて同じメンバーにアクセスする。

理由：

- `vehicle`は構造体型なので`.`
- `p`は構造体ポインタ型なので`->`
- `*p`は構造体型なので`.`

## 6-3. 構造体配列の場合

```c
Vehicle vehicles[3];
Vehicle *p = vehicles;
```

| 書き方 | 左側の式が表すもの | 正しい記法 |
|---|---|---|
| vehicles[1] | 構造体 | vehicles[1].remaining |
| p[1] | 構造体 | p[1].remaining |
| p + 1 | 構造体ポインタ | (p + 1)->remaining |
| &p[1] | 構造体ポインタ | (&p[1])->remaining |

これらは、すべて同じ2番目の構造体の`remaining`にアクセスする。

## 6-4. pがポインタでもp[i]は構造体

ここは今回、特に重点的に復習した内容。

```c
Vehicle *p = vehicles;
```

この場合、

```c
p
```

はポインタ。

しかし、

```c
p[i]
```

は構造体そのもの。

理由は、C言語では次の関係が成立するため。

```c
p[i] == *(p + i)
```

※ここでの`==`は記法の意味が対応することを示している。
構造体同士をC言語の`==`演算子で比較できるという意味ではない。

正確には、

```c
p[i]
```

と、

```c
*(p + i)
```

は同じ構造体要素を表す式。

したがって、

```c
p[i].remaining
```

が正しい。

一方、

```c
p[i]->remaining
```

は、今回の`Vehicle *p`では誤り。

`p[i]`はポインタではなく構造体型だから。

# 7. ポインタ演算と構造体配列

## 7-1. p + i の意味

```c
Vehicle vehicles[3];
Vehicle *p = vehicles;
```

このとき、

```c
p + 1
```

は、2番目の構造体を指すポインタ型の値。

```c
p + 2
```

は、3番目の構造体を指すポインタ型の値。

ポインタ演算では、`+1`は単純に1バイト進むという意味ではない。

ポインタが指す型の1要素分だけ進む。

例えば、

```c
Vehicle *p;
```

なら、`p + 1`は`Vehicle`構造体1個分だけ進んだアドレスを表す。

この大きさはコンパイラが型情報から判断する。

## 7-2. p[i]との関係

| 書き方 | 意味 |
|---|---|
| p | 先頭の構造体を指すポインタ |
| p + i | i番目の構造体を指すポインタ |
| p[i] | i番目の構造体そのもの |
| *(p + i) | i番目の構造体そのもの |
| &p[i] | i番目の構造体のアドレス |

重要な関係：

```c
p[i]       // *(p + i) と同じ意味

p + i      // &p[i] と同じアドレス
```

`p[i]`も内部的な意味としては`p + i`を利用している。

したがって、別々の仕組みでアクセスしているわけではない。

## 7-3. ポインタの指す先を変更する場合

```c
p = p + 1;
```

これは、ポインタ`p`に保存されているアドレスを変更する。

一方、

```c
(p + 1)->remaining = 50;
```

これは、2番目の構造体の`remaining`を変更する。

ポインタ変数`p`自身の値は変更しない。

## 7-4. ポインタの変更と構造体のコピー

```c
Vehicle vehicle1 = {1, 80, 1.5f};
Vehicle vehicle2 = {2, 40, 1.0f};

Vehicle *p = &vehicle1;
```

```c
p = &vehicle2;
```

これは、ポインタが指す先を`vehicle2`に変更する。

一方、

```c
*p = vehicle2;
```

これは、現在`p`が指している構造体全体に、`vehicle2`の値をコピーする。

違い：

- `p = &vehicle2;`：保存するアドレスを変更
- `*p = vehicle2;`：指している構造体の内容をコピーして上書き

# 8. 構造体の中に配列がある場合

今回、構造体配列との違いを重点的に確認した。

## 8-1. 前提コード

```c
struct Device {
    int number;
    int values[3];
};

struct Device device = {1, {10, 20, 30}};
struct Device *p = &device;
```

構造体は1個。

その中に、

- number：int型メンバー
- values：int型配列メンバー

が存在する。

## 8-2. 通常のメンバー

| 構造体から | ポインタから | 意味 |
|---|---|---|
| device.number | p->number | numberメンバー |
| &device.number | &p->number | numberメンバーのアドレス |

例えば、

```c
device.number
p->number
```

どちらも値は1。

```c
&device.number
&p->number
```

どちらも同じ`int`型メンバーのアドレス。

## 8-3. 配列メンバー

| 構造体から | ポインタから | 意味 |
|---|---|---|
| device.values | p->values | 通常は先頭要素のアドレスに変換 |
| device.values[0] | p->values[0] | 1番目の値 |
| device.values[1] | p->values[1] | 2番目の値 |
| &device.values[0] | &p->values[0] | 先頭要素のアドレス |
| &device.values[1] | &p->values[1] | 2番目の要素のアドレス |
| &device.values | &p->values | 配列全体のアドレス |

重要：

```c
device.values
p->values
```

この2つは配列メンバーを表し、通常の式では先頭要素のアドレスに変換される。

構造体そのものからアクセスしたか、ポインタからアクセスしたかは関係ない。

## 8-4. メンバーの型によって結果が異なる

通常のint型メンバー：

```c
device.number
```

これはint型のメンバーそのもの。

配列メンバー：

```c
device.values
```

これは配列型のメンバーであり、通常は先頭要素のアドレスに自動変換される。

つまり、

**構造体のメンバーを選んだ後は、そのメンバーの型に応じたC言語のルールが適用される。**

# 9. 構造体内の配列と構造体配列の違い

## 9-1. 構造体内に配列がある場合

```c
struct Device {
    int values[3];
};

struct Device device;
struct Device *p = &device;
```

```c
p->values[1]
```

意味：

1. `p`が指す構造体を対象にする。
2. `->values`で構造体内の配列メンバーを選ぶ。
3. `[1]`でその配列の2番目の要素を選ぶ。

## 9-2. 構造体そのものが配列の場合

```c
struct Vehicle {
    int remaining;
};

struct Vehicle vehicles[3];
struct Vehicle *p = vehicles;
```

```c
p[1].remaining
```

意味：

1. `p[1]`で2番目の構造体そのものを選ぶ。
2. `.remaining`でその構造体のメンバーを選ぶ。

## 9-3. 比較

| 記法 | 配列になっているもの |
|---|---|
| p->values[1] | 構造体の中のint型メンバー |
| p[1].remaining | 構造体そのもの |

この違いが重要。

`[i]`がどの対象に付いているかを判断する。

# 10. メンバーの値とメモリアドレス

## 10-1. 値を表す場合

```c
vehicle.remaining
p->remaining
```

これらは、構造体内の`remaining`メンバーそのものを表す。

値を読み取ることも変更することもできる。

```c
p->remaining = 50;
```

## 10-2. アドレスを取得する場合

```c
&vehicle.remaining
&p->remaining
```

これらは、`remaining`メンバーのメモリアドレスを表す。

重要：

`->`を使うだけでは、メンバーのアドレスを取得することにはならない。

`->`は、ポインタが指している構造体のメンバーを選ぶ演算子。

メンバーのアドレスを取得したい場合は`&`を使用する。

## 10-3. メンバーを指すポインタ

```c
Vehicle vehicle = {1, 80, 1.5f};
Vehicle *p = &vehicle;
```

```c
int *q = &p->remaining;
```

これは、`remaining`メンバーのアドレスを`q`に保存する。

値を変更する場合：

```c
*q = 25;
```

`q`は`int *`型なので、`->remaining`ではアクセスできない。

```c
*q = 25;
```

が正しい。

なぜなら、`q`が指しているのは構造体全体ではなく、int型メンバーそのものだから。

# 11. & と演算子の優先順位

今回、新たに確認した重要事項。

## 11-1. 構造体のアドレスからメンバーにアクセス

```c
Vehicle vehicles[3];
```

2番目の構造体のアドレスは、

```c
&vehicles[1]
```

このアドレスからメンバーにアクセスする場合、

```c
(&vehicles[1])->remaining
```

と書く。

## 11-2. なぜ括弧が必要なのか

誤った書き方：

```c
&vehicles[1]->remaining
```

`->`は単項`&`より優先順位が高い。

そのため、この式は、

```c
&(vehicles[1]->remaining)
```

という形で解釈される。

しかし、`vehicles[1]`は構造体そのものなので、`->`は使えない。

正しくは、

```c
(&vehicles[1])->remaining
```

と括弧でまとめる。

## 11-3. メンバー自体のアドレスを取得する場合

```c
&vehicles[1].remaining
```

これは正しい。

理由：

1. `vehicles[1]`で構造体を選ぶ。
2. `.remaining`でメンバーを選ぶ。
3. `&`でそのメンバーのアドレスを取得する。

比較：

```c
vehicles[1].remaining
```

メンバーそのもの。

```c
&vehicles[1].remaining
```

メンバーのアドレス。

```c
(&vehicles[1])->remaining
```

構造体のアドレスを通してメンバーにアクセス。

この3つは目的が異なる。

# 12. 構造体を関数に渡す方法

## 12-1. 構造体の値渡し

```c
void checkVehicle(Vehicle v)
{
    v.speed = 0.0f;
}
```

呼び出し：

```c
checkVehicle(vehicle);
```

構造体の値をコピーして関数に渡す。

関数内の`v`はコピーされた構造体。

そのため、`v.speed`を変更しても呼び出し元の`vehicle.speed`は変更されない。

## 12-2. 構造体のアドレス渡し

```c
void checkVehicle(Vehicle *p)
{
    p->speed = 0.0f;
}
```

呼び出し：

```c
checkVehicle(&vehicle);
```

構造体のアドレスを渡す。

関数内の`p`には、呼び出し元の構造体のアドレスが保存される。

そのアドレスを使って元の構造体を直接変更できる。

注意：

厳密には、C言語ではポインタ自体も値渡しされている。

コピーされるのはアドレスの値であり、構造体全体ではない。

## 12-3. returnが不要な理由

```c
void checkVehicle(Vehicle *p)
{
    p->speed = 0.0f;
}
```

`p`を通して元の構造体を変更しているため、変更後の速度を`return`で返す必要はない。

`void`関数は戻り値を持たない。

処理が終了すると呼び出し元の関数に制御が戻る。

# 13. 構造体配列を関数に渡す方法

## 13-1. 配列の先頭アドレスを渡す

```c
Vehicle vehicles[5];

updateVehicles(vehicles, 5);
```

このとき、

```c
vehicles
```

は先頭要素のアドレスに変換される。

したがって、

```c
updateVehicles(&vehicles[0], 5);
```

と同じ先頭アドレスを渡せる。

## 13-2. 関数側で受け取る

```c
void updateVehicles(Vehicle *p, int count)
```

- `p`：先頭要素を指すポインタ
- `count`：配列の要素数

ポインタだけでは、配列に何個の要素があるか判断できない。

そのため、要素数も渡す。

## 13-3. 関数の仮引数における2つの記法

```c
void updateVehicles(Vehicle *p, int count);
```

```c
void updateVehicles(Vehicle p[], int count);
```

この2つは、関数の仮引数としては同じ意味になる。

どちらも構造体の先頭要素を指すポインタとして扱われる。

ただし、通常の変数宣言において、

```c
Vehicle vehicles[5];
```

と、

```c
Vehicle *p;
```

は異なる。

前者は構造体5個分の配列。

後者はポインタ変数。

## 13-4. 関数内で複数の構造体を処理

```c
void updateVehicles(Vehicle *p, int count)
{
    for (int i = 0; i < count; i++) {
        if (p[i].remaining <= 20) {
            p[i].speed = 0.0f;
        }
    }
}
```

`p[i]`で配列の各構造体にアクセスできる。

`p[i]`は構造体そのものなので`.`を使う。

同じ処理は次の記法でも書ける。

```c
(p + i)->remaining
(p + i)->speed
```

実際の配列処理では、`p[i].remaining`のほうが簡潔で読みやすい。

# 14. 関数内とmain関数内で変数名が異なる理由

## 14-1. main関数側

```c
Vehicle vehicles[5];
```

構造体配列の名前は`vehicles`。

したがって、

```c
vehicles[i].remaining
```

とアクセスできる。

## 14-2. 関数側

```c
void updateVehicles(Vehicle *p, int count)
```

引数の名前は`p`。

そのため、関数内では、

```c
p[i].remaining
```

と書く。

ここで重要なのは、**配列の名前が自動的にpへ変更されるわけではない**ということ。

関数に渡された先頭アドレスを、関数側で`p`という名前の変数として受け取っている。

したがって、今回のプログラムでは、

```c
vehicles[i].remaining
p[i].remaining
```

は、対応する同じ配列要素のメンバーにアクセスしている。

ただし、異なる関数内では使用できるローカル変数名が異なる。

# 15. 1台ずつ渡す方法と配列全体を渡す方法

## 15-1. main関数で繰り返す方法

```c
for (int i = 0; i < 5; i++) {
    checkVehicle(&vehicles[i]);
}
```

この場合、

- main関数が繰り返しを担当
- checkVehicle関数が1台分の処理を担当

する。

## 15-2. 配列全体を関数に渡す方法

```c
updateVehicles(vehicles, 5);
```

関数側：

```c
void updateVehicles(Vehicle *p, int count)
{
    for (int i = 0; i < count; i++) {
        // 各車体の処理
    }
}
```

この場合、

- main関数は配列と要素数を渡す
- updateVehicles関数が繰り返しを担当

する。

## 15-3. 今回の総合最終問題で使用した方法

2つの関数を連携させた。

```c
void updateVehicles(Vehicle *p, int count)
{
    for (int i = 0; i < count; i++) {
        checkVehicle(&p[i]);
    }
}
```

処理の流れ：

1. main関数からupdateVehicles関数に配列と要素数を渡す。
2. updateVehicles関数がfor文で各車体を選ぶ。
3. `&p[i]`で各車体のアドレスを取得する。
4. checkVehicle関数へ1台ずつ渡す。
5. checkVehicle関数が各車体の速度を変更する。
6. 処理終了後、main関数で結果を表示する。

## 15-4. checkVehicle関数で使う記法

```c
void checkVehicle(Vehicle *p)
{
    if (p->remaining <= 20) {
        p->speed = 0.0f;
    }
}
```

この関数では、渡された1台の車体を扱う。

したがって、

```c
p->remaining
p->speed
```

と書ける。

同じ意味で、

```c
(*p).remaining
(*p).speed
```

と書いてもよい。

一方、`updateVehicles`関数内で宣言したループ変数`i`は、別の関数である`checkVehicle`内では使用できない。

# 16. 実務を意識した記法の使い分け

今回、実務で一般的に使われる記法についても整理した。

| 状況 | 代表的な書き方 |
|---|---|
| 構造体1個 | vehicle.remaining |
| 構造体ポインタ | p->remaining |
| 構造体配列 | vehicles[i].remaining |
| 構造体配列をポインタで受け取る | p[i].remaining |
| 構造体内の配列 | device.values[i] |
| 構造体ポインタから内部の配列 | p->values[i] |

通常の構造体配列処理では、

```c
p[i].remaining
```

のほうが、

```c
(p + i)->remaining
```

より簡潔で読みやすい。

ただし、両方とも正しいC言語の記法。

自分でコードを書く際は読みやすい記法を選び、既存コードを読む際には別の表記も理解できることが重要。

# 17. Day29で間違えやすかった点と修正した理解

## 17-1. ポインタだから必ず->を使うわけではない

誤った理解：

「pがポインタなら、pを使う処理はすべて->になる」

正しい理解：

`.`と`->`の直前にある式の型によって決まる。

```c
p[i].remaining       // p[i]は構造体型
(p + i)->remaining   // p + iは構造体ポインタ型
```

## 17-2. ->はアドレス取得ではない

誤った理解：

「->はメモリアドレスを取得する記号」

正しい理解：

`->`は、構造体ポインタから構造体のメンバーにアクセスする記号。

```c
p->remaining
```

はメンバーそのもの。

```c
&p->remaining
```

はメンバーのアドレス。

## 17-3. 配列名と通常のメンバーは違う

配列：

```c
device.values
```

通常の式では先頭要素のアドレスに変換される。

通常のint型メンバー：

```c
device.number
```

これは配列ではないので、アドレスへの自動変換は起こらない。

メンバーのアドレスが必要なら、

```c
&device.number
```

と書く。

## 17-4. &pと&p[i]は異なる

```c
&p
```

はポインタ変数p自身のアドレス。

```c
&p[i]
```

はi番目の構造体のアドレス。

両者は異なる。

## 17-5. p[i]とp + iは異なる

```c
p[i]
```

構造体そのもの。

```c
p + i
```

構造体を指すポインタ型の値。

この区別によって`.`と`->`を使い分ける。

## 17-6. pに保存するアドレスとメンバーの値を区別する

```c
p = &vehicles[1];
```

ポインタpの指す先を変更する。

```c
p->remaining = 50;
```

ポインタが指す構造体のメンバーを変更する。

この2つは目的が異なる。

## 17-7. 別の関数のローカル変数は直接使えない

updateVehicles関数のfor文にある`i`は、そのfor文のスコープ内の変数。

別の関数checkVehicleでは、その`i`を直接使用できない。

1台の構造体ポインタを受け取った場合は、

```c
p->remaining
```

などでアクセスする。

# 20. 最終まとめ：構造体の表記を判断する手順

構造体のメンバーにアクセスするときは、次の順番で判断する。

## STEP 1：対象が構造体そのものか、構造体ポインタか

構造体そのもの：

```c
vehicle
vehicles[i]
p[i]
*p
```

構造体ポインタ：

```c
p
p + i
&vehicles[i]
&p[i]
```

## STEP 2：. と -> を選ぶ

構造体型：

```c
vehicle.remaining
vehicles[i].remaining
p[i].remaining
(*p).remaining
```

構造体ポインタ型：

```c
p->remaining
(p + i)->remaining
(&vehicles[i])->remaining
(&p[i])->remaining
```

## STEP 3：メンバーの型を確認する

通常のint型：

```c
vehicle.remaining
```

メンバーそのもの。

配列型：

```c
device.values
```

通常は先頭要素のアドレスに自動変換される。

## STEP 4：値かアドレスかを判断する

値やメンバーそのもの：

```c
vehicle.remaining
p->remaining
```

メンバーのアドレス：

```c
&vehicle.remaining
&p->remaining
```

配列のn番目の要素：

```c
device.values[n]
p->values[n]
```

配列のn番目の要素のアドレス：

```c
&device.values[n]
&p->values[n]
```
