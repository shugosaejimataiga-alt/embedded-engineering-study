# 1. bit数と整数の関係

コンピュータでは、データは基本的に0と1の組み合わせで表現される。

8bitの場合は、

    00000000
    ～
    11111111

となる。

8bitで作れる組み合わせの総数は、

    2^8 = 256通り

となる。

2進数では、右から順に、

    2^0 = 1
    2^1 = 2
    2^2 = 4
    2^3 = 8
    2^4 = 16
    2^5 = 32
    2^6 = 64
    2^7 = 128

という値を持つ。

例えば、

    11111111

の場合、

    128 + 64 + 32 + 16 + 8 + 4 + 2 + 1
    = 255

となる。

そのため、8bitを0以上の整数として扱えば、

    0 ～ 255

を表現できる。

重要なのは、

「メモリ全体がGB単位で大量に存在していても、1つの変数に割り当てられたbit数によって、その変数が表現できる値の範囲が決まる」

ということ。

---

# 2. メモリ全体と変数の関係

PCなどで見る、

    メモリ 8GB
    メモリ 16GB

などは、通常RAM全体の容量を表している。

その大きなメモリ領域の一部を、各変数が使用する。

例えば、ある環境で`int`が4Byteなら、

    4Byte = 32bit

分の領域を使用する。

つまり、

    メモリ全体
        ↓
    変数ごとに一部を使用
        ↓
    変数に割り当てられたbit数が決まる
        ↓
    0と1の組み合わせ数が決まる
        ↓
    表現できる値の範囲が決まる

という関係になる。

---

# 3. signed

`signed`は符号あり整数を表す。

例：

    signed int temperature = -20;

`signed`では、

- 負の数
- 0
- 正の数

を扱うことができる。

通常の、

    int value;

も、基本的には符号付き整数として扱われる。

---

# 4. unsigned

`unsigned`は符号なし整数を表す。

例：

    unsigned int count = 20;

`unsigned`では、

- 0
- 正の数

を扱う。

負の数を表さない代わりに、同じbit数であればsignedより大きな正の整数まで表現できる。

例えば8bitなら、

    signed   : -128 ～ 127
    unsigned :    0 ～ 255

となる。

どちらも8bitなので、

    2^8 = 256通り

という組み合わせ総数自体は同じ。

違うのは、その256通りをどの整数の範囲として扱うかである。

---

# 5. signed / unsigned の考え方

今回理解した重要な考え方は、

「変数に割り当てられたbit数によって、0と1で作れる組み合わせ数が決まる。その組み合わせをsignedでは負の数・0・正の数として扱い、unsignedでは0以上の数として扱う」

ということ。

8bitなら256通り存在し、それを、

    signed
    → -128 ～ 127

    unsigned
    → 0 ～ 255

として扱う。

---

# 6. unsigned整数の表現範囲

n bitのunsigned整数の範囲は、

    0 ～ 2^n - 1

となる。

8bitなら、

    0 ～ 2^8 - 1
    = 0 ～ 255

16bitなら、

    0 ～ 2^16 - 1
    = 0 ～ 65535

となる。

---

# 7. signed整数の表現範囲

n bitのsigned整数の範囲は、

    -2^(n-1) ～ 2^(n-1) - 1

となる。

8bitなら、

    -2^7 ～ 2^7 - 1
    = -128 ～ 127

となる。

---

# 8. 覚える範囲の式

signed：

    -2^(n-1) ～ 2^(n-1) - 1

unsigned：

    0 ～ 2^n - 1

bit数が分かれば、この式から整数の表現範囲を求めることができる。

---

# 9. 基本整数型

C言語には、

- char
- short
- int
- long

などの基本整数型がある。

それぞれに`signed`または`unsigned`を付けることができる。

例：

    signed char a;
    unsigned char b;

    signed short c;
    unsigned short d;

    signed int e;
    unsigned int f;

    signed long g;
    unsigned long h;

`signed / unsigned`は、そのbit数で作れる組み合わせを、どの整数範囲として扱うかに関係する。

---

# 10. charも整数型

`char`は文字を扱うためによく使用されるが、C言語では整数型の一種でもある。

例：

    char letter = 'A';

文字も内部では文字コードに対応する数値として扱われる。

ASCIIでは例えば、

    'A' = 65
    'B' = 66
    'C' = 67

となる。

そのため、

    signed char
    unsigned char

という書き方も存在する。

ただし、文字そのものを扱う場合は通常、

    char letter = 'A';

のように`char`を使用する。

---

# 11. 基本のデータ型と環境依存

`char`、`short`、`int`、`long`などの基本のデータ型は、環境や処理系によって使用するbit数が異なる場合がある。

例えば、ある環境では、

    char  = 8bit
    short = 16bit
    int   = 32bit
    long  = 64bit

という場合がある。

ただし、すべての環境で必ず同じとは限らない。

型が何Byte使用しているかは`sizeof`で確認できる。

例：

    sizeof(int)

`sizeof`が返す値はByte単位。

---

# 12. stdint.h

固定幅整数型を使用する場合は、

    #include <stdint.h>

を書く。

`stdint.h`は、

- uint8_t
- uint16_t
- uint32_t
- int8_t
- int16_t
- int32_t

などの固定幅整数型を使えるようにするヘッダーファイル。

---

# 13. uint8_tの意味

`uint8_t`を分解すると、

    u
    → unsigned

    int
    → integer（整数）

    8
    → 8bit

    _t
    → type（型）

という意味になる。

つまり、

    uint8_t

は、

「8bitの符号なし整数型」

を表す。

---

# 14. 主なunsigned固定幅整数型

`uint8_t`

    unsigned
    8bit
    0 ～ 255

`uint16_t`

    unsigned
    16bit
    0 ～ 65535

`uint32_t`

    unsigned
    32bit
    0 ～ 4294967295

---

# 15. signed側の固定幅整数型

固定幅整数型にはsigned側も存在する。

- int8_t
- int16_t
- int32_t

例えば、

    int8_t

は、

    signed
    8bit
    -128 ～ 127

を扱う。

`uint8_t`の`u`はunsignedを意味する。

`int8_t`には`u`がないためsigned側の固定幅整数型になる。

---

# 16. 基本整数型と固定幅整数型

基本整数型：

- char
- short
- int
- long

など。

これらは環境によってbit数が異なる場合がある。

固定幅整数型：

- uint8_t
- uint16_t
- uint32_t
- int8_t
- int16_t
- int32_t

など。

こちらは名前によってbit幅が明確になっている。

例えば、

    uint8_t value;

なら、8bitの符号なし整数型として使用する。

---

# 17. uint8_tが8bitと言える理由

基本整数型は環境によってbit数が異なる場合がある。

一方、その環境にちょうど8bitの符号なし整数型が存在すれば、処理系側が`stdint.h`でそれを`uint8_t`として使用できるように定義している。

例えば、その環境で`unsigned char`が8bitなら、概念的には、

    typedef unsigned char uint8_t;

のように定義される場合がある。

そのため、

    uint8_t value;

と書けば、8bitの符号なし整数型として使用できる。

自分で`sizeof`を使って型の大きさを調べてから`uint8_t`を作るわけではない。

処理系側が、その環境に存在する整数型の大きさに合わせて固定幅整数型を用意している。

---

# 18. sizeofとstdint.hの違い

`sizeof`

    この環境で、その型が何Byte使用するのかを確認する。

`stdint.h`

    uint8_tなどの固定幅整数型を使用できるようにする。

つまり、

    sizeof
    → 型の大きさを確認する

    stdint.h
    → 固定幅整数型を使えるようにする

という違いがある。

---

# 19. 固定幅整数型の宣言

固定幅整数型を使う場合も、変数宣言の基本形は同じ。

    固定幅整数型 変数名;

例：

    #include <stdint.h>

    uint8_t brightness;
    uint16_t count;
    int8_t temperature;

初期値を同時に設定する場合は、

    uint8_t brightness = 200;

と書く。

これは、

    uint8_t
    → 8bitの符号なし整数型

    brightness
    → 変数名

    200
    → 初期値

という意味。

---

# 20. 必要な値の範囲から型を選ぶ

実際に型を選択するときは、現在入れる初期値だけではなく、

「その変数が仕様上どの範囲の値を取り得るのか」

を確認することが重要。

例えば、

    temperature：-40 ～ 100
    brightness ：0 ～ 200
    count      ：0 ～ 50000

という仕様がある場合。

---

## temperature

範囲：

    -40 ～ 100

負の数が存在するためsignedが必要。

8bit signedの範囲は、

    -128 ～ 127

なので、すべて収まる。

したがって、

    int8_t temperature;

を使用できる。

---

## brightness

範囲：

    0 ～ 200

負の数は不要。

8bit unsignedの範囲は、

    0 ～ 255

なので、すべて収まる。

したがって、

    uint8_t brightness;

を使用できる。

---

## count

範囲：

    0 ～ 50000

負の数は不要。

8bit unsignedでは、

    0 ～ 255

なので足りない。

16bit unsignedなら、

    0 ～ 65535

なので、すべて収まる。

したがって、

    uint16_t count;

を使用できる。

---

# 21. 型を選択するときの考え方

今回理解した型選択の流れ。

    変数が何を表すのか確認する
        ↓
    変数が取り得る値の範囲を確認する
        ↓
    負の数が必要か確認する
        ↓
    必要なbit数を考える
        ↓
    その範囲を収められる型を選ぶ

例えば、

    -40 ～ 100
        ↓
    負の数が必要
        ↓
    signed
        ↓
    8bit signedで足りる
        ↓
    int8_t

となる。

---

# 22. 初期値だけでは適切な型を一意に決められない

例えば、

    temperature = -20

という情報しかない場合、

- int8_t
- int16_t
- int32_t

のどれでも`-20`を保存できる。

そのため、適切な型を選択するには、

    temperatureは -40 ～ 100 の範囲

のように、仕様上取り得る値の範囲を確認する必要がある。

つまり、

「現在の初期値ではなく、その変数が取り得る値の範囲を見て型を選択する」

ことが重要。

---
