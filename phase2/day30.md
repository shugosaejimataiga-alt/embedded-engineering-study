# 3. enumの理解

## 3-1. enumとは

enum（列挙型）は、複数の状態や種類を、名前の付いた定数としてまとめて定義する仕組み。

例：

```c
enum MotorState {
    MOTOR_STOP,
    MOTOR_RUNNING,
    MOTOR_ERROR
};
```

それぞれの列挙定数には整数値が割り当てられる。

この例では、値を明示的に指定していないため、以下のようになる。

| 列挙定数 | 値 | 意味 |
|---|---|---|
| MOTOR_STOP | 0 | 停止 |
| MOTOR_RUNNING | 1 | 回転中 |
| MOTOR_ERROR | 2 | 異常 |

## 3-2. enumを使うメリット

例えば、

```c
int state = 1;
```

では、1が何を意味しているのか分かりにくい。

一方、

```c
enum MotorState state = MOTOR_RUNNING;
```

であれば、モーターが回転中であることが分かりやすい。

メリット：
- 数値に意味のある名前を付けられる
- 関連する状態をまとめて定義できる
- 状態の意味を読み取りやすくなる
- 状態管理プログラムの可読性が向上する

ただし、C言語のenumは、定義した列挙定数以外の整数値を完全に禁止するものではない。

## 3-3. enumとswitch文の関係

enumは状態を定義する。

switch文は、現在の値に応じて処理を分岐する。

例：

```c
switch (state) {

    case MOTOR_STOP:
        printf("STOP");
        break;

    case MOTOR_RUNNING:
        printf("RUNNING");
        break;

    case MOTOR_ERROR:
        printf("ERROR");
        break;
}
```

重要なのは、enumとswitch文の役割が異なること。

- enum：状態を定義する
- switch：値に応じて処理を分岐する

enumを使用したからといって、必ずswitch文が必要になるわけではない。

# 4. typedefの理解

## 4-1. typedefとは

typedefは、既存の型に別名を付けるための機能。

基本構文：

```c
typedef 元の型 新しい型名;
```

例：

```c
typedef unsigned int MeasurementCount;
```

これによって、MeasurementCountを型名として使用できる。

```c
MeasurementCount count = 20;
```

これは、次の宣言と同じ意味になる。

```c
unsigned int count = 20;
```

## 4-2. typedefについて理解したこと

typedefは元の型を消したり、置き換えたりする機能ではない。

既存の型に、もう1つの名前を追加する仕組み。

したがって、

```c
typedef unsigned int MeasurementCount;
```

と定義した後も、

```c
unsigned int count = 20;
```

と書ける。

また、

```c
MeasurementCount count = 20;
```

とも書ける。

どちらも同じ型の変数を宣言している。

重要な区別：

```c
typedef unsigned int MeasurementCount;
```

これは型の別名を定義している。

```c
MeasurementCount count = 20;
```

これは変数を宣言している。

MeasurementCountが型名であり、countが変数名である。

## 4-3. typedefを使う目的

主な目的は、型の役割や意味を分かりやすくすること。

ただし、単純な整数型に別名を付ければ必ず読みやすくなるわけではない。

構造体や列挙型の型名を整理するときにも使われる。

# 5. signed・unsignedとメモリの復習

学習中に、unsignedとメモリの関係について復習した。

## 基本的な考え方

整数型が表現できる値の範囲は、ビット数や符号の有無によって決まる。

例えば、8ビットの場合：

- 8ビットで表現できるビットの組み合わせは256通り
- 8ビットの符号なし整数は0〜255
- 8ビットの符号付き整数は通常-128〜127

unsignedはメモリのバイト数を直接指定するものではなく、負の値を扱わない整数型にするための指定。

メモリの大きさは、型や処理系によって決まる。

## 学習したポイント

- ビット数によって表現できる値の組み合わせ数が決まる
- unsignedは負の整数を扱わない
- signedは負の整数も扱える
- 同じビット数でもsignedとunsignedでは表現範囲が異なる
- typedefで別名を付けても元の型のメモリサイズや表現範囲は変わらない

# 6. typedef enumの理解

## 6-1. enumだけの場合

```c
enum MotorMode {
    MODE_STOP,
    MODE_RUNNING,
    MODE_ERROR
};
```

変数宣言：

```c
enum MotorMode mode = MODE_RUNNING;
```

## 6-2. typedef enumの場合

```c
typedef enum {
    MODE_STOP,
    MODE_RUNNING,
    MODE_ERROR
} MotorMode;
```

変数宣言：

```c
MotorMode mode = MODE_RUNNING;
```

## 違い

typedefを組み合わせることで、enumを毎回書かずに、MotorModeという型名を使用できる。

役割：
- enum：列挙型を定義する
- typedef：その型に別名を付ける
- MotorMode：使用する型名
- mode：変数名

## 実務との関係

組み込みソフトウェアでは、モーターの動作状態や機器の制御モードなどを管理するためにenumが使われる。

例えば、

```c
typedef enum {
    DRIVE_STOP,
    DRIVE_MANUAL,
    DRIVE_AUTO,
    DRIVE_ERROR
} DriveMode;
```

このように状態をまとめることで、どのような動作モードが存在するのか把握しやすくなる。

# 7. if文とswitch文の使い分け

今回、特に理解を深めた内容。

## 7-1. if文

if文は条件式が成立するかどうかを判定する。

適している処理：
- 数値の大小比較
- 範囲判定
- 複数の条件の組み合わせ
- 条件の優先順位に応じた処理

例：

```c
if (distance < 0) {
    mode = DRIVE_ERROR;
} else if (distance <= 20) {
    mode = DRIVE_STOP;
} else {
    mode = DRIVE_FORWARD;
}
```

if・else ifは上から順番に条件を判定する。

そのため、条件の順番に意味がある。

## 7-2. switch文

switch文は、1つの式の値に応じて処理を分岐する。

例：

```c
switch (mode) {

    case DRIVE_FORWARD:
        printf("FORWARD");
        break;

    case DRIVE_STOP:
        printf("STOP");
        break;

    case DRIVE_ERROR:
        printf("ERROR");
        break;
}
```

適している処理：
- モードごとの分岐
- enumの列挙定数による分岐
- 特定の整数値による分岐

switch文では、caseの記述順が優先順位を表すわけではない。

また、caseに範囲判定を直接書くことはできない。

## 7-3. 今回理解した使い分け

if文：
条件から動作モードを決める。

switch文：
決まったモードに応じて処理を分岐する。

例えば、車体制御では、

1. センサーデータを取得する
2. if文で状態を判定する
3. enumで定義したモードの値を決める
4. switch文でモードごとの処理を振り分ける
5. 必要な関数を実行する

という構成が考えられる。

ただし、すべてのプログラムが必ずこの構成になるわけではない。

# 8. 条件分岐の可読性について

今回、数値範囲の判定をどのように書けば読みやすいかも学習した。

例えば、モーターの回転速度について、

- 0：停止
- 1〜100：通常
- 101以上：高速

としたい場合。

## 範囲を明示する書き方

```c
if (speed == 0) {
    printf("STOP");
} else if (speed >= 1 && speed <= 100) {
    printf("NORMAL");
} else {
    printf("HIGH");
}
```

## 条件を簡潔にする書き方

speedがunsigned int型の場合：

```c
if (speed == 0) {
    printf("STOP");
} else if (speed <= 100) {
    printf("NORMAL");
} else {
    printf("HIGH");
}
```

最初のif文で0を除外しているため、else ifでは1以上であることが確定している。

学んだこと：

- 条件式は、単純に短ければよいわけではない
- 条件を明示したほうが理解しやすい場合もある
- 直前の条件を利用すれば簡潔に書ける
- 可読性とは、処理の意図を読み取りやすくすること

# 10. 総合最終問題：車体の走行状態管理プログラム

## 作成したプログラム

車体のセンサー情報とバッテリー残量から走行モードを決定し、結果を表示するシミュレーターを作成した。

使用した内容：
- typedef struct
- typedef enum
- 関数
- 引数
- 戻り値
- if・else if・else
- switch
- 論理演算子
- 構造体のメンバーアクセス
- ローカル変数
- printf

## 完成したコード

ファイル名：main.c

```c
#include <stdio.h>

typedef struct {
    int distance_cm;
    int battery_percent;
    int sensor_error;
} VehicleData;

typedef enum {
    DRIVE_FORWARD,
    DRIVE_SLOW,
    DRIVE_STOP,
    DRIVE_ERROR
} DriveMode;


// 関数プロトタイプ宣言
DriveMode decide_mode(VehicleData data);
void display_mode(DriveMode mode);


int main(void)
{
    // 車体のセンサーデータ
    VehicleData data = {35, 60, 0};

    // センサーデータから走行モードを決定
    DriveMode mode = decide_mode(data);

    // 決定した走行モードを表示
    display_mode(mode);

    return 0;
}


// 走行モードを決定する関数
DriveMode decide_mode(VehicleData data)
{
    DriveMode mode;

    if (data.sensor_error == 1) {
        mode = DRIVE_ERROR;

    } else if (data.distance_cm < 0 ||
               (data.battery_percent < 0 ||
                data.battery_percent > 100)) {
        mode = DRIVE_ERROR;

    } else if (data.battery_percent <= 15) {
        mode = DRIVE_STOP;

    } else if (data.distance_cm <= 20) {
        mode = DRIVE_STOP;

    } else if (data.distance_cm >= 21 &&
               data.distance_cm <= 50) {
        mode = DRIVE_SLOW;

    } else {
        mode = DRIVE_FORWARD;
    }

    return mode;
}


// 走行モードを表示する関数
void display_mode(DriveMode mode)
{
    switch (mode) {

        case DRIVE_FORWARD:
            printf("FORWARD");
            break;

        case DRIVE_SLOW:
            printf("SLOW");
            break;

        case DRIVE_STOP:
            printf("STOP");
            break;

        case DRIVE_ERROR:
            printf("ERROR");
            break;
    }
}
```

※学習時に完成・動作確認したコードを基に、コメントと整形を加えた記録用コード。初期値は基本テストの{35, 60, 0}に戻している。

# 11. 総合問題で発生した間違いと修正内容

今回の重要な学習事項として、実際に発生した間違いを記録する。

## 11-1. modeが宣言されていなかった

修正前：

```c
mode = decide_mode(data);
```

修正後：

```c
DriveMode mode = decide_mode(data);
```

原因：

decide_mode関数の中でDriveMode型のmodeを宣言していたため、main関数でも使えると考えていた。

しかし、関数内で宣言したローカル変数は、その関数のスコープ内でしか使用できない。

decide_mode関数のreturnは値を返すだけで、main関数に変数を自動生成するわけではない。

学んだこと：

- ローカル変数の有効範囲
- 関数の戻り値と変数は別のもの
- 呼び出し元で戻り値を受け取る場合の変数宣言

## 11-2. 戻り値の型をintにしていた

修正前：

```c
int decide_mode(VehicleData data);
```

修正後：

```c
DriveMode decide_mode(VehicleData data);
```

関数定義側も同様に修正。

enumの列挙定数には整数値が対応しているため、intで返すことも可能。

しかし、今回の関数が返すものは走行モードである。

そのため、DriveMode型を使用するほうが関数の役割を明確にできる。

学んだこと：

関数の戻り値には、intやdoubleだけでなく、typedefで定義した型名も使用できる。

## 11-3. 論理演算子を間違えた

修正前：

```c
data.battery_percent < 0 &&
data.battery_percent > 100
```

修正後：

```c
data.battery_percent < 0 ||
data.battery_percent > 100
```

原因：

「0未満または100超」という条件なのに&&を使用していた。

&&では、同じ数値が0未満かつ100超である必要があり、成立しない。

学んだこと：

- &&：両方成立
- ||：どちらかが成立
- 日本語の条件を正確に論理式へ変換する必要がある

## 11-4. 構造体のメンバーアクセスを忘れた

修正前：

```c
distance_cm >= 21
```

修正後：

```c
data.distance_cm >= 21
```

原因：

distance_cmは単独の変数ではなく、VehicleData型のdataに含まれるメンバーである。

学んだこと：

構造体変数のメンバーにアクセスするときは、ドット演算子を使用する。

```c
data.distance_cm
```

## 11-5. 型名のスペルミス

修正前：

```c
VehicleDate data = {35, 60, 0};
```

修正後：

```c
VehicleData data = {35, 60, 0};
```

原因：

DateとDataのスペルを間違えていた。

C言語では型名が一致していないとコンパイルエラーになる。

## 11-6. ソースファイルに不要な文字を書いていた

ファイルの先頭に、

```text
解答：
```

という日本語が残っていた。

これにより、GCCで構文エラーが発生した。

対処：

ソースコードではない文字列を削除した。

学んだこと：

C言語のソースファイルには、C言語として有効な記述を行う必要がある。

日本語を説明として記述する場合は、コメントなど適切な形式で記述する。

## 11-7. enum型をNULLで初期化しようとした

Level 3の演習中に、

```c
VehicleMode mode = NULL;
```

と書いていた。

NULLは主にポインタが何も指していないことを表すために使用する。

enum型の変数を初期化するためのものではない。

修正：

```c
VehicleMode mode;
```

すべての条件分岐で必ず値を代入する場合、最初に初期化しなくてもよい。

ただし、初期化していないローカル変数を、代入する前に読み取ってはいけない。

# 16. 関数・戻り値・printfの復習

今回、void関数とprintfの関係についても確認した。

例えば、

```c
void display(int number)
{
    printf("%d\n", number);
}
```

この関数はvoid型だが、printfで画面に数値を表示できる。

呼び出し元では、

```c
display(35);
```

と書くだけでよい。

理由：

printfによる出力と、returnによる戻り値は別の仕組みだから。

- printf：標準出力に文字や数値を表示する
- return：呼び出し元に値を返す
- void：呼び出し元に値を返さない

つまり、関数が値を返さなくても、その中でprintfによる表示処理を実行できる。

## 今回のプログラムとの関係

```c
DriveMode mode = decide_mode(data);
```

この処理では、decide_mode関数から返された値を受け取る。

```c
display_mode(mode);
```

この処理では、戻り値を受け取らず、関数内で表示処理を実行する。

総合最終問題の完成後、プログラムの役割を自分の言葉で説明するテストを実施した。

## 17-1. typedef structの役割

自分の説明：

「typedef structにすることによって複数のデータを一まとめにしながらも、型のVehicleDataを追加して使うことが出来る。」

## 17-2. enumとtypedefの役割

自分の説明：

「enumにすることによって状態に名前を付けることで定義が出来、それをつかってswitch文で、状態を名前で分かりやすく分けることが出来る。typedefがあると、そのそれらを使う型に名前を付けることが出来る。」

判定：合格

理解したこと：

enumで状態を定義し、typedefで列挙型に別名を付け、switch文で状態ごとの処理を分岐する。

## 17-3. decide_mode関数の役割

自分の説明：

「VehicleDataという型の変数dataを引数として受け取り、様々な条件でふるいをかける関数としてdecide_modeで、それによりmodeを決める。そのmodeもDriveMode型として定義したものを返す。」

VehicleData型のデータを受け取り、センサー情報やバッテリー残量から動作モードを決定し、DriveMode型の値を返す。

## 17-4. display_mode関数の役割

自分の説明：

「DriveMode型の変数modeを引数として受け取り、display_modeという関数名で状態がmode名で分かれ、出力するものを分ける。で、printfで出力するだけだからvoidである。」

## 18-1. 状態管理の基本構造

今回、特に重要だったのは、状態管理を1つの処理にまとめるのではなく、役割に分けるという考え方。

- struct：データをまとめる
- enum：状態を定義する

- if：条件を判定する
- switch：値に応じて処理を分岐する
- 関数：処理を分割する
- return：計算や判定の結果を返す

それぞれの役割を区別して使用することができた。

## 18-2. ローカル変数と戻り値

関数内で宣言した変数は、その関数の外でそのまま使用できない。

関数からreturnで値を返し、呼び出し元でその値を受け取る必要がある。

今回のmodeのエラーを通じて理解した。

## 18-3. 型を用途に合わせて選択する

関数の戻り値はintやdoubleだけではない。

typedefで定義した型も使用できる。

今回の場合、走行モードを返すため、DriveMode型を使用することが適切だった。

## 18-4. 条件の順序は重要

異常状態を優先して判定し、その後でバッテリーや距離を確認する。

複数の条件が同時に成立する可能性がある場合、判定順序によって結果が変わる。

## 18-5. コンパイルエラーを読むこと

GCCが表示するエラーには、行番号や問題の種類が記載される。

今回、エラーを1つずつ読み、原因を考えて修正した。

エラーの原因が1つでも、複数のエラーが連鎖して表示される場合があることも確認した。

## 18-6. 動作確認の重要性

コンパイルに成功しただけでは、プログラムが仕様どおりに動作しているとは限らない。

正常値・異常値・異なる動作モードなどを設定して実際の結果を確認することが必要。
