# 2. 構造体（struct）とは

構造体とは、**複数の関連するデータを1つの型にまとめる仕組み**である。

例えば、荷物運搬車体には以下の情報が必要になる。

- 荷物の重量
- バッテリー残量
- 走行速度
- 運転モード

通常の変数で管理する場合：

    int weight = 12;
    int battery = 80;
    float speed = 2.5f;
    char mode = 'A';

構造体を使う場合：

    struct Vehicle {
        int weight;
        int battery;
        float speed;
        char mode;
    };

これらの情報を、Vehicleという1つの構造体の型にまとめることができる。

### 構造体を使うメリット

- 関連する情報をまとめて管理できる
- 各データの役割を明確にできる
- 複数の車体を同じ構造で管理できる
- 複雑なプログラムでも情報を整理しやすい
- センサーやモーターなどの情報を管理する際に役立つ

# 3. 構造体の定義

基本構文：

    struct 構造体名 {
        データ型 メンバー名;
        データ型 メンバー名;
    };

使用例：

    struct Vehicle {
        int weight;
        float speed;
        char mode;
    };

### 各部分の意味

| 書き方 | 意味 |
|---|---|
| struct | 構造体を表すキーワード |
| Vehicle | 構造体の名前（タグ名） |
| int weight | 重量を保存するメンバー |
| float speed | 速度を保存するメンバー |
| char mode | 運転モードを保存するメンバー |
| }; | 構造体の定義の終了 |

### 注意点

構造体の定義の最後にはセミコロンが必要。

正しい書き方：

    struct Vehicle {
        int weight;
    };

誤った書き方：

    struct Vehicle {
        int weight;
    }

このセミコロンが不足するとコンパイルエラーになる。

また、構造体を定義しただけでは、通常はまだ構造体変数のデータ領域は確保されない。

# 4. 構造体変数の宣言と初期化

構造体の型を定義した後、その型の変数を作成する。

    struct Vehicle vehicle1;

これにより、Vehicle型のvehicle1という構造体変数を宣言できる。

### 宣言と同時に初期化する

    struct Vehicle vehicle1 = {12, 2.5f, 'A'};

対応するメンバー：

| メンバー | 値 |
|---|---|
| weight | 12 |
| speed | 2.5 |
| mode | 'A' |

初期化では、基本的に構造体で宣言したメンバーの順番に値が対応する。

### 注意点

- int型には整数を設定する
- float型の小数には必要に応じてfを付ける
- char型の1文字にはシングルクォーテーションを使う

例：

    12
    2.5f
    'A'

# 5. ドット演算子（.）

構造体のメンバーにアクセスするときは、ドット演算子を使う。

基本構文：

    構造体変数.メンバー名

例：

    vehicle1.weight
    vehicle1.speed
    vehicle1.mode

### 値の読み取り

    printf("%d\n", vehicle1.weight);
    printf("%.1f\n", vehicle1.speed);
    printf("%c\n", vehicle1.mode);

### 値の変更

    vehicle1.weight = 15;
    vehicle1.speed = 3.5f;
    vehicle1.mode = 'S';

通常の変数と同じように、構造体の各メンバーを読み書きできる。

### 重要

構造体のメンバーは、それぞれ独立した値を持っている。

例えば、

    vehicle1.speed = 0.0f;

と変更しても、weightやmodeが自動的に変更されるわけではない。

変更したいメンバーには、それぞれ処理を記述する必要がある。

# 6. 異なるデータ型を含む構造体

構造体には、異なるデータ型をまとめて保存できる。

    struct Vehicle {
        int weight;
        float speed;
        char mode;
    };

### データ型の役割

| データ型 | 用途 |
|---|---|
| int | 重量、温度、バッテリー残量など |
| float | 走行速度、電圧などの小数 |
| double | より高い計算精度が必要な小数 |
| char | 状態やモードを表す1文字 |

### floatとdoubleの違い

一般的な環境では以下の違いがある。

| 項目 | float | double |
|---|---|---|
| サイズ | 4バイト | 8バイト |
| 有効桁数 | 約6〜7桁 | 約15〜16桁 |
| 精度 | 単精度 | 倍精度 |

doubleの方が通常は計算精度が高い。

ただし、組み込み開発では、マイコンの性能・メモリ・必要な精度によって使い分ける。

STM32の中には単精度の浮動小数点演算をハードウェアで処理できる製品がある。

また、電圧をミリボルト単位の整数で管理する方法もある。

重要なのは、**精度が高い型を必ず選ぶのではなく、用途に合った型を選ぶこと**である。

# 7. printfの書式指定子

今回使用した書式指定子：

| 書式指定子 | 意味 |
|---|---|
| %d | 整数を表示 |
| %f | 小数点以下6桁を表示 |
| %.1f | 小数点以下1桁で表示 |
| %.2f | 小数点以下2桁で表示 |
| %c | 1文字を表示 |
| %% | %そのものを表示 |

例：

    float speed = 3.5f;

    printf("%f\n", speed);
    printf("%.1f\n", speed);
    printf("%.2f\n", speed);

出力：

    3.500000
    3.5
    3.50

### %.1fの意味

%.1fの「.1」は、小数点以下を1桁で表示する指定。

保存されている数値そのものを変更するわけではない。

なお、printfではfloat型の引数はdouble型に変換されて渡されるため、floatもdoubleも%fで表示できる。

### 注意点

誤り：

    printf("%f.1\n", speed);

正解：

    printf("%.1f\n", speed);

また、%を表示するときは、

    printf("バッテリー: %d %%\n", battery);

と記述する。

# 8. 複数の構造体変数を管理する

同じ構造体の型から、複数の変数を作成できる。

    struct Vehicle vehicle1 = {10, 2.5f, 'A'};
    struct Vehicle vehicle2 = {15, 1.5f, 'M'};

それぞれの構造体変数は独立している。

例えば、

    vehicle1.speed = 0.0f;

としても、vehicle2.speedには影響しない。

複数台の車体を管理する場合にも使用できる。

※構造体を配列で管理する方法はC-Day29の学習範囲。

# 9. 構造体のコピー

構造体は、同じ構造体型の変数へまとめてコピーできる。

例：

    struct Vehicle vehicle1 = {12, 3.5f, 'A'};

    struct Vehicle vehicle2 = vehicle1;

これにより、vehicle1の各メンバーの値がvehicle2にコピーされる。

### コピー後の状態

| メンバー | vehicle1 | vehicle2 |
|---|---|---|
| weight | 12 | 12 |
| speed | 3.5 | 3.5 |
| mode | A | A |

その後、

    vehicle2.speed = 0.0f;
    vehicle2.mode = 'S';

と変更しても、vehicle1の値は変わらない。

### 重要な書き方

新しい構造体変数を作成してコピー：

    struct Vehicle vehicle2 = vehicle1;

既存の構造体変数にコピー：

    vehicle2 = vehicle1;

今回のように数値や文字だけを保持する構造体なら、それぞれのデータは独立する。

ただし、構造体内にポインタがある場合、コピーによってポインタが指している先のデータまで複製されるわけではない。

# 10. 構造体と配列・for文の組み合わせ

実際のセンサー制御では、測定値を取得して状態を更新する。

今回は実際のセンサーを使わず、配列に用意した測定値を使用した。

例：

    int temperatures[5] = {28, 35, 41, 39, 33};

配列の値を順番に構造体へ保存する。

    for (int i = 0; i < 5; i++) {
        vehicle1.temperature = temperatures[i];
    }

### 処理の意味

1. 配列から測定値を取得する
2. 構造体のtemperatureへ保存する
3. 次の測定値へ進む
4. 指定した回数だけ繰り返す

### 実務との関係

今回：

    vehicle1.temperature = temperatures[i];

実際の組み込み開発では、温度センサーから取得した測定値を保存する処理などに置き換わる。

測定値を取得した後の状態管理や判定には、今回の学習内容を応用できる。

# 11. 構造体とif文による異常判定

今回の荷物運搬車体では、複数のセンサー情報を使って安全停止を判定した。

例：

    if (vehicle1.temperature >= 40) {
        vehicle1.speed = 0.0f;
        vehicle1.mode = 'S';
    }

これは温度が40℃以上になった場合、車体の速度とモードを停止状態に変更する処理である。

※40℃は学習用の仮の設定値。

### 比較演算子

| 演算子 | 意味 |
|---|---|
| > | より大きい |
| >= | 以上 |
| < | より小さい |
| <= | 以下 |
| == | 等しい |
| != | 等しくない |

特に境界値に注意する。

    temperature > 40

これは40℃ちょうどを含まない。

    temperature >= 40

これは40℃ちょうどを含む。

実務の制御では、この違いによって停止する条件が変わる。

# 12. 複数の異常条件と優先順位

複数の異常を判定する場合、if・else ifを使える。

例：

    if (vehicle1.temperature >= 40) {
        vehicle1.cause = 'T';

    } else if (vehicle1.distance <= 30) {
        vehicle1.cause = 'D';

    } else if (vehicle1.remaing <= 20) {
        vehicle1.cause = 'B';
    }

### 停止原因の意味

| 文字 | 意味 |
|---|---|
| N | 停止原因なし |
| T | 温度異常 |
| D | 障害物異常 |
| B | バッテリー残量不足 |

### if・else ifの特徴

最初に成立した条件の処理だけが実行される。

例えば温度異常と障害物異常が同時に発生した場合、

    if (温度異常)
    else if (障害物異常)

の順番であれば、温度異常を優先できる。

### 注意点

if・else ifによって優先順位を付けることと、過去に記録した停止原因を保持することは別の処理である。

# 13. 比較式の結果を変数に代入する

今回新しく理解した重要な書き方。

    vehicle1.tempFaultNow =
        (vehicle1.temperature >= 40);

これは、温度が40℃以上かどうかを比較し、その結果を変数へ保存している。

### C言語の比較式

比較式は以下の整数値を返す。

- 真：1
- 偽：0

例えば、

    vehicle1.temperature = 43;

の場合、

    vehicle1.tempFaultNow =
        (vehicle1.temperature >= 40);

の結果は、

    tempFaultNow = 1

となる。

温度が35℃なら、

    tempFaultNow = 0

となる。

### if文で書いた場合

    if (vehicle1.temperature >= 40) {
        vehicle1.tempFaultNow = 1;
    } else {
        vehicle1.tempFaultNow = 0;
    }

今回の用途では、このif文と比較式を直接代入する書き方は同じ結果になる。

### 重要

比較式はif文の中でしか使えないものではない。

比較結果を直接変数へ保存することもできる。

# 14. 現在の異常（FaultNow）

現在の異常とは、**今回測定した値が異常かどうか**を示す情報である。

例：

    vehicle1.tempFaultNow =
        (vehicle1.temperature >= 40);

    vehicle1.distanceFaultNow =
        (vehicle1.distance <= 30);

    vehicle1.batteryFaultNow =
        (vehicle1.remaing <= 20);

この3つはそれぞれ独立して判定される。

### 管理する情報

| 変数 | 意味 |
|---|---|
| tempFaultNow | 現在の温度異常 |
| distanceFaultNow | 現在の障害物異常 |
| batteryFaultNow | 現在のバッテリー異常 |

### 例

温度が43℃の場合：

    tempFaultNow = 1

次の測定で35℃になった場合：

    tempFaultNow = 0

このように、現在の異常は測定するたびに更新する。

### 重要

現在の異常は、過去の異常を保存するものではない。

現在の状態だけを表している。

---

# 15. 過去の異常履歴（FaultHistory）

異常履歴とは、**過去に一度でも異常が発生したか**を保存する情報である。

例：

    if (vehicle1.tempFaultNow) {
        vehicle1.tempFaultHistory = 1;
    }

これは現在の温度異常が1であれば、温度異常の履歴を1に変更するという意味。

### FaultNowとの違い

| 温度 | FaultNow | FaultHistory |
|---|---|---|
| 35℃ | 0 | 0 |
| 43℃ | 1 | 1 |
| 45℃ | 1 | 1 |
| 36℃ | 0 | 1 |
| 42℃ | 1 | 1 |

※異常判定は40℃以上とする。

### 重要

FaultNowは現在の測定結果に応じて0と1が切り替わる。

FaultHistoryは一度1になれば、今回のプログラムでは0へ戻さない。

したがって、

    tempFaultNow = 0
    tempFaultHistory = 1

という状態も発生する。

これは「現在は正常だが、過去に温度異常が発生した」という意味になる。

# 16. 最初の停止原因を保持する

今回、特に重要だった学習内容。

車体が一度停止した場合、最初に停止した原因を保存する。

例：

    if (vehicle1.cause == 'N') {

        if (vehicle1.tempFaultNow) {
            vehicle1.cause = 'T';

        } else if (vehicle1.distanceFaultNow) {
            vehicle1.cause = 'D';

        } else if (vehicle1.batteryFaultNow) {
            vehicle1.cause = 'B';
        }
    }

### 外側のif文

    if (vehicle1.cause == 'N')

これは「まだ停止原因が記録されていない場合」という意味。

### 内側のif文

温度・障害物・バッテリーを順番に判定して、最初の停止原因を記録する。

### 実際の処理例

1回目：

    cause = 'N'

異常なし。

2回目：

    cause = 'N'

異常なし。

3回目：

障害物を検出。

    cause = 'D'

4回目：

温度異常を検出。

しかし、

    cause == 'N'

は成立しない。

そのため、causeは'D'のままになる。

### 重要

最初の停止原因は、新しい異常が発生しても書き換えない。

これは「新しい異常が発生していない」という意味ではない。

**最初に何が原因で車体が停止したのかを保存するための仕組み**である。

# 17. 停止状態を維持する

車体を停止した後、異常が解消されても勝手に走行を再開させない。

例：

    if (vehicle1.cause != 'N') {
        vehicle1.speed = 0.0f;
        vehicle1.mode = 'S';
    }

### 条件式の意味

    cause != 'N'

これは「最初の停止原因が記録されている」という意味。

停止原因が記録されていれば、

    speed = 0.0f
    mode = 'S'

にする。

### 注意点

causeとmodeは異なる情報を管理している。

| 変数 | 役割 |
|---|---|
| cause | 最初に停止した原因 |
| mode | 車体の運転状態 |
| speed | 車体の走行速度 |

'N'は「走行中」という意味ではない。

'N'は「停止原因がまだ記録されていない」という意味である。

# 18. if文の配置と処理の分離

今回、最も難しかった部分の一つ。

複数のif文は、それぞれ異なる役割を持っている。

### 正しい処理の考え方

    // ① 現在の異常を更新する

    // ② 異常履歴を更新する

    // ③ 最初の停止原因を記録する

    // ④ 停止状態を維持する

    // ⑤ 測定結果を表示する

### 特に重要な部分

    if (vehicle1.cause == 'N') {
        // 最初の停止原因を記録
    }

    if (vehicle1.cause != 'N') {
        // 停止状態を維持
    }

    // 測定結果を表示する

停止原因を記録する処理と、停止状態を維持する処理は分けて管理できる。

### なぜ分けるのか

停止原因を記録するif文の中に、測定結果の表示まで入れてしまうと、停止後にそのif文が実行されなくなった際、表示処理も実行されなくなる。

そこで、役割ごとに処理を分ける。

### 学んだ考え方

- 何を判定する処理なのか
- どの変数を更新する処理なのか
- どの条件で実行されるのか
- どの処理は毎回実行する必要があるのか

これらを区別することで、複雑なプログラムを整理できる。

# 19. 停止後もセンサー監視を続ける

車体が停止しても、センサーによる測定は続ける。

例えば、

    for (int i = 0; i < 5; i++) {

        // センサーの測定値を更新

        // 現在の異常を判定

        // 異常履歴を更新

        // 最初の停止原因を記録

        // 停止状態を維持

        // 結果を表示
    }

### 重要

車体の停止とfor文の終了は別である。

    vehicle1.mode = 'S';

としても、for文は自動的には終了しない。

また、停止後も監視を継続する場合には、途中でbreakによってループを終了させない。

### なぜ監視を続けるのか

例えば、障害物で停止した後でも、

- モーターが異常な温度になっていないか
- 障害物がまだ存在するか
- バッテリー残量が低下していないか

などを確認する必要があるため。

# 20. 異常履歴と異常発生回数の違い

今回、新しく疑問に感じた内容。

異常が過去に発生したかだけでなく、何回発生したのかを管理した方が便利な場合もある。

### ① 異常履歴の有無

    if (vehicle1.tempFaultNow) {
        vehicle1.tempFaultHistory = 1;
    }

この場合、1は「過去に一度でも異常が発生した」という意味。

異常が何度発生しても1のままである。

### ② 異常を検出した測定回数

    if (vehicle1.tempFaultNow) {
        vehicle1.tempFaultCount += 1;
    }

この場合、異常を検出するたびにカウントが増える。

例えば、

    0 → 1 → 1 → 0 → 1

という異常状態なら、異常を検出した測定回数は3回になる。

### ③ 新しく異常が発生した回数

異常が継続している場合、それを1回の異常発生として数える方法もある。

    int previousFault = 0;
    int tempFaultCount = 0;

    // 以下を測定ごとに実行する

    if (vehicle1.tempFaultNow == 1 &&
        previousFault == 0) {

        tempFaultCount += 1;
    }

    previousFault = vehicle1.tempFaultNow;

この場合、

    0 → 1 → 1 → 0 → 1

は、正常から異常への変化が2回あるため、異常発生回数は2回になる。

### 違いの整理

| 管理方法 | 分かること |
|---|---|
| FaultHistory | 過去に一度でも異常があったか |
| FaultCount（毎回加算） | 異常を検出した測定回数 |
| FaultCount（0→1で加算） | 異常が新しく発生した回数 |

実際のセンサーでは測定値が境界付近で揺れることもあるため、必要に応じて異常判定の安定化も行う。

# 21. 実務に近い安全監視の基本構成

今回学習した処理を整理すると、次のようになる。

    センサーの測定値を取得
             ↓
    構造体に測定値を保存
             ↓
    現在の異常を判定
             ↓
    過去の異常履歴を更新
             ↓
    最初の停止原因を記録
             ↓
    必要に応じて停止状態へ変更
             ↓
    測定結果を表示
             ↓
    次の測定へ進む

### それぞれの変数の役割

| 変数 | 管理する情報 | 更新方法 |
|---|---|---|
| temperature | 現在の温度 | 測定ごとに更新 |
| distance | 現在の距離 | 測定ごとに更新 |
| remaing | 現在の残量 | 測定ごとに更新 |
| tempFaultNow | 現在の温度異常 | 毎回0・1に更新 |
| tempFaultHistory | 過去の温度異常 | 一度1になったら保持 |
| cause | 最初の停止原因 | 最初の異常時だけ記録 |
| mode | 運転状態 | 条件に応じて変更 |
| speed | 走行速度 | 条件に応じて変更 |

※remaingは今回の演習で使用したメンバー名。英語としてはremainingが正しい。

### 今回最も重要だったこと

変数をただ増やすのではなく、

**「何の情報を管理する変数なのか」「いつ値を変更するのか」「いつ値を保持するのか」**

を考えて設計することが重要だと分かった。

- 意図しない再始動の防止
- 異常解除の条件
- 異常発生時刻や測定値の記録
- センサー値の揺れへの対策

今回学習したのは、これらの制御システムを設計するための基礎となる考え方である。

# 24. 今回発見した間違いと注意点

## ① 構造体定義のセミコロン不足

誤り：

    struct Vehicle {
        int weight;
    }

正解：

    struct Vehicle {
        int weight;
    };

## ② printfの書式指定

誤り：

    printf("%f.1\n", speed);

正解：

    printf("%.1f\n", speed);

## ③ %の表示

正解：

    printf("%d %%\n", battery);

## ④ 配列の添字と確認回数

    temperatures[i]

は配列のi番目の値。

    i + 1

は、iが0から始まるfor文での確認回数表示などに使用できる。

## ⑤ 変数名の一致

C言語では大文字と小文字を区別する。

例えば、

    batteryFaultNow

と、

    batteryfaultNow

は異なる名前である。

## ⑥ 現在の異常と履歴の取り違え

    distanceFaultNow

は現在の異常。

    distanceFaultHistory

は過去の異常履歴。

同じ1が入っていても、意味は異なる。

## ⑦ if文の配置

最初の停止原因の記録と、停止状態の維持、測定結果の表示は、それぞれ異なる役割の処理である。

特定のif文の内側に処理を配置すると、その条件が成立しない場合に実行されなくなる。

## ⑧ 構文ミスと論理ミスの違い

構文ミス：

- セミコロン不足
- 変数名のスペルミス
- 不正な書式

論理ミス：

- 停止条件の不一致
- 停止原因の上書き
- 異常履歴の更新漏れ
- 現在の異常と履歴の混同
- 必要な処理が実行されないif文の配置

論理ミスはコンパイルが成功しても残る場合があるため、特に注意する。

# 25. C-Day28で理解が進んだこと

今回の学習では、最初は構造体の書き方を覚えるところから始まった。

その後、構造体の中で管理する情報が増え、現在の状態と過去の情報を区別する必要が出てきた。

特に難しかったのは、複数の変数と条件分岐がどのようにつながって動作するのかという点だった。

### 学習後半

- 現在の異常を判定する
- 過去の異常履歴を保持する
- 最初の停止原因を保持する
- 停止状態を維持する
- 停止後も監視する

### 最も重要だった学び

**変数は、何を保存するのかによって更新条件が異なる。**

例えば、

- 現在の温度は毎回更新する
- 現在の異常は毎回判定する
- 過去の異常履歴は一度発生したら保持する
- 最初の停止原因は最初だけ記録する
- 停止状態は必要な解除条件が成立するまで維持する

これらの違いを理解することが、複雑な制御プログラムを作るうえで重要になる。
