## 2. プリプロセッサとは

### 2-1. プリプロセッサの役割

プリプロセッサとは、C言語のソースコードをコンパイルする前に、特定の指示に従って前処理を行う仕組みである。

代表的な指示には、以下のものがある。

| 指示 | 役割 |
|---|---|
| #include | 指定されたファイルの内容を取り込む |
| #define | マクロを定義し、指定した名前を別の内容に置き換える |
| #ifdef | 指定したマクロが定義されているか判定する |
| #else | 条件が成立しなかった場合の処理対象を指定する |
| #endif | 条件付きコンパイルの範囲を終了する |

重要なのは、プリプロセッサが#includeだけを処理する仕組みではないということである。

#include、#define、#ifdefなどの指示は、いずれもプリプロセッサによって処理される。

### 2-2. ソースコードから実行ファイルができる流れ

C言語のプログラムは、一般的に以下の流れで実行ファイルになる。

① ソースファイル（.c）
    ↓
② プリプロセッサ（前処理）
    ↓
③ コンパイラ（コンパイル）
    ↓
④ アセンブラ（アセンブル）
    ↓
⑤ オブジェクトファイル（.o）
    ↓
⑥ リンカ（リンク）
    ↓
⑦ 実行ファイル

それぞれの役割は以下のとおり。

【プリプロセッサ】

- #includeなどの指示を処理する
- ヘッダーファイルの内容を取り込む
- #defineによるマクロの置き換えを行う
- 条件付きコンパイルによって不要なコードを除外する

【コンパイラ】

- 前処理されたC言語のコードを処理する
- 一般的なGCCの処理ではアセンブリコードを生成する
- 文法や型に関する問題を検出する

【アセンブラ】

- アセンブリコードを機械語に変換する
- オブジェクトファイルを生成する

【リンカ】

- 複数のオブジェクトファイルを結び付ける
- 必要なライブラリを利用できるようにする
- 関数などの参照先を解決する
- 最終的な実行ファイルを生成する

### 2-3. GCCとの関係

例えば、次のコマンドを実行する。

    gcc main.c sensor.c -o main.exe

このコマンドは、main.cとsensor.cを使ってmain.exeという実行ファイルを生成する指示である。

GCCは、指定されたソースファイルについて前処理、コンパイル、アセンブルを行い、その後にリンク処理を実行する。

重要なことは、フォルダ内に存在するすべての.cファイルを自動的にコンパイルするわけではないということである。

今回のコマンドでは、main.cとsensor.cがコンパイル対象となる。

## 3. ソースファイルとヘッダーファイル

プリプロセッサと#includeの仕組みを理解するうえで、ソースファイルとヘッダーファイルの違いも学習した。

### 3-1. ソースコードとは

ソースコードとは、人間がプログラミング言語で書いたプログラムの内容である。

例えば、次のコードが該当する。

```c
#include <stdio.h>

int main(void)
{
    printf("Hello\n");

    return 0;
}
```

このソースコードをmain.cという名前で保存すると、ソースファイルになる。

つまり、

- ソースコード：プログラムの内容
- ソースファイル：ソースコードを保存したファイル

という違いがある。

### 3-2. ソースファイル（.c）

ソースファイルは、関数の実際の処理などを書くファイルである。

例えば、sensor.cに次の関数を書く。

```c
// sensor.c

// 温度を取得する関数
int getTemperature(void)
{
    return 25;
}
```

この場合、getTemperature関数の実際の処理がsensor.cに書かれている。

### 3-3. ヘッダーファイル（.h）

ヘッダーファイルは、関数の宣言や型定義などをまとめるためのファイルである。

例えば、sensor.hに次のように書く。

```c
// sensor.h

// 温度を取得する関数の宣言
int getTemperature(void);
```

このコードは、getTemperatureという関数が存在し、引数を受け取らず、int型の値を返すことを知らせている。

関数の実際の処理は書かれていない。

ヘッダーファイルには、主に以下の内容を記述できる。

- 関数の宣言
- typedefによる型名の定義
- structによる構造体の定義
- enumによる列挙型の定義
- マクロの定義
- その他、複数のソースファイルで共有する宣言

### 3-4. 関数の宣言と定義

【関数の宣言】

```c
int getTemperature(void);
```

どのような関数なのかをコンパイラに知らせる。

【関数の定義】

```c
int getTemperature(void)
{
    return 25;
}
```

関数の実際の処理を記述する。

つまり、

- 宣言：どのような関数なのかを知らせる
- 定義：関数の実際の処理を書く

という違いである。

### 3-5. ファイルを分割する理由

例えば、車体制御プログラムを作る場合、以下のように分割できる。

project/
├── main.c
├── sensor.c
├── sensor.h
├── control.c
└── control.h

それぞれの役割は以下のとおり。

| ファイル | 役割 |
|---|---|
| main.c | プログラム全体の中心となる処理 |
| sensor.c | センサーに関する関数の実際の処理 |
| sensor.h | センサーに関する関数の宣言など |
| control.c | モーターなどの制御処理 |
| control.h | 制御に関する関数の宣言など |

ファイルを分割する理由は、主に以下のとおり。

1. 可読性を高める
2. 修正する場所をわかりやすくする
3. 関数や型定義を複数のソースファイルで共有する
4. 処理ごとの役割を明確にする
5. プログラムの保守や再利用をしやすくする

なお、小さなプログラムでは、すべての処理を1つの.cファイルに記述することもできる。

ヘッダーファイルを自作することは必須ではない。

## 4. #includeの仕組み

### 4-1. #includeとは

#includeは、指定したファイルの内容を取り込むようにプリプロセッサへ指示するものである。

例えば、

```c
#include <stdio.h>
```

これは、stdio.hというヘッダーファイルの内容を取り込む指示である。

stdio.hには、printfなどの標準ライブラリ関数の宣言が含まれている。

その宣言を取り込むことで、コンパイラがprintfの使い方を確認できる。

ただし、stdio.hにprintfの実際の処理がすべて書かれているわけではない。

printfの実際の処理は、通常、標準ライブラリから利用される。

### 4-2. 自作ヘッダーファイルの取り込み

例えば、次のファイルがあるとする。

project/
├── main.c
├── sensor.h
└── sensor.c

sensor.hの中身：

```c
// sensor.h

int getTemperature(void);
```

main.cの中身：

```c
#include "sensor.h"

int main(void)
{
    int temperature = getTemperature();

    return 0;
}
```

ここで、

```c
#include "sensor.h"
```

という指示をプリプロセッサが処理する。

すると、sensor.hの内容がmain.cのコードに取り込まれる。

前処理後のコードは、簡略化すると次のようなイメージになる。

```c
int getTemperature(void);

int main(void)
{
    int temperature = getTemperature();

    return 0;
}
```

重要なのは、元のmain.cが直接書き換えられるわけではないということである。

プリプロセッサがコンパイラへ渡すコードを加工している。

### 4-3. #includeは.h専用ではない

#includeは、指定したファイルの内容を取り込む仕組みである。

そのため、.hだけでなく.cファイルを指定することも技術的には可能である。

例えば、

```c
#include "sensor.c"
```

という記述も可能である。

しかし、通常のC言語開発では、.cファイルを#includeする設計は避ける。

理由は、複数のソースファイルに同じ関数の定義が取り込まれると、関数の重複定義によるリンクエラーなどが発生する可能性があるためである。

一般的には、

- .h：#includeで内容を取り込む
- .c：別々にコンパイルする
- リンカ：コンパイルされた部品を結び付ける

という役割分担にする。

## 5. #includeの<>と""の違い

### 5-1. 2種類の書き方

#includeには、代表的な2種類の書き方がある。

```c
#include <stdio.h>
#include "sensor.h"
```

これらは、ファイルを探す方法が異なる。

| 書き方 | 主な用途 | 検索方法 |
|---|---|---|
| <stdio.h> | 標準ヘッダーなど | GCCに設定された検索先から探す |
| "sensor.h" | 自作ヘッダーなど | 通常、まず#includeが書かれたファイルと同じフォルダから探す |

### 5-2. GCCに設定された検索先とは

GCCなどの開発環境には、標準ヘッダーファイルを探すためのフォルダが設定されている。

例えば、stdio.hは通常、開発環境が用意した標準ヘッダーファイル用のフォルダに存在する。

GCCを含む開発環境を導入すると、通常、それらを探すための設定も利用できるようになる。

実際の保存場所は、OSや開発環境によって異なる。

そのため、利用者が自分の学習プロジェクトにstdio.hを保存する必要は通常ない。

### 5-3. ファイルを探す場所とは

ここでいう「場所」は、パソコン内のフォルダを意味する。

例えば、Windowsに以下のようなフォルダがあるとする。

C:\
└── study
    └── project
        ├── main.c
        ├── sensor.c
        └── sensor.h

main.cに、

```c
#include "sensor.h"
```

と書かれている場合、GCCでは通常、main.cが保存されているprojectフォルダからsensor.hを探す。

つまり、

- 探す場所：C:\study\project
- 探すファイル：sensor.h

という関係である。

### 5-4. 実際の処理順序

main.cに次のように書いたとする。

```c
#include <stdio.h>
#include "sensor.h"
```

この場合、前処理は基本的に次の流れになる。

① GCCがmain.cの処理を開始する。

② プリプロセッサが#include <stdio.h>を発見する。

③ 設定された検索先からstdio.hを探す。

④ stdio.hの内容を取り込む。

⑤ 続いて#include "sensor.h"を発見する。

⑥ 通常、main.cと同じフォルダからsensor.hを探す。

⑦ sensor.hの内容を取り込む。

⑧ 前処理後のコードをコンパイラへ渡す。

重要なのは、<>を先に処理してから""を処理するという決まりではないことである。

基本的には、ソースコードに書かれた順番で処理される。

### 5-5. 同じ名前のヘッダーが複数ある場合

例えば、次のフォルダ構成があるとする。

project/
├── A/
│   ├── main.c
│   └── sensor.h
└── B/
    ├── test.c
    └── sensor.h

A/main.cに、

```c
#include "sensor.h"
```

と書いた場合、通常はAフォルダにあるsensor.hを優先して探す。

B/test.cに同じ記述を書いた場合、通常はBフォルダにあるsensor.hを優先して探す。

つまり、同じファイル名でも、その#includeが書かれているファイルの場所によって、検索する場所が変わる。

なお、ヘッダーファイルの中に別の#includeがある場合は、その指示が書かれているヘッダーファイルの場所が基準となる。

### 5-6. 重要なまとめ

<>と""は、ファイルの種類を識別するための記号ではない。

- <>：設定された検索先から探す
- ""：通常、まず#includeが書かれたファイルと同じフォルダから探す

どちらも、指定されたファイルの内容を取り込む。

## 6. #defineとは

### 6-1. 基本的な役割

#defineは、マクロを定義するためのプリプロセッサへの指示である。

例えば、

```c
#define MAX_SPEED 100
```

これは、MAX_SPEEDという名前を100に置き換えるという意味である。

重要なのは、変数を作成しているわけではないということである。

プリプロセッサが、コンパイル前にコードを置き換える。

### 6-2. 実際の例

```c
#include <stdio.h>

#define MAX_SPEED 100

int main(void)
{
    int speed = MAX_SPEED;

    printf("%d\n", speed);

    return 0;
}
```

前処理によって、

```c
int speed = MAX_SPEED;
```

という部分が、

```c
int speed = 100;
```

に置き換えられる。

そのため、実行結果は以下のようになる。

    100

### 6-3. #defineで重要なこと

- マクロ名を指定した内容に置き換える
- プリプロセッサがコンパイル前に処理する
- マクロ自体は変数ではない
- マクロ名は大文字とアンダースコアで書くことが多い
- #defineの末尾には通常セミコロンを付けない

また、置き換えは一方向である。

```c
#define MAX_SPEED 100
```

これはMAX_SPEEDを100に置き換える指示であり、100をMAX_SPEEDへ置き換える指示ではない。

## 7. オブジェクト形式マクロ

### 7-1. オブジェクト形式マクロとは

オブジェクト形式マクロとは、引数を持たないマクロである。

例えば、

```c
#define MAX_SPEED 100
#define STOP_DISTANCE 20
#define LED_ON 1
#define LED_OFF 0
```

これらはすべてオブジェクト形式マクロである。

### 7-2. 使用例

```c
#include <stdio.h>

#define LED_ON 1
#define LED_OFF 0

int main(void)
{
    int ledState = LED_ON;

    if (ledState == LED_ON) {
        printf("LED ON\n");
    } else if (ledState == LED_OFF) {
        printf("LED OFF\n");
    }

    return 0;
}
```

実行結果：

    LED ON

### 7-3. メリット

オブジェクト形式マクロを使うメリットは、主に以下の2つである。

【可読性】

例えば、

```c
if (distance <= 20)
```

と書くより、

```c
if (distance <= STOP_DISTANCE)
```

と書いた方が、20という数値が何を意味するのかわかりやすい。

【保守性】

停止距離を20cmから30cmに変更する場合、

```c
#define STOP_DISTANCE 20
```

を、

```c
#define STOP_DISTANCE 30
```

に変更すればよい。

そのマクロ名を使用している箇所に、変更を反映できる。

### 7-4. 注意点

例えば、

```c
#define LED ON 1
```

と書くと、LED_ONというマクロを作ったことにはならない。

この場合は、

- マクロ名：LED
- 置き換える内容：ON 1

と解釈される。

正しくは、

```c
#define LED_ON 1
```

と書く。

## 8. 関数形式マクロ

### 8-1. 関数形式マクロとは

関数形式マクロとは、引数を持つマクロである。

通常の関数に似た書き方ができる。

例えば、

```c
#define TRIPLE(x) ((x) * 3)
```

これは、渡された式を3倍するマクロである。

それぞれの意味は以下のとおり。

- TRIPLE：マクロ名
- x：引数として受け取る部分
- ((x) * 3)：置き換える内容

### 8-2. 使用例

```c
#include <stdio.h>

#define TRIPLE(x) ((x) * 3)

int main(void)
{
    int value = 10;

    int newValue = TRIPLE(value);

    printf("%d\n", newValue);

    return 0;
}
```

前処理によって、

```c
int newValue = TRIPLE(value);
```

が、

```c
int newValue = ((value) * 3);
```

に置き換えられる。

実行結果：

    30

### 8-3. 通常の関数との違い

通常の関数は、関数として定義された処理を呼び出して使用する。

一方、関数形式マクロは、プリプロセッサがコードを置き換える。

例えば、

```c
#define DOUBLE(x) ((x) * 2)
```

というマクロを、

```c
DOUBLE(10)
```

と使用すると、

```c
((10) * 2)
```

に展開される。

つまり、関数形式マクロは、見た目が関数に似ていても通常の関数ではない。

## 9. 条件付きコンパイル

### 9-1. 条件付きコンパイルとは

条件付きコンパイルとは、指定した条件に応じて、コンパイル対象となるコードを選択する仕組みである。

例えば、開発中だけデバッグ用の情報を表示する場合に利用できる。

### 9-2. #ifdef

#ifdefは、指定したマクロが定義されているかどうかを判定する。

基本的な書き方は以下のとおり。

```c
#ifdef DEBUG_MODE
    // DEBUG_MODEが定義されている場合
#else
    // DEBUG_MODEが定義されていない場合
#endif
```

### 9-3. 実際の使用例

```c
#include <stdio.h>

#define DEBUG_MODE

int main(void)
{
#ifdef DEBUG_MODE
    printf("DEBUG MODE\n");
#else
    printf("NORMAL MODE\n");
#endif

    return 0;
}
```

実行結果：

    DEBUG MODE

DEBUG_MODEが定義されているため、#ifdef側のコードがコンパイル対象として残る。

一方、#else側は前処理で除外される。

### 9-4. マクロが定義されていない場合

例えば、

```c
#define DEBUG_MODE
```

という定義が存在しない場合、#else側が選択される。

そのため、表示結果は以下のようになる。

    NORMAL MODE

### 9-5. #define DEBUG_MODE 0の場合

ここは特に注意が必要である。

```c
#define DEBUG_MODE 0
```

と書いた場合でも、

```c
#ifdef DEBUG_MODE
```

は成立する。

理由は、#ifdefがマクロの値ではなく、マクロが定義されているかどうかを判定するためである。

つまり、

- #define DEBUG_MODE：定義されている
- #define DEBUG_MODE 1：定義されている
- #define DEBUG_MODE 0：定義されている
- DEBUG_MODEが未定義：定義されていない

という違いがある。

### 9-6. if文との違い

| 比較 | if文 | #ifdef |
|---|---|---|
| 判定する段階 | プログラムの実行中 | コンパイル前の前処理 |
| 判定するもの | 条件式 | マクロの定義の有無 |
| 主な用途 | 実行中の処理の分岐 | コンパイル対象のコードの切り替え |

重要なのは、#ifdefが実行中の条件分岐ではなく、コンパイル前にコードを選択する仕組みだということである。

## 10. マクロの注意点①：演算子の優先順位

### 10-1. 問題があるマクロ

例えば、次のマクロを定義する。

```c
#define SQUARE(x) x * x
```

このマクロで、

```c
int result = SQUARE(2 + 3);
```

と書いた場合を考える。

プリプロセッサは、単純にxを2 + 3に置き換える。

そのため、

```c
int result = 2 + 3 * 2 + 3;
```

というコードになる。

C言語では乗算が加算より優先されるため、結果は11になる。

本来期待していた結果は、5の2乗である25だった。

### 10-2. 正しいマクロの書き方

この問題を防ぐため、引数と式全体を括弧で囲む。

```c
#define SQUARE(x) ((x) * (x))
```

これなら、

```c
int result = SQUARE(2 + 3);
```

が、

```c
int result = ((2 + 3) * (2 + 3));
```

に展開される。

正しい計算結果は25になる。

### 10-3. 覚えること

関数形式マクロでは、基本的に以下を意識する。

1. 引数を括弧で囲む
2. 式全体も括弧で囲む
3. 演算子の優先順位による問題を防ぐ

ただし、括弧を付けるだけですべての問題を防げるわけではない。

## 11. マクロの注意点②：引数の複数回評価

### 11-1. 引数の複数回評価とは

関数形式マクロでは、引数に渡した式が複数箇所へ展開されることがある。

例えば、

```c
#define CHECK(x) ((x) > 0 && (x) < 20)
```

というマクロがある。

ここで、

```c
int number = 10;

int result = CHECK(++number);
```

と書いた場合を考える。

プリプロセッサによって、

```c
int result = ((++number) > 0 && (++number) < 20);
```

に置き換えられる。

### 11-2. 実際の処理

初期値：

    number = 10

最初の条件：

    ++number

これによってnumberは11になる。

    11 > 0

が真なので、&&の右側も評価される。

次の条件：

    ++number

ここでもnumberが1増加する。

そのため、

    number = 12

となる。

最終的なnumberの値は12になる。

### 11-3. なぜ注意が必要なのか

通常の関数では、引数として渡す式は関数呼び出しの際に評価される。

しかし、関数形式マクロはコードの置き換えなので、引数に渡した式が複数回現れる場合がある。

そのため、

- ++
- --
- 代入
- 副作用を持つ関数呼び出し

などをマクロの引数に渡す場合には注意が必要である。

特に、マクロの展開後の式によっては、未定義動作が発生する可能性もある。

### 11-4. 対策

副作用がある処理を先に実行し、その結果をマクロへ渡す。

例えば、

```c
++number;

int result = CHECK(number);
```

この場合、numberを増やす処理は1回だけになる。

### 11-5. 重要なまとめ

関数形式マクロは便利だが、通常の関数と同じように考えてはいけない。

プリプロセッサがコードを置き換える仕組みであることを理解して使用する必要がある。

## 12. constと#defineの違い

### 12-1. constとは

constは、変数を通じて値を変更できないようにするための型修飾子である。

例えば、

```c
const int maxSpeed = 100;
```

これは、int型の変数maxSpeedを宣言し、100で初期化している。

constが付いているため、通常の代入によって値を変更できない。

例えば、

```c
maxSpeed = 200;
```

という代入は許されない。

### 12-2. #defineとは

一方、

```c
#define MAX_SPEED 100
```

は変数の宣言ではない。

MAX_SPEEDという名前を100へ置き換えるマクロ定義である。

例えば、

```c
int speed = MAX_SPEED;
```

は、プリプロセッサによって、

```c
int speed = 100;
```

に置き換えられる。

### 12-3. 比較

| 比較項目 | const | #define |
|---|---|---|
| 正体 | 型修飾子 | マクロ定義 |
| 変数 | 変数を宣言できる | マクロ自体は変数ではない |
| 型 | intなどの型を持つ | マクロ自体には型がない |
| 処理 | コンパイラが扱う | プリプロセッサが展開する |
| アドレス | 変数のアドレスを取得できる | マクロ自体にはアドレスがない |
| 主な用途 | 型のある変更不可の値 | 定数的な置き換えや前処理の制御 |

なお、constで宣言した変数については、コンパイラの最適化により実際のメモリ配置が省略されることもある。

### 12-4. 使い分け

例えば、車体の停止距離を定義する場合、次の2つが考えられる。

【constの場合】

```c
const int stopDistance = 20;
```

【#defineの場合】

```c
#define STOP_DISTANCE 20
```

どちらも固定的な設定値として使用できる。

ただし、目的が異なる。

- 型のある変更不可の値を扱いたい場合：const
- コンパイル前に名前を別の内容へ置き換えたい場合：#define
- 条件付きコンパイルに使用する場合：#define

固定的な数値だからといって、必ず#defineを使う必要はない。

## 13. 車体制作におけるマクロの活用

今後のSTM32を利用した車体制作では、マクロをさまざまな場面で使用できる。

### 13-1. 使用例

```c
#define STOP_DISTANCE 20
#define MAX_SPEED 100

#define MOTOR_ON 1
#define MOTOR_OFF 0

#define LED_ON 1
#define LED_OFF 0
```

これらのマクロによって、制御に使用する数値へ意味のある名前を付けられる。

### 13-2. 障害物の検知と停止判定

例えば、前方の距離センサーで障害物までの距離を測定し、20cm以下になった場合にモーターを停止するプログラムを考える。

```c
#include <stdio.h>

// 停止判定距離（cm）
#define STOP_DISTANCE 20

// モーターの状態
#define MOTOR_ON 1
#define MOTOR_OFF 0

int main(void)
{
    // センサーの測定値を想定
    int distance = 15;

    // 初期状態はモーターON
    int motorState = MOTOR_ON;

    // 停止距離を判定
    if (distance <= STOP_DISTANCE) {
        motorState = MOTOR_OFF;
    }

    // モーターの状態を表示
    if (motorState == MOTOR_OFF) {
        printf("MOTOR OFF\n");
    } else {
        printf("MOTOR ON\n");
    }

    return 0;
}
```

実行結果：

    MOTOR OFF

今回の例では、distanceが15であり、STOP_DISTANCEが20なので、停止条件が成立する。

### 13-3. 実際の車体との違い

このプログラムは、PC上でモーターの状態を判定するシミュレーションである。

実際の車体では、さらに以下の処理が必要となる。

- STM32からセンサーの測定値を取得する
- センサーの値を基に状態を判定する
- モータードライバなどを通してモーターを制御する

今回の#defineは、これらの制御プログラムで使用する設定値や状態をわかりやすく管理するために役立つ。

なお、実際の組み込み開発では、const、enum、マクロなどを用途に応じて使い分ける。

## 14. 本日の内容を組み合わせたサンプル

今回学習した以下の内容を組み合わせる。

- #include
- #define
- オブジェクト形式マクロ
- 関数形式マクロ
- #ifdef
- const
- 条件分岐

```c
#include <stdio.h>

// 停止距離の設定
#define STOP_DISTANCE 20

// モーター状態の定義
#define MOTOR_ON 1
#define MOTOR_OFF 0

// 数値を2倍にする関数形式マクロ
#define DOUBLE(x) ((x) * 2)

// デバッグモード
#define DEBUG_MODE

int main(void)
{
    // センサーの測定値を想定
    const int distance = 15;

    // モーターの初期状態
    int motorState = MOTOR_ON;

    // 障害物との距離を判定
    if (distance <= STOP_DISTANCE) {
        motorState = MOTOR_OFF;
    }

    // デバッグモードの場合のみ表示
#ifdef DEBUG_MODE
    printf("DEBUG MODE\n");
    printf("Distance: %d cm\n", distance);
    printf("Double Distance: %d cm\n", DOUBLE(distance));
#endif

    // モーターの状態を表示
    if (motorState == MOTOR_OFF) {
        printf("MOTOR OFF\n");
    } else {
        printf("MOTOR ON\n");
    }

    return 0;
}
```

実行結果：

    DEBUG MODE
    Distance: 15 cm
    Double Distance: 30 cm
    MOTOR OFF

### 処理の流れ

① GCCがソースファイルの処理を開始する。

② プリプロセッサがstdio.hの内容を取り込む。

③ #defineによって各マクロを定義する。

④ DEBUG_MODEが定義されているため、デバッグ表示のコードが残る。

⑤ DOUBLE(distance)が((distance) * 2)に置き換えられる。

⑥ 前処理後のコードをコンパイルする。

⑦ アセンブル・リンクを経て実行ファイルが作られる。

⑧ 実行時に距離が判定され、モーターの状態が決定される。

この例では、プリプロセッサが行う処理と、プログラム実行時に行う処理を区別することが重要である。

## 15. 特に重要な理解事項

### 15-1. #includeとプリプロセッサの関係

#include自体がファイルを取り込む処理を実行するわけではない。

#includeは取り込みを指示するものであり、プリプロセッサが実際にその指示を処理する。

### 15-2. ヘッダーファイルとソースファイルの関係

ヘッダーファイルには関数の宣言や型定義などを記述する。

ソースファイルには関数の実際の処理などを記述する。

ヘッダーファイルを取り込むだけで、対応するソースファイルの処理まで自動的に取り込まれるわけではない。

### 15-3. <>と""の違い

<>と""は処理の優先順位ではなく、ファイルを探す方法の違いである。

両者とも#includeによって指定され、プリプロセッサが処理する。

### 15-4. #defineと変数の違い

#defineは変数を作成する仕組みではない。

マクロ名を指定した内容へ置き換える仕組みである。

### 15-5. #ifdefの判定

#ifdefはマクロが定義されているかどうかを判定する。

マクロの値が0であっても、定義されていれば成立する。

### 15-6. 関数形式マクロの注意点

関数形式マクロは、通常の関数とは異なる。

引数を含むコードを直接展開するため、括弧の不足や引数の複数回評価に注意する必要がある。

### 15-7. コンパイルとリンクの違い

コンパイルは、C言語のコードを機械語へ変換するための処理の一部である。

リンクは、コンパイル・アセンブルされた部品を結び付け、実行ファイルを作る処理である。

- 引数と式全体を括弧で囲む
- 引数が複数回評価される場合がある
