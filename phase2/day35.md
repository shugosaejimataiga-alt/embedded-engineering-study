## 2. コンパイルエラーと警告の違い

### コンパイルエラー（Error）

コンパイラがコードを正しく処理できない場合に発生する。

例：
- 文法の誤り
- 存在しない変数の使用
- 不正な型の使い方

通常、エラーが発生するとコンパイルは失敗する。

### 警告（Warning）

コンパイル自体は可能だが、問題が発生する可能性があるコードについて知らせるもの。

例：
- 未使用変数
- 型の不一致
- 符号付き整数と符号なし整数の比較
- 暗黙的な型変換による情報の欠落
- 戻り値が必要な関数で戻り値が不足している

警告が出ても実行ファイルが生成される場合がある。

ただし、警告が出ないことはプログラムの正しさを保証するものではない。

また、`-Werror`を指定すると、警告をエラーとして扱うことができる。

## 3. GCCの警告オプション

基本的なコンパイルコマンド：

```bash
gcc -Wall -Wextra main.c -o main.exe
```

各オプションの意味：

| オプション | 意味 |
|---|---|
| `gcc` | GCCコンパイラを実行 |
| `-Wall` | 多くの代表的な警告を有効化 |
| `-Wextra` | 追加の警告を有効化 |
| `-Wconversion` | 暗黙的な型変換に関する警告を有効化 |
| `-g` | デバッグ情報を実行ファイルに付与 |
| `-o` | 出力ファイル名を指定 |

詳しく警告を確認する場合：

```bash
gcc -Wall -Wextra -Wconversion main.c -o main.exe
```

GDBでデバッグする場合：

```bash
gcc -g -Wall -Wextra main.c -o main.exe
```

### `-g`の重要性

`-g`は、GDBがデバッグ時に利用する情報を実行ファイルに含めるオプション。

これにより、GDB上で以下の情報を確認しやすくなる。

- ソースコードの行番号
- 関数名
- 変数名
- 変数の値
- 関数の呼び出し関係

注意点：

- `-g`自体はデバッガではない。
- `-g`を指定しただけではプログラムはデバッグされない。
- デバッグ操作にはGDBなどのツールを使用する。
- 最適化などの影響で、一部の変数情報が確認できない場合もある。

## 4. コンパイラ警告の種類

### ① 未使用変数（unused variable）

```c
int main(void)
{
    int speed = 20;

    return 0;
}
```

`speed`を宣言したものの、一度も使用していない。

代表的な警告：

```text
warning: unused variable 'speed'
```

意味：

「speedという変数が宣言されているが、使用されていない」

対応方法：

- 不要な変数なら削除する。
- 必要な変数なら、適切に使用する。

### ② printfの型不一致（format）

```c
#include <stdio.h>

int main(void)
{
    int speed = 30;

    printf("%f\n", speed);

    return 0;
}
```

問題点：

- `speed`は`int`型
- `%f`は`double`型を期待する
- 指定子と引数の型が一致していない

修正：

```c
printf("%d\n", speed);
```

主な書式指定子：

| 指定子 | 対応する型 |
|---|---|
| `%d` | int |
| `%u` | unsigned int |
| `%f` | double |
| `%c` | int（文字を表示） |
| `%s` | char*（文字列） |
| `%p` | void* |

※`printf`に渡される`float`型の値は、`double`型に変換される。

警告メッセージの例：

```text
format '%f' expects argument of type 'double',
but argument 2 has type 'int'
```

意味：

「%fはdouble型を期待しているが、2番目の引数はint型である」

`argument 2`は、`printf`の2番目の引数を意味する。

```c
printf("%f\n", speed);
```

- 第1引数：`"%f\n"`
- 第2引数：`speed`

### ③ 符号付き・符号なし整数の比較

```c
int speed = 10;
unsigned int limit = 20;

if (speed < limit)
{
    /* 処理 */
}
```

`int`と`unsigned int`を比較している。

代表的な警告：

```text
comparison of integer expressions of different signedness
```

意味：

「符号の有無が異なる整数式を比較している」

注意点：

負の値が符号なし整数に変換される場合、意図しない比較結果になる可能性がある。

対応方法：

値の範囲や意味を確認し、適切な型で比較する。

### ④ 暗黙的な型変換（conversion）

```c
double temperature = 25.8;
int value = temperature;
```

`double`から`int`への変換が発生している。

この場合、小数部分が失われる。

`-Wconversion`を有効にすると、次のような警告を確認できる。

```text
conversion from 'double' to 'int' may change value
```

意味：

「doubleからintへの変換によって値が変わる可能性がある」

対応方法：

- 本当に変換が必要なのか確認する。
- 小数部分が必要なら`double`のまま扱う。
- 整数化が必要なら、範囲や変換方法を検討する。

### ⑤ 戻り値不足

```c
int getSpeed(void)
{
    int speed = 30;
}
```

この関数は`int`型の値を返す必要があるが、`return`がない。

代表的な警告：

```text
control reaches end of non-void function
```

意味：

「戻り値が必要な関数の末尾まで処理が到達している」

修正：

```c
int getSpeed(void)
{
    int speed = 30;

    return speed;
}
```

## 5. GDBとは

GDB（GNU Debugger）は、プログラムの内部状態を調べるためのデバッガ。

通常の実行では、プログラムが開始から終了まで進む。

GDBを利用すると、プログラムを途中で停止させ、変数の値や関数の呼び出し関係を調査できる。

主な用途：

- 不具合が発生した場所の特定
- 変数の値の確認
- 処理の流れの追跡
- 関数の呼び出し関係の確認
- 変数が変更されたタイミングの調査

### 開発環境

- Windows
- MSYS2 UCRT64
- GCC
- GDB 18.1

GCCとGDBの役割：

| ツール | 役割 |
|---|---|
| MSYS2 UCRT64 | 開発ツールを利用する環境 |
| GCC | C言語のコードをコンパイルする |
| GDB | コンパイルされたプログラムをデバッグする |

## 6. GDBの基本操作

### 使用したソースコード

ファイル名：`debug_step.c`

```c
#include <stdio.h>

int addTen(int value)
{
    int result = value + 10;
    return result;
}

int main(void)
{
    int speed = 20;

    speed = addTen(speed);

    printf("Speed: %d\n", speed);

    return 0;
}
```

このプログラムは、`main`関数から`addTen`関数を呼び出し、`speed`に10を加算する。

### ① コンパイル

```bash
gcc -g -Wall -Wextra debug_step.c -o debug_step.exe
```

GDBで調査できるように、`-g`を付けてコンパイルする。

### ② GDBの起動

```bash
gdb ./debug_step.exe
```

`./`は現在のディレクトリを意味する。

GDBが起動すると、次のような入力待ち状態になる。

```text
(gdb)
```

ここからGDBの各コマンドを使用する。

## 7. break：ブレークポイントの設定

### コマンド

```gdb
break main
```

意味：

`main`関数の開始位置にブレークポイントを設定する。

別の関数に設定する場合：

```gdb
break addTen
```

行番号を指定することもできる。

```gdb
break 13
```

意味：

現在読み込まれているソースコードの13行目にブレークポイントを設定する。

### 重要なポイント

`break`は、あくまで停止位置を設定するコマンド。

**`break`を入力しただけではプログラムは実行されない。**

---

## 8. run：プログラムを実行する

### コマンド

```gdb
run
```

意味：

プログラムを最初から実行する。

ブレークポイントが設定されている場合、その位置に到達すると停止する。

例えば、

```gdb
break main
run
```

と実行すると、`main`関数の開始位置で停止する。

### 最も重要な理解

**GDBがブレークポイントで停止したとき、停止している行の処理はまだ実行されていない。**

例えば、

```c
int speed = 20;
```

で停止しているなら、この行の初期化処理はまだ実行されていない。

次の実行操作によって、この行が実行される。

---

## 9. next：次の行へ進む

### コマンド

```gdb
next
```

意味：

現在停止している行を実行し、次の実行位置で停止する。

例：

```c
int speed = 20;

speed = speed + 10;

printf("%d\n", speed);
```

最初の行で停止しているとする。

```gdb
next
```

を実行すると、

```c
int speed = 20;
```

が実行され、次の行に進む。

さらに`next`を実行すると、

```c
speed = speed + 10;
```

が実行される。

### 関数呼び出しの場合

```c
speed = addTen(speed);
```

この行で`next`を実行すると、`addTen`関数の内部では停止せず、関数の処理を完了してから次の行へ進む。

つまり、**nextは関数の内部に入って逐次停止しない。**

---

## 10. step：関数の内部に入る

### コマンド

```gdb
step
```

`next`との主な違いは、関数呼び出しがある場合に、その関数の内部に入って停止できること。

例：

```c
speed = addTen(speed);
```

この行で`step`を実行すると、`addTen`関数の内部に移動する。

```c
int addTen(int value)
{
    int result = value + 10;
    return result;
}
```

最初の実行対象の行で停止する。

### nextとstepの違い

| コマンド | 動作 |
|---|---|
| `next` | 関数内部で停止せずに次の行へ進む |
| `step` | 関数呼び出しがあれば内部に入る |

どちらも、停止した先の行は原則として実行前である。

---

## 11. print：変数の値を確認する

### コマンド

```gdb
print speed
```

意味：

現在の`speed`の値を表示する。

例：

```text
$1 = 20
```

これは、`speed`の現在の値が20であることを示す。

`$1`はGDBの値履歴を表す番号であり、C言語で定義した変数名ではない。

関数内の変数についても、参照可能な位置であれば確認できる。

```gdb
print result
```

例：

```text
$2 = 30
```

これによって、プログラム実行中の変数の状態を調べられる。

---

## 12. continue：実行を再開する

### コマンド

```gdb
continue
```

意味：

現在の停止位置からプログラムの実行を再開する。

次のブレークポイントやウォッチポイントなどに到達するか、プログラムが終了するまで実行を進める。

### runとの違い

| コマンド | 意味 |
|---|---|
| `run` | プログラムを最初から実行する |
| `continue` | 現在の停止位置から実行を再開する |

---

## 13. watch：変数の変更を監視する

### コマンド

```gdb
watch speed
```

意味：

変数`speed`の値が変更されたことを検出した際に、プログラムを停止させる。

例：

```c
int speed = 20;

speed = speed + 10;
```

初期化後に`speed`の監視を設定した場合、

```c
speed = speed + 10;
```

が実行され、値が変更されると停止する。

### GDBの表示例

```text
Hardware watchpoint 2: speed

Old value = 20
New value = 30
```

それぞれの意味：

- `Hardware watchpoint`：ハードウェアを利用した監視ポイント
- `speed`：監視対象の変数
- `Old value`：変更前の値
- `New value`：変更後の値

### 学習中に確認した重要事項

`Old value`と`New value`の`value`は、「値」という英単語。

C言語の関数引数として定義した`value`という変数名を指しているわけではない。

例えば、

```c
int addTen(int value)
```

という関数が存在していても、

```text
Old value = 20
New value = 30
```

は、`watch speed`で監視している変数`speed`の変更前後の値を意味する。

### breakとの違い

| コマンド | 停止条件 |
|---|---|
| `break` | 指定した関数や行に到達したとき |
| `watch` | 監視対象の値が変更されたとき |

`watch`は、どの処理によって変数が変更されたかを調べる際に役立つ。

## 14. backtrace：関数の呼び出し関係を確認する

### コマンド

```gdb
backtrace
```

省略形：

```gdb
bt
```

意味：

現在の実行位置に至るまでの関数の呼び出し関係を表示する。

### 実際に学習した例

`debug_step.c`で次の操作を行った。

```gdb
break addTen
run
backtrace
```

`addTen`関数で停止した状態で、関数の呼び出し関係を確認した。

表示例：

```text
#0  addTen (value=20) at debug_step.c:5
#1  main () at debug_step.c:13
```

意味：

#### #0 addTen

現在停止している関数。

`addTen`関数の5行目で停止しており、引数`value`には20が渡されている。

#### #1 main

`addTen`関数を呼び出した関数。

`main`関数の13行目から`addTen`が呼び出されている。

### 呼び出し関係

```text
main()
  ↓
addTen()
```

### backtraceの読み方

- `#0`：現在の関数
- `#1`：現在の関数を呼び出した関数
- `#2`：さらにその呼び出し元の関数

このように、番号が大きくなるほど呼び出し元をさかのぼる。

例：

```text
#0  checkSensor()
#1  readSensor()
#2  main()
```

実際の呼び出し順序：

```text
main()
  ↓
readSensor()
  ↓
checkSensor()
```

### 注意点

`backtrace`は、過去に実行した全処理の履歴ではない。

現在の実行位置における**関数の呼び出しスタック（コールスタック）**を確認するためのコマンドである。

## 15. GDBで実行ファイルを読み込めない場合

今回、実行ファイル名を誤って指定したことで、GDBが正しくファイルを読み込めない問題が発生した。

入力したコマンド：

```bash
gdb ./debug_35.exe
```

表示：

```text
./debug_35.exe: No such file or directory.
```

意味：

指定した実行ファイルが見つからない。

そのまま、

```gdb
break addTen
```

を実行すると、

```text
No symbol table is loaded. Use the "file" command.
```

と表示された。

### 原因

実行ファイルが正しく読み込まれていないため、GDBが`addTen`関数の位置を特定できなかった。

### 解決方法

GDB上で正しい実行ファイルを読み込む。

```gdb
file ./debug_step.exe
```

正常に読み込めれば、次のように表示される。

```text
Reading symbols from ./debug_step.exe...
```

その後、

```gdb
break addTen
```

を実行すると、ブレークポイントを設定できる。

### 学んだこと

- GDBの起動と実行ファイルの読み込みは区別する。
- GDBを起動できても、対象の実行ファイルが読み込まれているとは限らない。
- ファイル名とパスを正しく指定する必要がある。
- GDB起動後も`file`コマンドで実行ファイルを読み込める。

## 18. 警告とGDBの使い分け

### コンパイラ警告

主にコードの問題をコンパイル時に検出する。

例：

- 型が一致していない
- 変数が使われていない
- 戻り値が不足している
- 暗黙的な型変換が発生している

### GDB

実行中のプログラムの状態を確認する。

例：

- 変数が想定と異なる値になっている
- どの関数から処理が呼び出されたか不明
- どの行で変数が変化したか調べたい
- 途中の処理を一行ずつ確認したい

### 違い

| 観点 | コンパイラ警告 | GDB |
|---|---|---|
| 使用する段階 | コンパイル時 | 実行時 |
| 主な目的 | コード上の問題の検出 | 実行中の問題の調査 |
| 変数の現在値 | 基本的に確認できない | 確認できる |
| 実行順序の追跡 | できない | できる |
| 呼び出しスタック | 確認しない | 確認できる |

どちらも、C言語で安全性や信頼性の高いプログラムを開発するために重要な技術である。

## 19. 今回の学習で理解した重要事項

### ① breakとrunの違い

`break`は停止位置の設定。

`run`はプログラムの実行開始。

ブレークポイントを設定しただけでは、プログラムは実行されない。

### ② 停止中の行はまだ実行されていない

GDBで現在表示されている停止行は、基本的に次に実行される行である。

その行を実行するには`next`や`step`などを使用する。

### ③ nextとstepの違い

`next`は関数呼び出しの内部を追跡せずに実行する。

`step`は関数呼び出しがあれば、その内部に入って追跡できる。

### ④ watchは値が変更された後に停止する

`watch`は、監視対象の値が変更されたことを検出して停止する。

変更前と変更後の値を確認できる。

### ⑤ backtraceは呼び出し元を調べる

`backtrace`を使うと、現在の関数がどの関数から呼び出されたかを調べられる。

`#0`が現在の関数であり、番号が大きくなるほど呼び出し元になる。

### ⑥ 警告は英語の意味を読み取ることが重要

警告の全文を暗記する必要はない。

- どのファイルか
- どの行か
- どのような問題か
- どの型や変数が関係しているか

を確認し、原因と修正方法を判断する。
