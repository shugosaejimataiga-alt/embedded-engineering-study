

# C-Day24 配列とポインタの関係

## 今日の学習内容

C-Day24では、以下を学習した。

- 配列名と先頭要素のアドレス
- 配列からポインタへの変換
- 配列とポインタの違い
- `sizeof` による配列とポインタの大きさの確認
- 配列がメモリ上でどのように配置されるか
- `p` と `*p` の違い
- `numbers`、`&numbers[0]`、`&numbers` の違い
- ポインタ自身の大きさと、指している値の大きさの違い

---

## 1. 配列名と先頭要素のアドレス

配列を次のように作る。

    int numbers[3] = {10, 20, 30};

配列名 `numbers` は、多くの式の中では、

    &numbers[0]

と同じように、配列の先頭要素のアドレスとして扱われる。

整理すると、

    numbers[0]
    → 先頭要素の値

    &numbers[0]
    → 先頭要素のメモリアドレス

    numbers
    → 多くの式では先頭要素のメモリアドレスとして扱われる

そのため、

    printf("%p\n", (void *)numbers);
    printf("%p\n", (void *)&numbers[0]);

では、同じアドレスが表示される。

理由は、

    配列が始まる場所
    =
    numbers[0] が置かれている場所

だからである。

---

## 2. 配列の先頭アドレスをポインタへ保存する

    int numbers[3] = {10, 20, 30};
    int *p = numbers;

と書くことができる。

これは、

    int *p = &numbers[0];

と同じ意味になる。

つまり、

    numbers
    → numbers[0] のアドレス

    p
    → numbers[0] のアドレスを保存するポインタ変数

となる。

---

## 3. `p` と `*p` の違い

    int numbers[3] = {10, 20, 30};
    int *p = numbers;

の場合、

    p
    → numbers[0] のメモリアドレス

    *p
    → pが指しているメモリアドレスに保存されている値
    → numbers[0]
    → 10

となる。

つまり、

    printf("%p\n", (void *)p);

ではアドレスを表示する。

一方、

    printf("%d\n", *p);

では、ポインタが指している先の値を表示する。

---

## 4. メモリを使うとは何か

「メモリを使う」とは、電力のように消費してなくなるという意味ではない。

RAMを大きな保存用の箱と考えると、

    RAM
    → 大きな保存領域

    変数や配列
    → その中の一部の領域を使用する

というイメージになる。

例えば、

    int number = 10;

で、`int` が4byteの環境なら、`number` は4byte分のメモリ領域を使用する。

イメージ：

    アドレス1000  [1byte]
    アドレス1001  [1byte]
    アドレス1002  [1byte]
    アドレス1003  [1byte]

    ↑
    number が使用する4byte

つまり、

    int型が4byte
    ↓
    int型の変数1個も4byte使用する

という関係になる。

---

## 5. データ型と変数の大きさ

例えば、

    int number;

では、

    int
    → データ型

    number
    → int型の変数

である。

その環境で `int` が4byteなら、

    sizeof(int)
    → 4

    sizeof(number)
    → 4

となる。

これは、

    int型のデータを保存するには4byte必要
    ↓
    int型の変数numberも4byte使用する

からである。

別の型なら大きさも変わる。

例えば、

    double number;

で `double` が8byteなら、

    sizeof(double)
    → 8

    sizeof(number)
    → 8

となる。

---

## 6. `sizeof` の意味

`sizeof` は、型・変数・配列などがメモリ上で何byte必要かを調べるために使う。

例えば、

    int numbers[5] = {10, 20, 30, 40, 50};

で `int` が4byteなら、

    sizeof(numbers)

は、

    4byte × 5要素
    = 20byte

となる。

配列の場合、

    sizeof(配列名)
    =
    要素1個の大きさ × 要素数

と考えられる。

---

## 7. ポインタ変数自身にも大きさがある

ポインタは、メモリアドレスを保存する変数である。

例えば、

    int *p;

では、`p` 自体も変数なので、メモリ上に保存される。

一般的な64bit環境では、

    sizeof(p)

は8byteになることが多い。

重要なのは、

    sizeof(p)

が測っているのは、

    pが指している先の値の大きさ

ではなく、

    ポインタ変数pそのものの大きさ

ということである。

一方、

    sizeof(*p)

なら、`p` が指している先の型の大きさになる。

例えば、

    int *p;

で、

    int型
    → 4byte

    ポインタ
    → 8byte

の環境なら、

    sizeof(p)
    → 8byte

    sizeof(*p)
    → 4byte

となる。

---

## 8. なぜ64bit環境ではポインタが8byteになることが多いのか

ポインタに保存されるのは、メモリアドレスである。

例えば、

    int number = 10;
    int *p = &number;

では、

    number
    → 値10を保存する変数

    p
    → numberが置かれている場所のアドレスを保存する変数

である。

ポインタに入るのは、アドレス1個だけである。

ただし、そのアドレス番号自体を表すために十分なbit数が必要になる。

一般的な64bit環境では、ポインタも64bit幅で扱われることが多い。

    8bit = 1byte

なので、

    64bit ÷ 8
    = 8byte

となる。

つまり、

    64bit分のアドレス番号を保存できる箱
    ↓
    8byteのポインタ

という関係である。

ただし、

    2^64個のアドレスを全部保存している

わけではない。

正しくは、

    64bitで表現できる多くのアドレス番号の中から
    1個のアドレス番号を保存する

という意味である。

---

## 9. ポインタの大きさと、指しているデータの大きさは別

例えば、

    char *a;
    int *b;
    double *c;

があった場合でも、一般的な64bit環境では、

    sizeof(a)
    → 8byte

    sizeof(b)
    → 8byte

    sizeof(c)
    → 8byte

となることが多い。

しかし、それぞれが指しているデータ型の大きさは違う。

    char
    → 1byte

    int
    → 4byte

    double
    → 8byte

つまり、

    ポインタの大きさ
    → アドレスを保存するための大きさ

    指している値の大きさ
    → そのデータ型によって決まる

という違いがある。

---

## 10. コンパイラとデータ型

コンパイラは、C言語で書いたコードをCPUが実行できる機械語へ変換するプログラムである。

例えば、

    int number;
    int *p = &number;

と書いた場合、コンパイラはCコードの宣言から、

    number
    → int型

    p
    → int型のデータを指すポインタ

と理解する。

その環境で、

    int = 4byte

と決まっていれば、

    *p

を扱うとき、

    pに保存されているアドレスから
    int型として4byte分を読み書きする

ような機械語を作る。

重要なのは、

    メモリアドレスそのものに
    「ここにはint型があります」
    という情報が入っているわけではない

ということである。

Cコードに書かれた型をコンパイラが理解し、その型に応じた大きさでメモリを読み書きする。

---

## 11. 配列とポインタは同じものではない

例えば、

    int numbers[4] = {5, 10, 15, 20};
    int *p = numbers;

の場合、

    numbers
    → int型4個を持つ配列そのもの
    → 配列全体で16byte

    p
    → メモリアドレスを1個保存するポインタ変数
    → 今回の環境では8byte

となる。

つまり、

    配列
    → 複数の値そのものを保存する領域

    ポインタ
    → メモリアドレスを1個保存する変数

である。

ただし、配列名 `numbers` は多くの式の中では、

    &numbers[0]

つまり先頭要素のアドレスとして扱われる。

このため、配列名とポインタは似た使い方ができるが、同じものではない。

---

## 12. `numbers` と `&numbers[0]` と `&numbers` の違い

次の配列がある。

    int numbers[4] = {5, 10, 15, 20};

`numbers` は多くの式では、

    &numbers[0]

と同じように、先頭要素のアドレスとして扱われる。

そのため、

    int *p = numbers;

と書ける。

一方、

    &numbers

は、

    配列numbers全体のアドレス

を表す。

アドレスの数値上は、どれも同じ開始地点になる。

    numbers
    &numbers[0]
    &numbers

しかし、C言語上の型は違う。

    numbers
    → 多くの式では int *

    &numbers[0]
    → int *

    &numbers
    → int (*)[4]

したがって、

    int *p = numbers;

は正しい。

一方、

    int *p = &numbers;

は型が違う。

配列全体を指すポインタを作るなら、

    int (*p)[4] = &numbers;

という形になる。

ただし、これは「4個のアドレスを保存する」という意味ではない。

このポインタも保存しているアドレスは1個である。

---

## 13. 配列の要素数とポインタ

    int numbers[4] = {5, 10, 15, 20};

と宣言した時点で、コンパイラは、

    numbers
    → int型4個の配列

と知っている。

そのため、

    sizeof(numbers)

では、

    int型4byte × 4要素
    = 16byte

と判断できる。

しかし、

    int *p = numbers;

とすると、`p` の型は、

    int *

である。

`p` が持っているのは先頭要素のアドレス1個であり、

    この配列は4要素ある

という情報は `p` 自体には保存されていない。

つまり、

    numbers
    → int[4]
    → 要素数4という情報がある

    p
    → int *
    → int型のデータを指すことは分かる
    → 元の配列が4要素だったという情報は持っていない

という違いがある。

これも、

    配列とポインタは同じものではない

という理由の1つである。

---

## 14. 配列はメモリ上で連続して配置される

例えば、

    int numbers[4] = {5, 10, 15, 20};

で `int` が4byteの場合、

    numbers[0]   numbers[1]   numbers[2]   numbers[3]

        5            10           15           20
    [ 4byte ]    [ 4byte ]    [ 4byte ]    [ 4byte ]

のように、配列の各要素はメモリ上で連続して配置される。

    int *p = numbers;

とすると、`p` が保存しているのは、

    numbers[0] のアドレス1個

だけである。

先頭アドレスと最後のアドレスの2つを保存しているわけではない。

また、`p` 自体には、

    この配列は4要素ある

という情報も保存されていない。

配列の2個目以降へポインタで移動する方法は、次のC-Day25「ポインタ演算」で学習する。

---

## 15. Day24で特に重要な整理

    numbers
    → 多くの式では numbers[0] のアドレス

    &numbers[0]
    → numbers[0] のアドレス

    p
    → メモリアドレスを保存するポインタ変数

    *p
    → pが指している場所に保存されている値

    sizeof(numbers)
    → 配列全体の大きさ

    sizeof(p)
    → ポインタ変数pそのものの大きさ

    &numbers
    → 配列全体を指すアドレス

---

## 16. 最終問題で確認した内容

使用した配列：

    int numbers[4] = {5, 10, 15, 20};

ポインタ：

    int *p = numbers;

このとき、

    p
    numbers
    &numbers[0]

は同じ開始アドレスを表す。

理由は、

    numbers
    → 多くの式では配列の先頭要素のアドレス

    p
    → そのアドレスを保存している

    &numbers[0]
    → 先頭要素そのもののアドレス

だからである。

また、

    *p

はアドレスではない。

    *p
    → pが指しているアドレスにある値
    → numbers[0]
    → 5

となる。

`sizeof` については、

    sizeof(numbers)
    → 4byte × 4要素
    → 16byte

    sizeof(p)
    → ポインタ変数pそのもの
    → 今回の環境では8byte

となる。
