# 2. .cファイルと.hファイル

## 2-1. .cファイルとは

`.c`ファイルは、C言語のソースファイルである。

主に、関数の定義や具体的な処理を記述する。

例：calc.c

```c
// 足し算を行う関数
int add(int a, int b)
{
    return a + b;
}
```

このファイルには、実際に足し算を行う処理が記述されている。

### 主な役割

- 関数の具体的な処理を記述する
- プログラムの動作を実装する
- main関数を定義する
- 必要に応じて変数などを定義する

main関数は通常、main.cなどのソースファイルに記述する。

また、関数を別の.cファイルに分割することもできる。

---

## 2-2. .hファイルとは

`.h`ファイルは、ヘッダーファイルである。

主に、他のファイルと共有する宣言や型定義などを記述する。

例：calc.h

```c
// 足し算を行う関数の宣言
int add(int a, int b);
```

これは関数の宣言であり、実際の計算処理は記述されていない。

### ヘッダーファイルに記述するもの

- 関数プロトタイプ
- structによる構造体の型定義
- enumによる列挙型の定義
- typedefによる型名の定義
- #defineによるマクロ定義
- 必要な定数などの宣言

例：

```c
#ifndef SENSOR_H
#define SENSOR_H

// センサーの構造体
typedef struct {
    int temperature;
    int humidity;
} Sensor;

// センサーを処理する関数の宣言
void processSensor(Sensor sensor);

#endif
```

このように、複数のファイルで共有する型や関数の宣言をまとめることができる。

### 注意点

.hファイルは、必ず型定義を書くためのファイルというわけではない。

関数の宣言だけを記述することもある。

また、ヘッダーファイルにすべての関数の実装を書くわけではない。

通常、関数の具体的な処理は.cファイルに記述する。

---

## 2-3. .cと.hの違い

| ファイル | 主な役割 |
|---|---|
| .c | 関数などの具体的な処理を実装する |
| .h | 関数の宣言や共有する型定義などを記述する |

### 今回理解したこと

.cファイルには、実際の関数の処理を記述する。

.hファイルには、他のファイルから利用する関数の宣言や、共有する構造体などを記述する。

このように役割を分けることで、プログラムを整理しやすくなる。

---

# 3. 宣言と定義

## 3-1. 宣言とは

宣言とは、コンパイラに名前や型などの情報を知らせることである。

関数の場合、次のように記述する。

```c
int add(int a, int b);
```

この宣言によって、コンパイラは以下の情報を把握できる。

- 関数名：add
- 第1引数：int型
- 第2引数：int型
- 戻り値：int型

ただし、実際の計算処理は記述されていない。

---

## 3-2. 定義とは

関数の定義とは、実際の処理内容を記述することである。

```c
int add(int a, int b)
{
    return a + b;
}
```

ここでは、2つの整数を足し合わせる処理を実装している。

### 違い

宣言：

```c
int add(int a, int b);
```

定義：

```c
int add(int a, int b)
{
    return a + b;
}
```

### 注意点

関数の定義は、宣言も兼ねる。

また、関数の定義を呼び出しより前に記述していれば、別途関数プロトタイプを書く必要はない。

変数にも宣言と定義の区別がある。

---

# 4. 関数プロトタイプ

## 4-1. 関数プロトタイプとは

関数の戻り値の型、名前、引数の型などをコンパイラに知らせるための宣言である。

例：

```c
int add(int a, int b);
```

これによって、コンパイラは関数の呼び出し方を確認できる。

---

## 4-2. 関数プロトタイプが必要な理由

例えば、次のコードを考える。

```c
#include <stdio.h>

// 関数プロトタイプ
int add(int a, int b);

int main(void)
{
    int result = add(10, 20);

    printf("%d\n", result);

    return 0;
}

// 関数の定義
int add(int a, int b)
{
    return a + b;
}
```

この場合、main関数より後ろにadd関数が定義されている。

しかし、main関数より前に関数プロトタイプがあるため、コンパイラはadd関数の情報を把握できる。

### コンパイラが確認する内容

```c
int add(int a, int b);
```

この関数にはint型の引数が2つ必要である。

正しい呼び出し：

```c
add(10, 20);
```

間違った呼び出し：

```c
add(10);
```

後者は引数が1つしかないため、コンパイルエラーになる。

### 重要

関数プロトタイプは、関数の処理内容を実行するものではない。

コンパイラが関数の呼び出し方を確認するための情報を与えるものである。

また、関数プロトタイプによって、すべてのプログラムの不具合を発見できるわけではない。

---

# 5. #includeの仕組み

## 5-1. #includeとは

`#include`は、指定されたファイルの内容を取り込むためのプリプロセッサ指示である。

例：

```c
#include "calc.h"
```

これは、calc.hというヘッダーファイルの内容を取り込むという意味である。

---

## 5-2. プリプロセッサによる展開

次の2つのファイルを考える。

### calc.h

```c
int add(int a, int b);
```

### main.c

```c
#include "calc.h"

int main(void)
{
    int result = add(10, 20);

    return 0;
}
```

プリプロセッサが#includeを処理すると、calc.hの内容がその場所に展開される。

概念的には、次のコードになる。

```c
int add(int a, int b);

int main(void)
{
    int result = add(10, 20);

    return 0;
}
```

つまり、

```c
#include "calc.h"
```

という部分に、calc.hの中身が取り込まれる。

これが「展開」である。

### 注意点

プリプロセッサがmain.cの保存内容を直接書き換えるわけではない。

コンパイル前に処理されたコードが、次のコンパイル工程に渡される。

---

## 5-3. #includeでcalc.cも取り込まれるのか

取り込まれない。

例えば、

```c
#include "calc.h"
```

と書いても、calc.cの関数の処理内容が自動的に展開されるわけではない。

取り込まれるのは、指定したcalc.hの内容である。

calc.cは別のソースファイルとしてコンパイルする。

そして、最終的にリンカがオブジェクトファイルを結び付ける。

---

# 6. プリプロセッサの復習

プリプロセッサは、コンパイル前にソースコードを加工する役割を持つ。

代表的な指示を整理する。

| 指示 | 役割 |
|---|---|
| #include | 指定されたファイルの内容を取り込む |
| #define | マクロを定義する |
| #ifdef | 指定したマクロが定義されている場合に処理する |
| #ifndef | 指定したマクロが定義されていない場合に処理する |
| #endif | 条件付き処理の範囲を終了する |

---

## 6-1. #define

#defineはマクロを定義するための指示である。

例：

```c
#define MAX_SPEED 100
```

この場合、MAX_SPEEDは100に置き換えられる。

一方、次のような書き方もできる。

```c
#define SENSOR_H
```

これは、SENSOR_Hというマクロを定義するだけである。

置き換える値は必要ない。

### 重要

マクロには、値の置き換えだけでなく、定義されているかどうかを条件判定に利用する使い方もある。

---

## 6-2. #ifdef

#ifdefは、指定されたマクロが定義されている場合に、その範囲を処理対象にする。

例：

```c
#include <stdio.h>

#define DEBUG

int main(void)
{
#ifdef DEBUG
    printf("DEBUG MODE\n");
#endif

    return 0;
}
```

DEBUGというマクロが定義されているため、printfの処理がコンパイル対象になる。

---

## 6-3. #ifndef

#ifndefは、指定されたマクロが定義されていない場合に、その範囲を処理対象にする。

例：

```c
#ifndef SENSOR_H
#define SENSOR_H

// この範囲はSENSOR_Hが未定義の場合に処理される

#endif
```

この仕組みを利用したものがインクルードガードである。

---

# 7. インクルードガード

## 7-1. インクルードガードとは

インクルードガードとは、同じヘッダーファイルの内容が、1つの翻訳単位で重複して展開されることを防ぐ仕組みである。

ヘッダーファイルには、構造体などの型定義を記述することがある。

同じ構造体の定義が1つの翻訳単位に重複して現れると、コンパイルエラーになる。

これを防ぐためにインクルードガードを使用する。

---

## 7-2. なぜ重複が発生するのか

例えば、次の3つのファイルがあるとする。

### sensor.h

```c
typedef struct {
    int temperature;
} Sensor;
```

### control.h

```c
#include "sensor.h"

// ファン制御関数の宣言
void controlFan(Sensor sensor);
```

### main.c

```c
#include "sensor.h"
#include "control.h"

int main(void)
{
    return 0;
}
```

この場合、main.cから次のような読み込みが発生する。

1. main.cの#include "sensor.h"を処理する
2. sensor.hの構造体を取り込む
3. main.cの#include "control.h"を処理する
4. control.hの中にある#include "sensor.h"を処理する
5. sensor.hの構造体を再び取り込もうとする

結果として、Sensorという構造体の型定義が重複する。

これは、main.cに#include "sensor.h"を2回直接書いたからではない。

ヘッダーファイル同士の読み込み関係によって、結果的に同じ内容が2回展開されるためである。

---

## 7-3. インクルードガードの書き方

sensor.hを次のように変更する。

```c
#ifndef SENSOR_H
#define SENSOR_H

// センサーの構造体
typedef struct {
    int temperature;
} Sensor;

#endif
```

### 各指示の意味

```c
#ifndef SENSOR_H
```

SENSOR_Hというマクロが定義されていなければ、対応する#endifまでの内容を処理する。

```c
#define SENSOR_H
```

SENSOR_Hというマクロを定義する。

```c
#endif
```

条件付き処理の範囲を終了する。

---

## 7-4. なぜ重複を防げるのか

1回目の読み込みでは、

- SENSOR_Hがまだ定義されていない
- #ifndefの条件が成立する
- #define SENSOR_Hが処理される
- 構造体の定義が取り込まれる

2回目の読み込みでは、

- SENSOR_Hがすでに定義されている
- #ifndefの条件が成立しない
- #endifまでの内容が処理対象から外れる
- 構造体の定義が再び取り込まれることを防げる

つまり、最初の読み込みでマクロを定義することによって、同じ前処理の中で2回目以降の内容を飛ばせる。

---

## 7-5. SENSOR_HやCALC_Hとは何か

SENSOR_HやCALC_Hは、実際のファイル名ではない。

プログラマーが決めたマクロの名前である。

例えば、

```c
#include "calc.h"
```

このcalc.hは実際のヘッダーファイルを指す。

一方、

```c
#define CALC_H
```

このCALC_Hはマクロ名である。

大文字で書くのは一般的な命名規則であり、C言語の文法上、必ず大文字でなければならないわけではない。

ヘッダーファイルの名前に対応したマクロ名を使用すると、管理しやすい。

ただし、他のマクロと名前が重複しないようにする必要がある。

---

## 7-6. インクルードガードが不要な場合

今回のcalc.hのように、単純な関数プロトタイプだけを記述したヘッダーでは、同じ宣言が繰り返されても問題にならない場合がある。

また、複数の.cファイルがそれぞれ同じ.hを読み込むこと自体も問題ではない。

問題になるのは、1つの翻訳単位で重複した定義が現れる場合である。

それでも、実際の開発では、ヘッダーファイルを作成するときにインクルードガードを記述するのが一般的である。

理由は、プログラムが大きくなった際に、ヘッダー同士の読み込みによる問題を防ぎやすくするためである。

### 注意点

インクルードガードは、複数の.cファイル間で発生する関数や外部変数の重複定義まで防ぐものではない。

# 8. モジュール分割

## 8-1. モジュール分割とは

プログラムの機能や役割ごとに、ソースファイルやヘッダーファイルを分けることである。

例えば、センサー制御プログラムの場合、

- main.c：プログラム全体の管理
- sensor.c：センサー処理の実装
- sensor.h：センサー関連の宣言や型定義
- control.c：制御処理の実装
- control.h：制御処理の宣言

という分割ができる。

### メリット

- ファイルごとの役割が明確になる
- プログラムを管理しやすくなる
- 不具合が発生したときに調査しやすい
- 機能ごとに修正しやすい
- 他のプログラムから関数などを再利用しやすくなる
- チームで開発しやすくなる

組み込みソフトウェア開発でも重要な考え方である。

# 9. 実践：複数ファイルによる計算プログラム

今回は、次の3つのファイルを作成した。

```text
embedded-engineering-study/
│
├── main.c
├── calc.c
└── calc.h
```

最初はadd関数のみを使用した。

その後、multiply関数を追加する演習を実施した。

実行結果は以下のとおり。

```text

```

以下は、今回の処理を整理したコード例である。

---

## 9-1. calc.h

```c

int add(int a, int b);

// 2つの整数を乗算する関数の宣言

```

### 役割

- add関数を宣言する
- multiply関数を宣言する
- インクルードガードで重複展開を防ぐ

---

## 9-2. calc.c

```c
#include "calc.h"

// 2つの整数を加算する関数
int add(int a, int b)
{
    return a + b;
}

// 2つの整数を乗算する関数
int multiply(int a, int b)
{
    return a * b;
}
```

### 役割

- add関数の具体的な処理を定義する
- multiply関数の具体的な処理を定義する

また、calc.hを読み込むことで、宣言と定義の型などが一致しているかコンパイラが確認できる。

---

## 9-3. main.c

```c
#include <stdio.h>

int main(void)
{
    // 足し算の結果を保存
    int result1 = add(10, 20);

    // 掛け算の結果を保存
    int result2 = multiply(5, 4);

    // 計算結果を表示
    printf("%d\n", result1);
    printf("%d\n", result2);

    return 0;
}
```

### 役割

- calc.hから関数の宣言を取り込む
- add関数を呼び出す
- multiply関数を呼び出す
- 計算結果を表示する

main.cには、add関数やmultiply関数の処理内容を直接記述していない。

実際の関数の処理はcalc.cに実装されている。

# 10. 複数ファイルのコンパイル

## 10-1. 使用したコマンド

PowerShellで以下のコマンドを実行した。

```powershell
gcc -Wall -Wextra main.c calc.c -o main.exe
```

### 各部分の意味

| コマンド | 意味 |
|---|---|
| gcc | GCCを使用する |
| -Wall | 多くの一般的な警告を有効にする |
| -Wextra | 追加の警告を有効にする |
| main.c | コンパイル対象のソースファイル |
| calc.c | コンパイル対象のソースファイル |
| -o main.exe | 生成する実行ファイル名を指定する |

GCCは、指定されたソースファイルに対して必要な処理を実行し、最終的に実行ファイルを生成する。

---

## 10-2. 実行コマンド

```powershell
.\main.exe
```

実行結果：

```text
30
20
```

正常に実行できた。

# 11. ソースコードから実行ファイルができる流れ

C言語のプログラムは、基本的に次の流れで実行ファイルになる。

```text
ソースコード（.c）
        ↓
① プリプロセッサ
        ↓
前処理済みソースコード
        ↓
② コンパイラ
        ↓
アセンブリ言語
        ↓
③ アセンブラ
        ↓
オブジェクトファイル（.o）
        ↓
④ リンカ
        ↓
実行ファイル（.exe）
```

---

## 11-1. プリプロセッサ

コンパイル前にソースコードを加工する。

例えば、

```c
#include "calc.h"
```

という指示に従い、calc.hの内容を取り込む。

また、

- #defineによるマクロの処理
- #ifdefによる条件付き処理
- #ifndefによる条件付き処理

なども行う。

---

## 11-2. コンパイラ

プリプロセッサが加工したコードを受け取り、文法や型などを確認する。

例えば、

```c
int add(int a, int b);
```

という宣言を確認すると、

- add関数が存在するという宣言
- 引数はint型が2つ
- 戻り値はint型

という情報を把握する。

その情報を使って、

```c
add(10, 20);
```

という呼び出しが、宣言された関数の型に適合しているか確認する。

そして、コードをアセンブリ言語に変換する。

### 重要

コンパイラは、単にコードを変換するだけではない。

文法や型の確認なども行う。

---

## 11-3. アセンブラ

コンパイラが生成したアセンブリ言語を機械語へ変換する。

その結果、オブジェクトファイルが作成される。

通常、拡張子は.oなどになる。

### 用語の違い

- アセンブリ言語：低水準のプログラミング言語
- アセンブラ：アセンブリ言語を機械語に変換するプログラム
- アセンブル：その変換処理

---

## 11-4. リンカ

リンカは、オブジェクトファイルや必要なライブラリを結び付ける。

例えば、

main.cからmain.oが生成される。

calc.cからcalc.oが生成される。

リンカは、main.oにあるadd関数の呼び出しと、calc.oにあるadd関数の実体を結び付ける。

その結果、実行ファイルが生成される。

### 重要

リンカは、.cファイルそのものを直接結び付けるわけではない。

コンパイル・アセンブルによって生成されたオブジェクトファイルなどを結び付ける。

---

# 12. main.cとcalc.cが連携できる理由

今回の学習で特に重要だった部分。

### main.c

```c
#include "calc.h"

int main(void)
{
    int result = add(10, 20);

    return 0;
}
```

### calc.h

```c
int add(int a, int b);
```

### calc.c

```c
#include "calc.h"

int add(int a, int b)
{
    return a + b;
}
```

この3つのファイルは、次の仕組みで連携する。

### ① プリプロセッサ

main.cにある

```c
#include "calc.h"
```

の指示に従って、calc.hにあるadd関数の宣言を展開する。

### ② コンパイラ

展開された関数の宣言を確認する。

その情報を使い、add関数の呼び出し方が正しいか確認する。

### ③ アセンブラ

main.cとcalc.cから、それぞれオブジェクトファイルを生成する。

### ④ リンカ

main.oにある関数の呼び出しと、calc.oにある関数の実体を結び付ける。

### 結論

main.cに関数の具体的な処理を書いていなくても、calc.hで関数の宣言を共有し、calc.cで実装し、最終的にリンカが結び付けることで、関数を呼び出せる。

# 13. コンパイル時のエラーと警告

今回の実践では、次のエラーが発生した。

```text
main.c:12:5: error: expected ',' or ';' before 'printf'
```

また、次の警告も表示された。

```text
main.c:7:9: warning: unused variable 'result1'
```

---

## 13-1. セミコロンの付け忘れ

C言語では、多くの文の最後にセミコロンが必要である。

誤った例：

```c
int result2 = multiply(5, 4)
printf("%d\n", result1);
```

正しい例：

```c
int result2 = multiply(5, 4);
printf("%d\n", result1);
```

今回のエラーは、セミコロンの付け忘れなどによって発生する構文エラーである。

---

## 13-2. unused variable

```text
warning: unused variable 'result1'
```

これは、変数result1が使用されていないとコンパイラが判断したことを示す。

ただし、別の構文エラーが原因で追加の警告が発生する場合もある。

そのため、まず構文エラーを修正し、再度コンパイルすることが重要である。

---

## 13-3. 修正結果

修正後、次のコマンドを再実行した。

```powershell
gcc -Wall -Wextra main.c calc.c -o main.exe
```

その後、

```powershell
.\main.exe
```

を実行した。

結果：

```text
30
20
```

エラーや警告が表示されず、正常に実行できた。

### 学んだこと

- コンパイルエラーの発生箇所を確認する
- エラーメッセージを読む
- セミコロンなどの構文を確認する
- 修正後に再コンパイルする
- 警告が残っていないことも確認する

# 14. 今回特に重要だった理解

## 14-1. .hファイルの役割

ヘッダーファイルは、他のファイルと共有する関数の宣言や型定義などを記述するために使う。

関数の具体的な処理は通常.cファイルに記述する。

---

## 14-2. #includeはファイルを取り込む指示

```c
#include "calc.h"
```

と記述すると、プリプロセッサがcalc.hの内容を展開する。

calc.cまで自動的に展開するわけではない。

---

## 14-3. プリプロセッサとコンパイラの違い

プリプロセッサは、#includeなどの指示を処理してコードを加工する。

コンパイラは、加工後のコードを受け取り、文法や型などを確認しながら変換する。

つまり、役割が異なる。

---

## 14-4. 関数プロトタイプの意味

関数プロトタイプは、コンパイラに関数の呼び出し方を知らせるための情報である。

関数の処理内容そのものではない。

---

## 14-5. インクルードガードの目的

複数のヘッダーファイルの読み込み関係によって、同じ型定義などが重複して展開されることがある。

インクルードガードは、その重複を防ぐための仕組みである。

一般的に、ヘッダーファイルを作成するときは、あらかじめ記述しておく。

---

## 14-6. CALC_Hはファイル名ではない

```c
#ifndef CALC_H
#define CALC_H
```

このCALC_Hはマクロの名前である。

実際のcalc.hというファイルそのものではない。

このマクロが定義されているかどうかを利用して、ヘッダーの内容を処理するか判断する。

---

## 14-7. 複数ファイルを結び付けるのはリンカ

main.cとcalc.cは、それぞれコンパイル・アセンブルされる。

その後、リンカがオブジェクトファイルを結び付ける。

これにより、別の.cファイルに定義された関数を呼び出せる。
